# 3D Layer v1

## 境界と移行

- GLBの検査と原本保存は assets。外部URI、圧縮デコーダーが必要な拡張、循環ノード、異常な寸法・配列はロード前に拒否する。
- DesignDocument v10に `model3d` を追加する。v1〜v9は既存の移行を維持する。モデルはasset IDで参照し、検査済みクリップ・ボーン一覧だけを小さなメタデータとして持つ。保存時に原本のメタデータと照合する。
- 選択、配置、複製、履歴、アンカー、マスクは既存のEditor CoreとDOMレイヤーを使う。3D専用の移動エンジンを作らない。
- Three.jsはRendererだけに依存させる。1ページ1 WebGLコンテキストで各モデルを描き、その直後にレイヤーの2Dキャンバスへ転送する。DOMの重なり順とグループマスクをそのまま利用する。モデル間の奥行き交差は行わない。
- Runtimeは既存の追従の速度と方向からクリップ・向きを評価する。再生時計・遷移も明示的な入力から計算し、ライブとテイクで同じ経路を通す。

## 実装順序

1. GLB検査、v10移行、共有描画、共通UIの3D追加・回転・保存。回帰テスト後にコミット。
2. クリップ選択、停止・ループ・速度・クロスフェード。In-placeを標準にする。テスト後にコミット。
3. 既存追従との接続、作者が設定する速度別クリップ、決定的なテイク再生。テスト後にコミット。
4. 指定ボーンの制限付き視線追従をアニメーション後に加算する。難しいモデルはOFFに戻せるようにする。

## 予算と制約

原本は既存の1ファイル32MiB・全素材256MiBを維持する。3Dは最大8レイヤー。未圧縮glTF 2.0のGLB、埋め込みPNG/JPEG、スキン、モーフ、標準PBRとunlitを対象とする。Draco、Meshopt、KTX2、外部ファイルは初版では拒否する。Blender固有ノードの再現は保証しない。

共有レンダラーでは最大30fps、解像度と合計キャンバス・テクスチャ予算を設ける。非表示・画面外・非表示タブでは更新を止め、削除・OFF時に参照とGPUリソースを解放する。WebGLが使えない場合は作品データを保持してエラーを表示する。

## 検証

自作の小さなリグ・複数クリップ・埋め込み透過テクスチャ付きGLBをfixtureとして使用する。検査、旧JSON、編集・保存・Undo、クリップ遷移、追従・停止、グループマスク、コンテキスト復旧、解放を自動検証する。全体テストと実YouTubeを分け、CPUの描画時間、GPU計測の可否、ドロー数、共有リソース数を報告する。main、通常版dist、Manifestの権限は変更しない。

## 実装した構造

| モジュール                          | 責務                                                                       |
| ----------------------------------- | -------------------------------------------------------------------------- |
| `src/assets/glb.ts`, `decode.ts`    | GLBの境界・参照・展開量の検査、埋め込み画像の実デコードと解放              |
| `src/models/types.ts`               | クリップ・ボーン情報と作者設定の検証。DOM/Chrome/Three.jsに依存しない      |
| `src/world/models.ts`               | クリップの時計、二つのクリップのフェード、速度による切替、向きと視線の評価 |
| `src/world/clock.ts`                | 再読み込み前のテイクから若いHost時計へ戻る場合の時刻補正                   |
| `src/renderers/three/models.ts`     | ページ共有WebGL、アセット参照数、透明面への転送、予算、復旧・解放、計測    |
| `src/renderers/three/rig-player.ts` | Runtimeの時刻をAnimationMixerへ反映。In-place処理と視線の加算              |
| `src/editor/model-panel.ts`         | 全Studioで共用する3D設定。既存の編集コマンドと履歴を使う                   |

Runtimeは1.3.0。既存の1.0/1.1/1.2開発記録、1.1/1.2テイクを読み込む。新しいモデル状態を含まない2D作品では、旧評価との比較テストを維持している。通常の再読み込みでは選択クリップを先頭から再生し、途中のポーズを確認したい場合は保存したテイクを使う。

v9 fixtureは`5490ab4`の型・移行処理に基づく再構成データで、作者の実保存ファイルではない。v1〜v8も既存のfixtureと由来の制約を引き継ぐ。読み込みで旧保存データを書き換えず、保存操作でv10を書く。

## 操作

1. Studioの立方体アイコンからGLBを追加する。ファイルのドロップも使える。
2. キャンバス上で移動・拡縮し、「3Dモデルの向き」でX/Y/Zを調整する。共通の「角度」はキャンバス面の回転として残す。
3. 「3Dアニメーション」で実際のクリップを選ぶ。停止、ループ、速度、クロスフェードを設定する。
4. 「移動とモーション」で待機・歩行・走行に好きなクリップを割り当て、「速度でクリップを切り替える」をONにする。下の共通「モーション」で「マウスを追いかける」をONにする。
5. 最高速度、加速、減速、遅延、停止距離を調整する。しきい値の単位は画面のCSS px/s。切替には小さなヒステリシスを設け、境界付近の往復を抑える。
6. 必要なら「頭・首の視線」でボーンを選ぶ。ローカルYが上、Zが正面のリグ向け。範囲と遅延を調整し、合わないモデルではOFFにする。
7. 保存する。Signal Timelineから操作を明示的に録画し、テイクを別に保存すると、クリップ・フェード・追従・視線をシークできる。

クリップ名からIdle/Walk/Runを推測しない。未割当の状態では基本クリップへ戻す。In-placeはルートと骨格ルートのX/Z移動を抑え、上下動を残す。素材内のRoot Motionからエンジンの移動量を抽出する機能はない。

## 描画上の範囲

各モデルを正投影カメラで個別に描き、初期境界の中心と最大辺で正規化する。キャンバスの高さに応じてモデルが拡大する。素材の標準PBR/unlit、色、PNG/JPEGテクスチャ、透過、スキン、モーフを使う。照明は固定の環境光と平行光で、Blender独自ノード、任意シェーダー、トゥーン/輪郭線の編集は提供しない。

DOMへ転送した面なので、画像との前後関係、グループの不透明度・マスク、個別マスクを共存できる。モデル同士の立体的な交差、Web UIとの奥行き遮蔽、接地、IK、物理は含めない。視線は画面上のモデル中心を基準に仮想方向へ変換した加算回転で、任意のリグ・目線位置を自動補正する仕組みではない。

シグナルの既存X/Yと回転レーンは共通キャンバスのオフセットとして働く。3DのX/Y/Z角度を個別キーフレーム化するレーンは次段階。追従の向きは、基本角度を保持したままモデルのY回転へ加算する。

## 実行時の上限

- 3D最大8個、全メディア32個。GLB原本32MiB、全素材256MiB。重複レイヤーで原本を複製しない。
- 2048ノード、256ボーン、64クリップ、100万頂点/三角形を上限とし、モデル内のインスタンスによる増幅も検査する。JSON部分2MiB、階層64段、キー合計50万まで。
- PNG/JPEGは4096px以下、展開64MiB/素材。モーフとアニメーションは各64MiBまでの展開予算を検査する。GPU資源は推定96MiB/素材・128MiB/ページまで（ドライバー・ボーンテクスチャ・描画面の実割当を保証する値ではない）。スパースアクセサー、Draco/Meshopt/KTX2、外部URIは拒否する。
- 描画は最大30fps。長辺1024px、1面512K画素、全8面で約16MiB以下の転送面に抑える。大きな配置では描画解像度を落とすが、原本は保持する。
- 非表示・画面外・マスク強度0ではポーズ更新を止め、面を1pxへ縮小する。非表示タブとreduced-motionでも停止する。資源は再表示のため保持し、削除・OFF・強さ0%で解放する。
- 予算超過やWebGL非対応では設定を保持してエラーを表示する。不要なモデルを削除し、対象の表示をOFF→ONするか再読み込みすると再試行できる。

同一JS実装では同じ入力列から同じ数値評価を得る。NodeとChromeの超越関数には最下位桁の差が出るため、実サイトのクロスエンジン比較は1e-9以内、単体テストの同一エンジン再生は完全一致で検証する。GPUピクセルの機種間完全一致は保証対象にしない。

## 次の検討

実際の作者モデルでの互換性・負荷の収集、クリップの同期位相、ボーン軸の指定、カメラ/基準サイズ、描画予算の優先度・品質低下、Storage Adapterからの3Dローダー注入を優先する。混合描画の転送が負荷になる場合に限り、共有GPU合成への移行を検討する。

ループOFFで最終ポーズへ到達したクリップを先頭からやり直す場合は、いったん「静止ポーズ」を選び、目的のクリップへ戻す。専用のリスタート操作は次段階とする。読み込み中のブラウザーの単発デコードは即座に中断できない場合があるが、OFF後の結果は破棄して解放し、描画を再開しない。

# 3D Layer v1

## 境界と移行

- GLBの検査と原本保存は assets。外部URI、圧縮デコーダーが必要な拡張、循環ノード、異常な寸法・配列はロード前に拒否する。
- DesignDocument v10に `model3d` を追加する。v1〜v9は既存の移行を維持する。モデルはasset IDで参照し、検査済みクリップ・ボーン一覧だけを小さなメタデータとして持つ。保存時に原本のメタデータと照合する。
- 選択、配置、複製、履歴、アンカー、マスクは既存のEditor CoreとDOMレイヤーを使う。3D専用の移動エンジンを作らない。
- Three.jsはRendererだけに依存させる。1ページ1 WebGLコンテキストで各モデルを描き、その直後にレイヤーの2Dキャンバスへ転送する。DOMの重なり順とグループマスクをそのまま利用する。モデル間の奥行き交差は行わない。
- Runtimeは既存の追従の速度と方向からクリップ・向きを評価する。再生時計・遷移も明示的な入力から計算し、ライブとテイクで同じ経路を通す。

## 実装順序

1. GLB検査、v10移行、共有描画、共通UIの3D追加・回転・保存。回帰テスト後にコミット。
2. クリップ選択、停止・ループ・速度・クロスフェード。In-placeを標準にする。テスト後にコミット。
3. 既存追従との接続、作者が設定する速度別クリップ、決定的なテイク再生。テスト後にコミット。
4. 指定ボーンの制限付き視線追従をアニメーション後に加算する。難しいモデルはOFFに戻せるようにする。

## 予算と制約

原本は既存の1ファイル32MiB・全素材256MiBを維持する。3Dは最大8レイヤー。未圧縮glTF 2.0のGLB、埋め込みPNG/JPEG、スキン、モーフ、標準PBRとunlitを対象とする。Draco、Meshopt、KTX2、外部ファイルは初版では拒否する。Blender固有ノードの再現は保証しない。

共有レンダラーでは最大30fps、解像度と合計キャンバス・テクスチャ予算を設ける。非表示・画面外・非表示タブでは更新を止め、削除・OFF時に参照とGPUリソースを解放する。WebGLが使えない場合は作品データを保持してエラーを表示する。

## 検証

自作の小さなリグ・複数クリップ・埋め込み透過テクスチャ付きGLBをfixtureとして使用する。検査、旧JSON、編集・保存・Undo、クリップ遷移、追従・停止、グループマスク、コンテキスト復旧、解放を自動検証する。全体テストと実YouTubeを分け、CPUの描画時間、GPU計測の可否、ドロー数、共有リソース数を報告する。main、通常版dist、Manifestの権限は変更しない。

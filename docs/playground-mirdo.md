# Playground に住むミルド

2026-11-07。基点は `codex/mirdo-spa-fix` の `6e789e1`。共有の world・Host・サイトアダプター・作品データ v16 はそのまま使用した。

## ビルド

外部の非公開素材リポジトリ `wwt-private-assets` の `d778429` を使用した。Git LFS を取り込んだチェックアウトをビルド時に指定する。

```powershell
$env:AROUND_PLAYGROUND_MIRDO_ROOT = 'C:\wwt-private'
npm run build:playground
```

通常ビルドは外部チェックアウトの指定が必要。出力は `dist-playground/`。既存の試験用ビルドは `AROUND_PLAYGROUND_TEST=1` で外部素材を渡さずに生成できる。承認済みの変換 VRM 1体と Quaternius Universal Animation Library から変換した合格 VRMA 16本だけを、ファイルの SHA-256 で照合して取り込む。出力でもモデル・動作の許可リストと内容のハッシュを照合する。トルーシェ、私用 VRM、Mixamo の名前と内容の検査も適用する。バイナリ素材は Around の Git に入れない。

翔太が確認した VN3 の許諾範囲で、変換済みのミルドを Playground に組み込む。ページ下部にモデルの作者と配布元、動作の出典を表示した。 [ミルド／ragooou（らぐー）](https://booth.pm/ja/items/6614116) · [Quaternius Universal Animation Library（CC0）](https://quaternius.com/packs/universalanimationlibrary.html)

## 動きと操作

開いたときに作品が適用される。動作はエディターでの取り込みと同じ分類・割り当てをビルドで行う。休み・うとうとは Sitting_Idle_Loop、逃げるときは Jog_Fwd_Loop、近づく・戻るときは Walk_Loop。Playground の既存アダプターはプレーヤーの上下を座れる縁として渡す。実ページで下の縁から逃げ、上の縁に歩いて戻って座るところまで確認した。上下とも座り重み1のフレームでキャラの箱中心は縁と一致した。

Playground の操作帯には、下の縁から48 pxの余白を設けた。座った足先が音量スライダーの切り抜きで分断されるのを防ぐ。操作部品の保護は同じ経路を通る。作品の適用と解除、緊急 OFF、着座後の音量操作をテストした。

## テストと引き継ぎ

unit は600件通過・2件スキップ。Playground の e2e は7件通過。最初の実素材の1件では、ローカルの manifest の取得が Chromium の `ERR_NO_BUFFER_SPACE` で失敗し、同じビルド・手順で再実行すると通過した。承認済みの VRM を LFS ポインターに置き換えた試験では、ビルドが拒否して出力を消した。GitHub Actions の push 対象ブランチにはこのブランチを含まない。

既知の編集テストを、Playground と分けた拡張ビルドで短く再試験した。

| テスト       | 結果    | 失敗時に確認したこと                                                                                                                                    |
| ------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| レイヤー編集 | 1/3通過 | 保存データは新しい名前・非表示・ロック状態を保持。開き直した Studio は古い名前と表示状態を未保存のプレビューとして復旧し、「表示する」が出なかった      |
| タイムライン | 6/7通過 | 保存後に開き直した Studio がレイヤー0件を表示し、再選択できなかった。trace にレイヤー編集と同じ「復旧中に保存済みデザインが変わりました」の通知があった |

両件とも製品の再接続時の復旧経路で起きる。保存操作と復旧用チェックポイントの更新順が候補で、どの順序で競合するかは未特定。この塊は Playground に限定し、編集側のコードと既存テストの判定は維持した。

Claude Code には、通常ビルドで下の縁と上の縁の座り姿勢、プレーヤーの操作ができること、公開候補の VRM・VRMA が承認した17件だけであることを確認してもらう。

# R3 の調べ

G1.4 を閉じるときに分かった前提を先に書き、そのあとに R3 の調べの結果と計画（2026-11-04、Claude Code）を書く。製品としての決定は [product-design.md](product-design.md) にある。

## 前提：画面に固定した絵と、ページと一緒に動く保護範囲

- 画面に固定した絵（viewport 基準）は、ページと一緒に動く保護範囲（`surface.scrolls`）を、その幅のまま**画面の全高の縦帯**に広げて切り抜く（[src/world/operations.ts](../src/world/operations.ts) の `sweptRegions`）。非同期スクロールでは、ページの部品が JS を待たずに画面上を動く。そのため、帯を縦に広げて、スクロール中に操作部品が絵の下へ入っても隠れないようにしている
- 視聴ページでは、プレーヤーの上下の操作帯がこの扱いになる（`scrolls=true`・`compositionCapability=exclusion`）。プレーヤーの幅の縦帯全体（実サイトの例：x=16〜1012）で、画面に固定した絵は描けない。映像の真ん中に置いても切り抜かれる（docs/g14-verification.md の実サイトの画像）
- プレーヤー基準の絵（`anchor: surface / video-player`）は、プレーヤーの中の面に描くので、映像の上に描ける

## R3 で調べて書くこと

1. **キャラをどの基準で置くか**：ページ・画面・プレーヤーのそれぞれで、置ける場所、スクロールでの動き方、上の縦帯の制限を受けるかを比べる
2. **基準をまたぐ瞬間移動の扱い**：例えばページの余白から映像の上へ移るとき、どの時点で基準を切り替えるか。切り替えの間に、操作部品の上へ一瞬出ないこと（G1）
3. **縦帯の制限を R3 で変えるか**：変えるなら、非同期スクロールで操作帯が絵の下へ入る場合の守りを残す設計が要る（例：スクロールの間だけ縦帯に戻す、帯の動きを先に読む）。変えないなら、画面に固定したキャラは映像の上に出られないことを、作者向けにどう示すか

[spatial-design.md](spatial-design.md) の4節・6節から、R3 でそのまま使う決まり：

- データを rig facts（不変の数値）／ behavior（状態と遷移）／ instance state（個体の可変状態）／ frame（描画への指示）に分ける。Renderer が持つ `AnimationMixer` や VRM の個体を world の入力にしない
- 姿勢の適用順：クリップ → クロスフェード → 加算と向き → 接地と IK → 視線 → 表情・制約 → 揺れもの
- 面との関係は `character → surfaceId / 縁の上の位置 / 向き / 接点` で持つ。UI の DOM をキャラの親にしない。面が消えたら古い矩形に座り続けず、待避点へ戻るか一時的に隠す。再接続は同じ意味の面かを確かめる
- 描画の重ね方（6節）：今の「モデルごとに描いて DOM の面へ載せる」方式で、キャラ1体には足りる。R3 で合成の方式は変えない

wwt-world-runtime のスキルの判断の仕方を R3 に当てると：

| 処理                                               | 置き場所                                     |
| -------------------------------------------------- | -------------------------------------------- |
| 座れる縁を DOM から読む                            | Host（`src/sites/`）                         |
| 縁の選び方・移動中の位置・座り方の選択・まばたき   | world（時刻と seed を入力にした純粋な関数）  |
| .vrma の解析、体型の測定、床に沈む量の焼き込み     | Asset Runtime（読み込んだときに1回）         |
| 骨への適用、手足の IK の見た目の補正、消えるノイズ | 描画（`src/renderers/three/`）               |
| 操作部品と重なる所の切り抜き                       | エンジン（今の G1 のまま。作品から変えない） |

## 2. .vrma の読み込みと作品での持ち方

### 読み方

- `@pixiv/three-vrm-animation@3.5.5`（MIT、依存は `@pixiv/three-vrm-core` など同じ 3.5.5）。`GLTFLoader` に `VRMAnimationLoaderPlugin` を登録して読み、`createVRMAnimationClip(vrmAnimation, vrm)` で three の `AnimationClip` にする。腰の移動は、モデルの腰の高さと動作の腰の高さの比で縮める作りと読める（R3-1 で実物で確かめる）。これが「腰の高さ」の補正の最初の一歩になる
- 作った `AnimationClip` は、今の `rig-player` と同じく mixer の時刻を world の時刻で置いて使える。**再生の時計を描画に持たせない**決まりはそのまま守れる
- 注意：.vrma のクリップは**正規化した骨**を動かす。今は `autoUpdateHumanBones = false` で、`humanoid.update()` が正規化した骨から生の骨へ写さない。.vrma を使う個体では写すようにする（モデルの中のクリップと .vrma を1体で混ぜない）
- 読み込みの守り：.vrma は「メッシュ・画像・外部 URL がなく、`VRMC_vrm_animation` だけを持つ glTF」として検証する。骨の数・チャンネル数・キーの数・長さに上限を付ける。実物は 1本 70〜175KB、骨の回転 51本＋腰の移動1本

### 作品での持ち方（版は v13 → v14）

- 素材に「動作」（.vrma）の種類を足す。素材 ID とハッシュで参照する（今のモデルと同じ）
- 作品の 3D の層に、省略できる `character` を足す。省略したら今の 3D の層と同じ動き（旧作品の動きを変えない）

```json
{
  "character": {
    "motionStage": "auto",
    "motions": [
      { "id": "idle", "assetId": "…", "role": "idle", "loop": true },
      { "id": "sit", "assetId": "…", "role": "sit", "loop": true },
      { "id": "jump-down", "assetId": "…", "role": "edge", "loop": false }
    ],
    "poses": [{ "id": "hug-knees", "assetId": "…", "contacts": [{ "part": "hips", "on": "edge" }] }]
  }
}
```

- `role` は manifest の種類（idle・gesture・react・dance・move・sit・edge）の列挙。名前は標準の名前（idle・walk・sit・peek・jump_down など）を ID の形（小文字とハイフン）にして持つ
- **長さ・腰の移動・In Place かどうかは作品に書かない。** 読み込んだときに .vrma から測る（rig facts）。manifest の値は信じず、取り込みの画面で「manifest と測った値が違う」ことを表示するだけにする
- manifest.json は**取り込みの道具**として読む（フォルダを選ぶと一覧を作る）。作品には上の検証済みの形だけが入る
- 素材の上限：数は 128 で足りるが、1回の取り込みは 8件まで（`ASSET_LIMITS.batchCount`）。36本を入れるには、取り込みを分けるか、複数の動作を1つの .vrma にまとめる（glTF の `animations` を複数持てる）。どちらにするかは R3-1 で決める
- 手順は wwt-design-version のスキル（移行チェーンに1段、履歴由来の fixture で v13 までの作品が移行前と一致すること）

## 3. 中の形の置き場所

新しく `src/characters/` を作り、VRM に縛られない型を置く。

| 型                         | 中身                                                                                               | R3 で作るか                                                    |
| -------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `HumanoidRig`              | 人型の骨の名前（VRM 1.0 の骨の名前を、エンジンの共通の語彙として使う）→ 個体の骨、基準の姿勢、親子 | 作る                                                           |
| `BodyMeasure`              | 身長、頭の大きさ、足・腕の長さ、肩幅、腰の高さ（4節）                                              | 作る                                                           |
| `ExpressionSet`            | 共通の表情の名前（happy・blink など）→ 個体の表情。まばたき・視線に使う                            | 作る                                                           |
| `MotionFacts`              | 動作ごとの長さ・ループ・腰の移動の曲線・床に沈む量の曲線・お尻の接点の位置                         | 作る                                                           |
| `SpringSet`・`MaterialSet` | 揺れもの・材質の共通の形                                                                           | 型だけ決め、R3 の中身は VRM のライブラリに任せる（翔太に確認） |

- 作るのは Asset Runtime の `fromVrm()`（読み込んだときに1回）。R7 で `fromFbx()` を足し、同じ型を作る
- 中の形は素材のハッシュとコンパイルの版に結び付け、信頼済みの生成処理だけが作る（spatial-design.md 4節「解析結果の共有」）
- world は `HumanoidRig` の数値だけを見る。three や VRM の型を world に入れない（world-boundaries のテストを弱めない）
- VRM 1.0 の骨の名前を語彙にするのは、Unity の Humanoid と同じ並びで、FBX（Mixamo など）の骨からも対応が取りやすいため。VRM の機能（揺れもの・材質）とは別に扱う

## 4. 体型の測り方と、段階を切り替える基準

### 測り方

読み込んだときに、基準の姿勢（T ポーズ）で次を測る。

- 身長：メッシュの高さ
- 頭の大きさ：首の骨から頭の上まで
- 足の長さ：太もも＋すね（骨の間の長さ）、腕の長さ：上腕＋前腕
- 腰の高さ、肩幅

### 実際の値（使い捨てのスクリプトで、glTF の骨の位置とメッシュの範囲から計算）

| 項目                        | トルーシェ（trusie.vrm） | 素体（lp_basebody.vrm） |
| --------------------------- | ------------------------ | ----------------------- |
| 身長                        | 0.921 m                  | 1.547 m                 |
| 頭身（身長÷頭）             | 2.69                     | 5.89                    |
| 足 ÷ 身長                   | 0.37                     | 0.52                    |
| 腕 ÷ 身長                   | 0.25                     | 0.28                    |
| 腰の高さ ÷ 身長             | 0.41                     | 0.59                    |
| 肩幅（上腕の間）            | 0.08 m                   | 0.25 m                  |
| 人型の骨                    | 51                       | 52                      |
| 表情のプリセット            | 18                       | 18                      |
| 揺れもの（VRMC_springBone） | **なし**                 | なし                    |

- トルーシェの「頭」は、メッシュのいちばん上までで測ったので、うさ耳の分だけ大きく出ている可能性がある。R3-1 では、頭の骨に重みのある頂点だけで測り、人型でない子の骨（`L.usamimi` など）に付いた頂点を除く
- 肩幅がとても狭い（素体の 1/3）。check の「腕が服に入る」と合う

### 切り替えの基準（仮）

| 条件（どれか1つで段階1） | トルーシェ    | 素体 |
| ------------------------ | ------------- | ---- |
| 頭身 < 4                 | 2.69 → 当たる | 5.89 |
| 足 ÷ 身長 < 0.42         | 0.37 → 当たる | 0.52 |
| 腰の高さ ÷ 身長 < 0.48   | 0.41 → 当たる | 0.59 |

- この基準でトルーシェは「どのモデルにも当てられる版（`anim/` 直下）は使わない＝段階1」、素体は段階2になる。トルーシェ用の `anim/trusie/` は**段階3（作者の動作）**として使える。3つの段階の切り替えを、2体でそのまま確かめられる
- 数値は2体だけから決めた仮の値。基準の根拠は check の判定（めり込み・床に沈む深さ）にする：標準の動作を当てて、判定が悪くなる境目を探す。体型の違うモデルが増えたら見直す
- 判定は使う人に表示し（「この体型では標準の動作が崩れるので、簡単な動きにしています」）、手で段階を変えられる（作品の `motionStage`）

## 5. 触れる所・IK・めり込みを R3 でどこまでやるか

| 項目                         | R3 でやるか                              | やり方                                                                                                                                                                            |
| ---------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| お尻を縁に合わせる           | **やる**（通過の条件に要る）             | 座る動作・姿勢ごとに、読み込んだときにお尻の接点（腰と太ももの付け根のいちばん低い所）の位置を測って rig facts に入れる。world はキャラ全体の位置を、その接点が縁に乗るように置く |
| 床に沈む分の腰の上下         | **やる**                                 | 読み込んだときに、動作を一定の刻み（30fps）でたどり、足の最も低い所が床より下になる量を曲線として焼き込む。再生のとき、その量だけ全体を持ち上げる                                 |
| 足を床に・両手をひざに（IK） | R3 の後半（R3-4）で、2本の骨の解析解だけ | 描画の側で、frame の姿勢に後から当てる見た目の補正。world の点の計算には使わない（同じ frame から同じ結果になるので決定的）                                                       |
| めり込みの押し出し           | やらない                                 | トルーシェは腕を補正した `anim/trusie/` を使う。押し出しは体型の違うモデルを増やす段階で                                                                                          |
| 届かないときの切り替え       | R3 では「より単純な姿勢へ」だけ          | 例：足を下ろす座り方で足が届かない縁なら、体育座りへ                                                                                                                              |

summary.md の「床に沈む」動作を、腰の上下の補正でどこまで直せるか（見立て。R3-2 で実物で確かめる）：

| 型                               | 動作                                                                     | 腰の上下で直るか                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| 全身が下がる（しゃがむ・のぞく） | peek −81mm、scared −87mm、lean_wall −28mm、surprised −32mm、beckon −30mm | 直る見込みが高い。足が床から離れない動作なので、持ち上げても浮かない                                    |
| 走りで片足が沈む                 | run −32mm、run_look_back −41mm、run_wobbly −37mm、jump −26mm             | 沈みは消えるが、腰が上下に揺れ、反対の足が浮いて見えることがある。R3 は歩かないので、急がない           |
| 腰の移動で下がるのが本来         | jump_down −427mm など、get_up、sit 系                                    | 直さない（床に沈んでいるのではなく、下へ移る・座る動作）。焼き込みの対象から外す（`role` が edge・sit） |
| 変換の差が大きい                 | run_goofy（右足 21.3°）                                                  | 腰では直らない。動作の側（翔太）で直すか、使わない                                                      |

- 「いちばん低い所」は、骨でなくメッシュの頂点で測ると長いスカートの裾が入る。焼き込みは**足の骨（つま先）**の高さで測る

## 6. 部品の上の縁を床にする（サイトアダプター）

### アダプターが渡すもの

アダプター（`src/sites/`）が、「座れる縁」（perch）を Host の入力として渡す。作品は縁の DOM を知らない（セレクターを作品に入れない）。

| 項目         | 内容                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------- |
| `id`         | 同じ部品なら同じになる、ページの中だけの不透明な ID（動画の ID など閲覧の記録は入れない） |
| `kind`       | `video-card`・`button`・`player-top`・`page-margin`                                       |
| `edge`       | 縁の左右と高さ（文書の座標）                                                              |
| `below`      | 下にあるもの：`control`（操作部品）・`video`（動画）・`none`（何もない）                  |
| `headroom`   | **縁の上の空き**：縁の上で、ほかの操作面に当たるまでの高さ                                |
| `generation` | 部品の世代（G1 の操作面と同じ考え方。変わったら古い縁に座らない）                         |

- 集め方：AGENTS.md の「繰り返さない設計」のとおり、page-change のたびに文書全体を探さない。G1.1 の差分の集め方（新しく印を付けた要素・変わった部分）と、操作面の表（`youtube-operations.ts` の行）から作る。動画カードはもう `youtube-cards.ts` で見分けている
- 件数に上限（例：画面とその近くの 64件）を付ける

### 最大の危険：カードの上は空いていない

- 動画カードは操作面（`occlusion: forbid`、切り抜き）。**カードの上の縁の上には、ふつう上の行のカードの文字（題名・チャンネル名。どれもリンク）がある。** ホームの格子でも、視聴ページの右の列でも、行の間は狭い
- そのため、カードの上に座ったキャラの体は、上のカードと重なる所が切り抜かれる。そのままでは「体の上半分がない」絵になる
- 対策の案：アダプターが `headroom` を渡し、world は**そのときの姿勢の高さより空きが大きい縁だけ**を選ぶ。空きがあるのは、例えば1行目（上はチップの帯）、格子の列の端、検索結果の行の間など。どれだけ空きがあるかは R3-0 で本物の YouTube で測る
- 空きの小さい縁しかなければ、キャラを小さくする・寝転ぶ（高さが低い姿勢）を選ぶ・その縁は選ばない、のどれか。翔太に決めてもらう（下の表）

### プレーヤーの上の縁

- プレーヤーの上の 64px は `player.controls.top`（クリックの操作面、隠れていても予約）、下の 112px は `player.controls.bottom`。**上の縁から足を下ろすと、足は上の 64px に入り、切り抜かれる**
- 予約の幅を狭めるのは G1 の守りを弱めるので、R3 ではしない。案：プレーヤーの上の縁では、足を下ろす座り方をあきらめる（体育座り）か、足が切れて見えることを許す。翔太に決めてもらう

### 部品が動いた・消えたとき

- world は毎フレーム、キャラの縁の ID から縁の今の位置を引き、その上にキャラを置く（縁と一緒に動く）。spatial-design.md の「面との関係」と同じ
- 世代が変わった・消えた：古い位置に座り続けない。次の縁をきっかけの決まりで選んで瞬間移動する。選べる縁がなければ、消える演出のあと隠す（spatial-design.md 12節のおすすめ「待避点がなければ非表示」と同じ）
- 戻ってきた縁は、同じ ID でも勝手に吸着しない。次のきっかけまで待つ

## 7. キャラを置く基準と、縦帯の制限

| 基準                                           | 今の層                         | スクロール             | 縦帯の制限                                   | キャラに使うか                                             |
| ---------------------------------------------- | ------------------------------ | ---------------------- | -------------------------------------------- | ---------------------------------------------------------- |
| ページ（`anchor: surface`）                    | `PAGE`（ページと一緒に動く層） | ページと一緒に動く     | 受けない（動く部品は今の位置で切る）         | **使う**。カード・ボタン・ページの余白・プレーヤーの上の縁 |
| 画面（`anchor: viewport`）                     | `SCREEN`                       | 画面に固定             | 受ける（プレーヤーの幅の縦帯全体に描けない） | 使わない                                                   |
| プレーヤー（`anchor: surface / video-player`） | プレーヤーの中の面             | プレーヤーと一緒に動く | 受けない                                     | 全画面のときだけ候補。R3 では全画面のときは隠す案          |

- キャラが座るのはどれもページと一緒に動く部品なので、**ページの層に置けば、縦帯の制限に当たらない。** R3 では縦帯の制限を変えない
- そのため「基準をまたぐ瞬間移動」は、R3 ではほぼ起きない（全部ページの層）。全画面の出入りのときだけ、キャラを消す・出すで済ませる
- 今の作品では、ページの層に置けるのは `anchor: surface` で名前のある面（今は `video-player` だけ）の子だけ。キャラは作者が決めた面ではなく、**縁を実行中に選ぶ**ので、「ページの層に置き、位置は world が縁から決める」新しい置き方を足す（R3-3、中核）
- 画面に固定したキャラを、後の段階で映像の上に出したくなったら、そのとき縦帯の守りを設計し直す。R3 の作者向けの表示は要らない（キャラは画面基準を選ばせない）

## 8. 瞬間移動と跳ねる動きを、world の決定的な評価でどう表すか

キャラの instance state に「どこにいるか」を持つ。

```ts
type CharacterPlace =
  | { kind: 'perched'; perchId: string; u: number /* 縁の上の位置 0..1 */; pose: string; sinceMs: number }
  | {
      kind: 'moving';
      how: 'teleport' | 'hop' | 'edge';
      from: PlaceRef;
      to: PlaceRef;
      startMs: number;
      durationMs: number;
      motionId?: string;
    }
  | { kind: 'hidden'; reason: 'no-perch' | 'fullscreen' | 'reduced-motion' };
```

- 位置と見た目は、world の時刻 `t` から計算する純粋な関数にする。`p = (t − startMs) / durationMs` から：
  - 瞬間移動：前半は元の縁で消える（ノイズの量 0→1）、後半は先の縁で現れる（1→0）。**位置と層を切り替えるのは、ノイズの量が 1（見えない）の瞬間**。描画は「見えない」フレームを1枚はさんでから新しい位置を出す。こうすると、操作部品の上へ一瞬出ることがない（G1）
  - 跳ねる：元と先の点を放物線で結ぶ。先の点は毎フレーム縁から引き直す（縁が動いても着地点がずれない）。**同じ層の中の近い縁だけ**に使い、途中で操作部品の上を通る道は選ばない
- ノイズの絵はエンジンのシェーダーの中に置き、frame には量（0〜1）と seed（整数）だけを入れる。作品からシェーダーを受け取らない
- 行き先の選び方：きっかけ（カーソルが近い縁、新しいコメントの欄、動画の停止ならプレーヤーの上など）ごとに点数を付け、同じ点数なら縁の ID の順。乱数は使わない。変化が欲しいときは、状態に seed を持ち、入力から進める
- 1tick に始められる移動は1回、移動中は次の移動を始めない。0時間の循環を作らない（spatial-design.md 4節の遷移の決まり）
- 録画（テイク）：きっかけの入力と `CharacterPlace` は録画に入る。縁の幾何は Host の入力なので、再生のときは**そのときのライブの縁**を使う（G1.2 の「Host の制限を録画に入れない」と同じ考え方）。同じ縁がなければ隠す
- reduced-motion：ノイズ・跳ねる動きをせず、元の縁で消えて先の縁に出る（間の演出なし）。緊急 OFF・`safeInteraction` のときは今の 3D の層と同じく止める

## 9. 縁の動作（edge）の使い方

manifest の edge の動作と、腰の移動（manifest の値、x・上・前、m）：

| 動作         | 腰の移動 m              | 使い道                                      |
| ------------ | ----------------------- | ------------------------------------------- |
| climb_up     | [0.001, 0.612, 0.137]   | 下の縁から上の縁へよじ登る                  |
| jump_down    | [−0.005, −0.479, 0.694] | 前へ跳んで下の縁へ降りる（_2・_3 も同じ型） |
| stop_at_edge | [0.0, 0.02, 0.987]      | 前へ歩いて縁で止まる                        |
| edge_slip    | [0.012, −0.004, −0.09]  | 縁で足を滑らせる（ほぼその場）              |
| teeter・hang | ループ（移動なし）      | 縁で揺れる・ぶら下がる（待つ姿勢）          |

- **位置の持ち主を1つにする**：描画は動作を In Place で再生し（今の `inPlace` と同じく腰の水平の移動を消す。edge の動作は上下も消す）、腰の移動は world がキャラの位置として動かす。腰の移動の曲線は読み込んだときに .vrma から測る（`MotionFacts`。manifest の値は使わない）
- 長さの換算：画面の px ＝ m × （キャラの表示の高さ px ÷ 身長 m）。トルーシェを高さ 120px で出すと、jump_down は下へ約 62px・前へ約 90px
- 縁の高さの差に合わせる：腰の移動の上下を、縁の高さの差に合わせて縮め・伸ばす。0.7〜1.4倍に収まらなければ、その動作は選ばず、跳ねるか瞬間移動にする
- **横向きが要る**：動作の「前」は体の前。正面を向いたままだと、前への移動は画面の奥へ向かい、画面の上で横へ動かない。隣の縁へ移るときは、体を横（±90°）に向けてから動作を始め、着いたら戻す。向きを変える時間も移動の長さに入れる
- 「部品の上を横切らない」：jump_down の放物線が、間の操作部品の上を通る縁の組は選ばない（隣の列のカードの間の隙間・ページの余白へ降りるときだけ）

## 10. 正面から座っているように見えにくい件

| 案                                                            | よい点                                                   | 弱い点                                                                                       |
| ------------------------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| A. 座るときだけ体を 20〜30° 斜めに向ける（world の `yawDeg`） | エンジンだけで済む。今の正投影のまま。足の曲がりが見える | 正面の顔が少し横を向く。視線（カーソルへ）と組み合わせて見え方を確かめる                     |
| B. カメラを斜めにする                                         | 体の向きを変えない                                       | 今の 3D の層はモデルごとの正投影で、カメラの角度は A と同じ見え方。G2 のカメラの仕事と混ざる |
| C. 座り方を、正面から読めるものにする                         | 体育座り・横座りは、ひざが胸の前に来るので正面から分かる | 椅子に座る型（sit・sit_2 など）は正面からは立ちと変わらない                                  |
| D. 作品の側で座り方を直す（翔太）                             | スカートの広がり・足の出し方まで作者が決められる         | 翔太の作業が増える                                                                           |

- すすめ：**A と C の組み合わせ。** 操作部品の上はもともと体育座り・横座り・寝転ぶなので C が効く。足を下ろす座り方（プレーヤーの上・余白）だけ A で斜めにする。D は A と C で足りないときに

| 変数                        | 中身                                                                                                                                                  |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WW_VRM_FILE`               | 今と同じ。キャラのモデル（例：`…\out\trusie.vrm`）                                                                                                    |
| `WW_VRMA_DIR`（案）         | 動作のフォルダ（例：`…\out\anim\trusie` または `…\out\anim`）。フォルダの中、なければ1つ上の階の `manifest.json` を、取り込みの道具と同じ読み方で読む |
| `WW_VRM_COMPARE_FILE`（案） | 比べる用のモデル（`lp_basebody.vrm`）。段階の切り替えの確かめに使う                                                                                   |

- どれもリポジトリに入れない。テストやスクリプトは、変数がなければ飛ばす（今の `WW_VRM_FILE` のテストと同じ）
- CI 用の公開の VRM・動作：pixiv の VRM のサンプルや VRoid のモーションの配布はあるが、**再配布してよい規約かを、この調べでは確かめていない。** CI に入れるなら、規約の確認を翔太にお願いする
- すすめは、**テストの中で作る**こと。もう `tests/helpers/vrm-fixture.ts` に、他の作者の物を含まない VRM（腰・背骨・腕・脚・目・頭）を作る関数がある。同じように、`VRMC_vrm_animation` を持つ小さな glTF（人型の骨ごとのノードと、回転・腰の移動のチャンネル）を作る関数を足す。腰を下げてひざを曲げる「座る」1コマ、腰が前と下へ動く「飛び降りる」の2本があれば、接点・腰の移動・床の補正の unit と e2e が組める

## 12. 性能

- 3D は GPU で描くので、**画面の外に置いた表示ありの窓**（`tests/fixtures.ts` の `launchExtension()` と同じ引数）で測る。G1.3 の D8 の 3D の参考値（中央値 0.80・p95 2.70ms）は headless の SwiftShader（CPU 描画）なので、R3 では取り直す
- 物差しは3つ：

| 物差し                       | 取り方                                                                                              | 合否                         |
| ---------------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------- |
| 拡張の CPU 時間（1フレーム） | 今の G11 のハーネス（`G11_HEADED=1`）。world の評価・姿勢の更新・2D への写しを分けて記録            | 合否はこれ（AGENTS.md）      |
| GPU の描画時間               | 開発用のフラグで有効にする計測フック（`EXT_disjoint_timer_query_webgl2`）。ソースの書き換えはしない | 参考値として記録             |
| 動画のフレーム落ち           | `video.getVideoPlaybackQuality()` の dropped / total を、キャラなしと交互に                         | 参考値。増えたら原因を調べる |

- 場面：起動直後、SPA 遷移の直後、定常（座って待つ）、移動中（瞬間移動・跳ねる）、スクロール中
- CPU を節約する案（ノート PC の i7-13650HX で動かす前提）：座って待つ間は、姿勢を 30fps（動作の元の刻み）で更新し、毎フレーム描き直さない（spatial-design.md 4節の「コマ打ち」の仕組みを使う）。まばたき・呼吸の間も 30fps で足りる見込み。止まっている間（揺れもの・呼吸を除き動きがない）は描かない
- 合否の交互計測は Codex。Claude Code は仮説を確かめる短い計測とプロファイルだけ

# R3 の調べ

2026-11-04 時点で、R3 の調べはまだ始まっていない。G1.4 を閉じるときに分かった前提を、先に書いておく。

## 前提：画面に固定した絵と、ページと一緒に動く保護範囲

- 画面に固定した絵（viewport 基準）は、ページと一緒に動く保護範囲（`surface.scrolls`）を、その幅のまま**画面の全高の縦帯**に広げて切り抜く（[src/world/operations.ts](../src/world/operations.ts) の `sweptRegions`）。非同期スクロールでは、ページの部品が JS を待たずに画面上を動く。そのため、帯を縦に広げて、スクロール中に操作部品が絵の下へ入っても隠れないようにしている
- 視聴ページでは、プレーヤーの上下の操作帯がこの扱いになる（`scrolls=true`・`compositionCapability=exclusion`）。プレーヤーの幅の縦帯全体（実サイトの例：x=16〜1012）で、画面に固定した絵は描けない。映像の真ん中に置いても切り抜かれる（docs/g14-verification.md の実サイトの画像）
- プレーヤー基準の絵（`anchor: surface / video-player`）は、プレーヤーの中の面に描くので、映像の上に描ける

## R3 で調べて書くこと

1. **キャラをどの基準で置くか**：ページ・画面・プレーヤーのそれぞれで、置ける場所、スクロールでの動き方、上の縦帯の制限を受けるかを比べる
2. **基準をまたぐ瞬間移動の扱い**：例えばページの余白から映像の上へ移るとき、どの時点で基準を切り替えるか。切り替えの間に、操作部品の上へ一瞬出ないこと（G1）
3. **縦帯の制限を R3 で変えるか**：変えるなら、非同期スクロールで操作帯が絵の下へ入る場合の守りを残す設計が要る（例：スクロールの間だけ縦帯に戻す、帯の動きを先に読む）。変えないなら、画面に固定したキャラは映像の上に出られないことを、作者向けにどう示すか

# G1.1.1：編集中のクリックで描画が止まったままになる件

翔太が手で見つけた「◇停止中」が消えない件の、2 回目の指示（翔太、2026-11-01）の 4 つ。レトロテーマは別の段階で撤去するので、レトロテーマでの再現はしない。

1. `validate` が、操作部品が見えているかを確かめていない。見えていない部品の上のクリックを失敗と数えないようにする（先に失敗するテスト）。本物の操作部品へのクリックを横取りされたときに止める判定は弱めない
2. 止まったままのとき、エディターの操作チェックから「描画を再開」で戻せるようにする。戻したあとも、同じ横取りでまた止まる
3. 止めたときの文を、デザインシステムの Copy の決まり（何を守ったか・どう直すかを 1 文ずつ、層の名前、内部の言葉を出さない）にする
4. 開発用のビルドフラグで、止めた理由（予想したクリック先と実際のクリック先）を記録できるようにする。製品のビルドには入れない

## 1 回目の調べ（再現できなかった）

本物の YouTube で 8 通り（W・S、絵の層の有無、着せ替え・カードの道具、プレビュー再生中、カードの上の格子状の 15 点）を試したが、止まったままにはならなかった。分かったことは 2 つ。

- 絵の層がない作品では、編集中も G1 はページのクリックを受け取らない（エディターの部品選びが先に受け取って止める）。止まるのは層がある作品だけ
- 起きた照合の不一致は、どれも「入力の直前に操作部品が動いた」ほうで、失敗に数えられず、0.4 秒ほどで戻った

この調べで、コードから「見えていない部品も比べている」「3 回で止めると、再読み込みしか戻す手がない」の 2 つの危ない作りを見つけ、この回で直した。

## 設計書と違う判断

- `docs/operation-safety.md` は「3 回で自動復帰を止め、再読み込みの案内を出す」だった。指示どおり「描画を再開」に変え、設計書も直した。判定と回数は変えていない
- 照合の対象から外すのは「見えていない」部品だけにした。`pointer-events: none` の部品（見えているがクリックを受けない）も同じ形で誤って数えうるが、指示の範囲を越えるので変えていない（下の「気になっている点」）

## 計測

ページの上で入力のたびに動く照合を変えたので、指示どおり 2 組だけ短く測った。`scripts/ui0c/marks.mjs`（`UI0C_MODE=ui0d3`）で、本物の YouTube の検索結果を、変更前（`e6cf9bc`）と変更後で交互に、未ログインの新しいプロファイル（headless、1920×1080）で測った。測った場面は、編集を閉じた起動直後 6 秒・定常 10 秒、エディターの窓で着せ替えの道具のホバーと、カードの道具でカードを選んだあとのスクロール。要約は `docs/benchmarks/g111-input-check.json`。

- 増えた処理は、クリック点を含む操作部品にだけ行う `getComputedStyle`（クリック・キー・フォーカスのときだけで、フレームごとではない）と、通知の比較に足した 2 つの値。2 組の短い計測なので、本計測の交互 4 組は行っていない

## 未確認の点、気になっている点

- **翔太が見た停止そのものは、まだ再現していない**。レトロテーマの作品で起きた可能性があり、指示どおり追っていない。また止まったら、`WW_GUARD_TRACE=1` のビルドでコンソールの `[Web World Themes G1]` を見てほしい（`docs/operation-safety.md` に手順）
- **カードの道具で、サムネイルのプレビュー再生をクリックすると、動画ページへ移動する**（本物の YouTube で確認。G1 ではなく、エディターの部品選びの既存の穴）。サムネイルにポインターが留まると、YouTube はカードの外の要素としてプレビューの `VIDEO` を重ねる。カードの道具はカードの中のクリックだけを止めるので、このクリックは YouTube に渡る。着せ替えの道具は、ページのクリックをすべて止めるので移動しない（ただし「この部品は着せ替えに対応していません」と出る）。記録ありのビルドでは、このとき G1 は横取りと判断していない（「直前に部品が動いた」だけ）
- `pointer-events: none` の操作部品（見えているが、クリックを受けない）も、同じ形で横取りと数えうる。今回は指示の「見えていない」に絞り、変えていない
- 覆いが出た直後の 1 回目のクリックは「部品の位置が変わった」で、失敗に数えない（既存の決まり）。そのため、ページの要素が新しく覆ったときは、自動の復帰を止めるまで 4 回かかる
- 操作チェックの層ごとの行（`image-…: 制限中 / host — …`）は、層の ID と面の ID を出したまま。止めたときの行は層の名前に変えたが、層ごとの行の書き方は今回の範囲の外にした
- 「描画を再開」で制限がいったん消えると、操作チェックの欄は閉じる（今の作り）。また止まったときは、欄を開き直す必要がある

## 次の担当への引き継ぎ

- `SafetyStatus` に `remedy` と `latched` を足した。`stopped` を読む箇所（`scene.ts` の `data-ww-safety`、テストの補助）はそのまま動く
- `pause()` の引数が増えた（`names`・`remedy`）。新しく止める理由を足すときは、Copy の決まりで 2 文を渡す
- `resume()` は失敗の回数を 0 に戻すだけで、判定は変えない。作品のデータや、編集を持たない接続からは呼べない（`studio-host.ts`）。ここを広げないこと
- `WW_GUARD_TRACE` ラベルは、content script を組むビルドすべてで落とす必要がある。新しい計測ビルドを足すときは `dropLabels` に入れる（ないと、照合が合わないたびにコンソールへ出る）
- 試していないこと：S（サイドパネル）での「描画を再開」の e2e（W のタブで確かめた。同じ接続の経路）、横取りの名前が 2 つ以上出る場面の見た目

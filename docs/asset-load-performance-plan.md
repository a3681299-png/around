# VRM読み込み性能の調査範囲

対象: `codex/creator-editor-spike` / `90926a6`。既存Rendererの移設、保存形式・権限の変更は行わない。

1. opt-inビルドだけで、各コンテキスト内の所要時間と共有計測IDを記録する。
2. 現在のStudio→Worker→YouTube経路を実測する。
3. 同じRendererを使う拡張機能ページで、File直接読み込み／IndexedDB Blob直接読み込みを比較する。
4. iframe案は検証用ビルドだけで公開し、オリジン、CSP、バイナリ転送、全画面を確認する。
5. 実測、コード上の事実、未検証の提案を分けて報告する。

区間の開始・終了は同一コンテキストの`performance.now()`で測る。他コンテキストの開始時刻は比較しない。RPCの往復とWorker内部処理、parse全体とテクスチャ・VRM初期化は包含関係があるため単純加算しない。初回描画はCPUのrender、2Dコピー、2回のrequestAnimationFrame後の表示可能時点を区別する。物理ディスプレイへの提示時刻、ドライバ内のコンパイル／転送内訳、正確なVRAM使用量を推測しない。

モデル原本・モデルのスクリーンショットはコミットしない。計測は明示操作でのみ開始し、本文・入力欄・認証情報・ファイル名を収集しない。通常ビルドでは計測・ベンチマーク・iframe公開を無効にする。

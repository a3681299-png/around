# UI0-d 1 回目：着せ替えを作業台へ移す

`docs/ui0d-plan.md` の 1 回目。UI の着せ替えを、サイドパネル（S）と別ウィンドウの Studio（W）でも使えるようにした。浮かぶエディター（F）とページの中の Studio（I）は変えていない。4 つの形すべてで着せ替えが動くことを確かめた。

決めごと（翔太、2026-10-31）のうち、この回で効くのは 2（カードは「動画カードを編集」の道具のときだけ選べる）。1・3〜7 は 2 回目・3 回目で行う。

## 変更点と理由

| どこ                           | 変更                                                                                                                                                                                                                                                                                                                                                                                        | 理由                                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `src/studio/app.ts`            | 接続先のタブの `StudioTarget.targets` から着せ替えのできる部品を選び、`createCreatorPanel` に `skin`（`targets`・`assetUrl`・`import`）を渡す。道具の一覧に「UIを着せ替え」が出る。ページから届く部品の一覧（`skinPage`）を `panel.setSkinPage` へ渡す。Studio のページへのドロップは、差し込み口（`data-skin-slot`）の上か着せ替えの道具のとき、絵の取り込みにする（画像レイヤーにしない） | 計画の 1・1a・1d                                                                                         |
| `src/browser/studio-page.ts`   | 着せ替えの絵のプレビューの URL を、拡張のページが自分で素材の保管庫から読む（`skinAssetPort.load`、ページを閉じるまで使い回す）                                                                                                                                                                                                                                                             | 計画の 1c。ページの側の blob URL は拡張のページから読めないため。新しい通信も権限も要らない              |
| `src/studio/protocol.ts`       | 要求に `import-skin`（`session`・`revision`・`assets`・`slot`）、通知に `skin-page`（部品の一覧）を足した                                                                                                                                                                                                                                                                                   | 計画の 1a・1b                                                                                            |
| `src/browser/studio-host.ts`   | `import-skin`：素材 ID（`asset-` ＋ 64 桁）と差し込み口（6 つの状態と `compact`）を確かめ、素材の情報を保管庫から読み、`editor.importSkin` へ。`skin-page`：`editor.subscribeSkinPage` の結果を、今つながっている port にだけ送る                                                                                                                                                           | 安全の確認は `import-assets` と同じ形。絵の中身は通さず、保管庫にある素材の ID だけを受ける              |
| `src/browser/studio-client.ts` | `import(files, slot?)`：差し込み口があるときは、今の素材の転送のあと `import-skin` を送る。`skinPage.subscribe` を出す                                                                                                                                                                                                                                                                      | 1 枚だけかどうかは Core が判定し、パネルに「1枚ずつ」と出す（F と同じ）                                  |
| `src/editor/controller.ts`     | `importSkin`・`subscribeSkinPage` を足した。部品の一覧を作る条件を「ページの中にパネルがある」から「パネルがあるか、Studio のページが一覧を待っている」にした（250ms の間引きはそのまま）                                                                                                                                                                                                   | 計画の 1a                                                                                                |
| `src/editor/controller.ts`     | カードを「どの道具でも」クリックで選ぶのは、浮かぶエディターがページの中にあるとき（`quickPanel()`）だけにした。W だけがつながっているときも、S と同じく「動画カードを編集」の道具のときだけ選ぶ                                                                                                                                                                                            | 決めごと 2。前は、W だけのとき `panelMode` が既定の `quick` のまま残り、選択の道具でもカードを選んでいた |

F の選び方（どの道具でもカードを選ぶ）は、この回では変えていない。F は 3 回目で消すので、そこで 1 つになる。F のテスト（約 116 件）の多くが選択の道具でカードを選んでいるため、F の選び方を今変えると、2 回目の移し替えの前に判定を書き換えることになる。

## 未確認の点・気になっている点

- 幅 400px の W のタブでは、今の作業台の並び方が右の列（着せ替えのパネルがある）を閉じるので、着せ替えを確かめられない。並び方を窓の幅で切り替える 2 回目（決めごと 3）で、`skin-studio.spec.ts` に 400px を足す（ファイルに注記を残した）
- Studio のページで絵の取り込みに失敗したとき（転送の上限など）の文言は、今の画像レイヤーの取り込みと同じく、パネルの下の文に出ない（`app.ts` の `void connection.import(...)` がエラーを捨てる、前からの動き）。2 回目で、作業台に保存の失敗の表示（UI0-b）を移すときに一緒に直す
- S の実サイトの確認は、画面の外の本物のサイドパネルで 1 回だけ。ノート PC の幅（YouTube が縮む）での見た目は、2 回目のスクリーンショットで見る
- 着せ替えのプレビューの URL（拡張のページの blob URL）は、Studio のページを閉じるまで解放しない。F の content script と同じ扱い

## 次の回（2 回目）への引き継ぎ

- `openEditor`（`tests/helpers/editor.ts`）を使って、F・I の e2e を W のタブへ移す。変えてよいのはパネルを探す場所と開き方だけ
- S と W の並び方を幅で切り替えるときは、`studio-page.ts` の `sidePanel`（＝背景の安全の確認と同じ値）を並び方から外す。`studio-client.ts` の `ownerTab` の選び方と、背景の `owner` の確認は `surface=sidepanel` のまま残す
- 決めごと 1 の確認：`workbench.ts` は `createWorkspace` を土台にしている。3 回目の前に、`workspace.ts` のうち F だけが使う部分を洗い出して報告に書く

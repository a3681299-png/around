`tests/design-migrations.spec.ts`で完全一致、入力の非変更、検証済み印・凍結・構造共有との整合、
旧版で禁止されていたフィールド・形式・上限を確認する。

依頼Dの編集ベンチマークは元の`tests/editor-benchmark.spec.ts`をそのまま使う。

しきい値による合否判定は行わない。

変更前に計測経路を確認した1組の中央値：32レイヤー9,424bytesは0.0514ms、
32ルール×8キー35,724bytesは0.0627ms、32ルール×64キー163,500bytesは0.0591ms。
Studioへの追加差分はいずれも499bytesだった。これだけで変更後との優劣を判断しない。

## スクロール評価の経路

既存の軽い経路と`evaluateTransforms`を、グループ付き4レイヤー・固定180入力で比較した。
180件すべてで出力が一致しなかった。軽い経路にはない`localRotationDeg`が汎用経路にはあり、
汎用経路はポインターの記憶を含むmotion状態も返す。評価を汎用経路へ統一した。子の座標・回転とmotion状態までそろえるための変換処理を共通化し、別経路を維持しない。

`tests/signal-evaluation-benchmark.spec.ts`は準備済みレイアウトでスクロール→不透明度を評価し、
2/32レイヤー・8/64キーを各100回ウォームアップ後に1,000回測る。
比較コマンドの4番目の引数を`world`にすると、同じハーネスで変更前後のWorld評価を交互に測れる。
変更前の32レイヤー×64キーの初期中央値は0.0232msだった。

## 登録表と点

`src/signals/registry.ts`に、既存11シグナルの種類・値型・座標系・軸・評価・購読・プリセットを集めた。
数値シグナルの型、入力検証、一覧、World評価、Hostの購読判断はこの表を参照する。
マスクの点・状態の検証と評価も同じ表を参照する。スクロール進捗の計算は1つにした。

`tests/signal-registry.spec.ts`の仮シグナルは登録1項目だけで型・検証・評価・一覧・購読・継続フレーム要求に反映される。
追加取得値のための任意の`samples`マップは、登録表の`hostSample`指定・値型・既存入力相当の範囲で厳密に検証する。
未登録IDは受け付けず、現在の本番シグナルには追加の取得値を実装していない。既存の作品保存形式は変えていない。

`src/world/points.ts`はマウス・アンカー中心・レイヤー中心・固定点を純粋に解決する。
欠落したアンカーや不正な座標はundefined。`tests/spatial-points.spec.ts`で登録1項目による仮の点の追加と、
既存anchor/layerの距離・角度の意味を確認する。点の接続は評価コアのAPIで用意し、作品への新しい保存項目やUIは追加しない。

## 作品の移行

`src/design/migrations.ts`の10個の純粋関数でv1→v2→…→v11と進める。
各段は当時のフィールド・素材形式・再生設定・件数・シグナル能力を拒否条件として持ち、
v1の素材配列とv2のlocked既定値だけを補う。最後に`schema.ts`のv11専用検証で必須項目・数値・参照を再構築する。
中間値は未検証のままで、`readDesign`が最終検証を通した後にだけ既存の検証済み印を付ける。
14件すべてで変更前の結果と完全一致し、凍結入力の非変更・全10段の個別実行・旧版の禁止項目もテストする。

## 最終計測（Windows / Node 24.16.0）

起点`d1a552e`と実装`56feb94`を同じ仮想パスのesbuildバンドルで比較した。
元のDベンチマークは変更せず、前→後を7組、後→前を7組、それぞれ別プロセスで交互実行した。
表の中央値は各回の中央値の中央値、最大は全回の最大。外れ値は除外していない。
生データ・CPU・各回の値は`signal-registry-schema-chain-benchmarks.json`に記録した。

| 作品                             | placements中央値 前→後 |      最大 前→後 | Studio差分 前→後 |
| -------------------------------- | ---------------------: | --------------: | ---------------: |
| 32層 / 9,424bytes                |      0.04730→0.04685ms | 0.5403→0.8499ms |     499→499bytes |
| 32層＋32本×8キー / 35,724bytes   |      0.05875→0.05845ms | 0.5745→0.5195ms |     499→499bytes |
| 32層＋32本×64キー / 163,500bytes |      0.05490→0.05730ms | 0.5601→0.6089ms |     499→499bytes |

短いウォームアップでは最大規模に0.0024ms（約4.4%）の増加が残った。
最新版の検証キーを毎回生成せず再利用し、検証の内容と位置は保った。
一時的な処理内訳計測では、変更した素材レイヤーの検証自体の増加は見られず、短い実行のコマンド/JIT初期化の影響が残る。
原因をJITだけに断定はできない。元の計測で「全数値が悪化しない」という条件は完全には満たせていない。
安全検証の省略や、依頼範囲外の編集コアの調整は行っていない。

追加診断として2,000回ウォームアップ後に100回計測した（5組、同じ前→後の交互実行）。
これは元のD計測を置き換えるものではない。

| 作品         | 追加診断の中央値 前→後 | 追加診断の最大 前→後 |
| ------------ | ---------------------: | -------------------: |
| シグナルなし |        0.0379→0.0381ms |      0.2648→0.2913ms |
| 32本×8キー   |        0.0503→0.0500ms |      3.6945→3.0640ms |
| 32本×64キー  |        0.0505→0.0497ms |      0.9112→4.8008ms |

再現コマンド：

```powershell
node scripts/compare-editor-benchmark.mjs d1a552e 7
node scripts/compare-editor-benchmark.mjs d1a552e 7 editor after
node scripts/compare-editor-benchmark.mjs d1a552e 5 editor before steady
node scripts/compare-editor-benchmark.mjs d1a552e 5 world
```

World評価は5組で比較した。スクロール→不透明度の2層・8/64キーの中央値は
0.0021→0.0042ms / 0.0021→0.0025ms、32層・8/64キーは0.0263→0.0338ms / 0.0229→0.0325ms。
32層×64キーの最大は0.7616→0.7161ms。汎用化による中央値の増加は0.0096msだった。
シグナル・motionがない場合は準備済みレイアウトをそのまま返す。

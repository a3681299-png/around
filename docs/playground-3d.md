# Playground の3Dの板

2026-11-07。基点は `codex/playground-mirdo` の `6e789e1`。

## 完成基準と見え方

| 場面                     | 撮影で見たもの                                                                                                                               |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 適用前 → 適用中 → 適用後 | 同じプレーヤーと操作部品を保ったまま、カメラが引き、板が傾いて部屋が見える。移行は約560 ms。最初の HTML テクスチャが出るまで平らな画面を残す |
| 傾いた板での操作         | ボタン、ドラッグしたシークバー、検索欄が画面の位置で操作できる。日本語の入力とフォーカス枠を撮影で確認。移行中は `inert` で入力を止める      |
| ミルド                   | 腰を板の上端と下端に置く。操作部品を避けて右外周を回る。座り待機と移動には Quaternius 由来の検証済み VRMA を使う                             |
| 視差・動画の光           | ポインターを外側の左右に動かすと、手前の板・鉢と奥の窓・棚の位置関係がずれる。動画の標本で床・壁・板の縁の色が変わる                         |

Chrome 157 は現行の HTML-in-Canvas、Chromium 153 はフラグありで旧 API、フラグなしで CSS3D。HTML の取り込みと操作面の同期は `src/browser/html-in-canvas.ts` に置いた。CSS3D では同じカメラで部屋とネイティブ DOM を表示し、動画はネイティブのまま再生する。小さい画面やハードウェア描画が使えない環境では基本版を使う。

[HTML in WebGL canvas](https://developer.chrome.com/docs/web-platform/html-in-canvas/webgl) · [HTML-in-Canvas の API 変更](https://developer.chrome.com/blog/html-in-canvas-ot-changes) · [CSS3DRenderer](https://threejs.org/docs/pages/CSS3DRenderer.html)

動画は HTML とは別のテクスチャにし、アスペクト比と透明部分を元のプレーヤーに合わせた。ガラスは低解像度で描いた部屋を参照し、屈折を縁に限定した。UI のテクスチャはブラウザーが発行する paint に応じて転送する。動画の色は360 ms以上間隔を空けて標本化し、色と明るさを補間する。reduced-motion では即時に切り替え、視差・ミルドの移動・動画光の変化を止める。

仮の部屋の差し込み口は `src/playground/room.ts` の `mountRoom`。板・動画・ミルドとカメラの投影は Playground 内に置いた。エンジンの中核に差分はない。

## ローカルビルド

```powershell
$env:WW_PLAYGROUND_PRIVATE_ASSETS = 'C:/wwt-private'
npm run build:playground
```

通常の Playground ビルドは `wwt-private-assets` のミルドと、ミルド向けに変換した Quaternius の `Sitting_Idle_Loop`・`Walk_Loop` を読む。モデルとモーションの検査に加え、出力検査を通す。CI の `WW_PLAYGROUND_TEST=1` はリポジトリ内の生成フィクスチャでも動く。ビルドの静的配信には WebM の HTTP Range 応答が必要。ミルドを含む画像・録画と生成物はローカルで扱う。

撮影した画像と録画は隔離チェックアウトの `.work/review-playground-3d/` に置いた。

## 計測とテスト

デスクトップの Ryzen 5 5600X、Radeon RX 6800（ANGLE／D3D11）、Chrome 157.0.8103.38、画面165 Hz、表示あり・画面外、1280×800で計測した。同じミルドと動画を使い、基本版と HTML-in-Canvas 版を2組交互に実行。主スレッドの値は、各ブラウザーフレームでアプリの rAF コールバックにかかった時間の合計。定常は各約4.3秒。3D側の定常中央値が0 msなのは、フレームの一部だけで描画するため。

| 指標                          | 基本版・組1 / 組2      | 3D版・組1 / 組2                |
| ----------------------------- | ---------------------- | ------------------------------ |
| 適用から6秒の CPU 合計        | 1121.5 / 388.5 ms      | 1292.3 / 580.7 ms              |
| 適用から6秒の CPU 中央値・p95 | 0.2・1.1 / 0.2・1.1 ms | 0.0・2.2 / 0.0・2.0 ms         |
| 定常 CPU 中央値・p95          | 0.2・0.9 / 0.2・0.9 ms | 0.0・1.8 / 0.0・1.8 ms         |
| 定常 3D描画 GPU 中央値・p95   | —                      | 0.562・0.658 / 0.560・0.653 ms |
| 定常 rAF 間隔 p95             | 6.2 / 6.1 ms           | 6.1 / 6.1 ms                   |
| 定常 動画落ち／総フレーム     | 0/27 / 0/27            | 0/26 / 0/27                    |

適用から6秒の CPU 合計の組差中央値は +181.5 ms。CPU の50 ms以上の処理は基本版が各1件、3D版が2件／0件。定常のGPUタイマーでは1組目に50 ms以上が4件、2組目は0件。動画を停止してUIを静止させた約1.6秒の HTML テクスチャ転送は両組とも0回、再生中は41回／43回。

ソフトウェア描画を強制した事前計測では、SwiftShader の GPU タイマー p95 は73.6〜84.0 ms。本番ビルドで SwiftShader から基本版に戻ることを確かめた。この PC に内蔵 GPU はなく、ノート PC の性能合否は保留。

型チェック、lint、素材を含む出力の検査が通過。unit は599件通過、2件スキップ。e2e は `tests/playground.spec.ts` の11件が通過。実際の Playground は Chrome 157 と Chromium 153 のフラグ有無の3経路で撮影し、別途 SwiftShader で基本版への切り替えを確認した。中核差分がないため e2e は対象 spec に絞った。CI と実 YouTube のテストは実行していない。

## Claude Code に見てほしい所

- 板が移る最初の数コマと、ミルドが立つときの上端。現状の移動は歩行クリップを外周の軌道に載せたもので、足が空中を歩いて見える短い区間がある。
- ノート PC の内蔵 GPU で、実際の Playground の適用直後と動画再生中を計測する。表示倍率を変えた CSS3D の操作位置も確認する。
- 部屋を差し替えるときは `mountRoom` で、動画光の位置・縁の映り込み・明るい部分の文字を見比べる。

後回し。板が右へ寄った状態でミルドが上端から立ち上がると、録画の一部で頭が画面上端に切れる。

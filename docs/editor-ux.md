# クリエイターエディターのUI再設計

## 調査と方針

起点は `3569568`。`panel.ts` に素材追加、一覧、カード設定、変形、再生、マスク、シグナルが縦に並び、一覧にもスクロールがある。複数選択は修飾キーの説明文だけで、グループ化の入口が選択後まで隠れている。各行の複製・削除も一覧を圧迫している。

YouTube自体をキャンバスとして残すため、通常は片側のコンパクトな作業パネルを使う。「レイヤー」「プロパティ」を切り替え、必要なら両方を並べる。左右配置、幅の調整、折りたたみを用意する。各作業領域にスクロールを一つだけ設け、保存と履歴は固定する。

- レイヤー行のチェックで、キーを使わず複数選択。選択数、グループ化、制約の理由を一覧の上に表示する。
- 行にはサムネイル、種類、名前、表示、ロックを置く。複製・削除・グループ操作は共通ツールバーと右クリックメニューへ移す。ダブルクリックで名前を編集する。
- プロパティは選択対象に応じて表示する。基本変形、再生、光とマスク、振る舞いを区分し、折りたためるようにする。グループの未対応の拡縮・回転は表示しない。
- グループ化後はグループを選択し、「光とマスクを設定」を次の入口にする。解除後は子の選択を維持する。既存の同一アンカー・連続順・ネスト禁止の判定を再利用する。
- 空の一覧、短い初回ガイド、ヘルプ、操作フィードバック、保存状態を設ける。未来のタイムラインの空UIは作らない。

## 責務と互換性

`layer-tree.ts` は階層と選択UI、`panel.ts` は編集操作の入口、作業領域の切り替えは別モジュールへ分離する。サムネイルは既存Rendererの表示から静止画を取得し、素材の再保存や再生器の追加を避ける。非同期結果は終了後に反映しない。

DesignDocument v7、asset ID、World Runtime、保存、移行、履歴の形式は変更しない。幅・配置・表示領域は編集セッション内だけで保持する。初回ガイドを閉じた状態だけ、既存の `chrome.storage.local` に作品と別のキーで保存する。新しい権限・依存パッケージ・外部通信は不要。

## 実装と検証

1. チェック選択、共通操作、階層一覧、グループ化理由、サムネイル。
2. 作業領域と対象別プロパティ、幅調整、左右配置、開閉、ガイド。
3. 初心者のマウス操作フロー、ロック、混在アンカー、32レイヤー、保存・破棄・履歴を回帰検証する。
4. 型チェック、lint、ビルド、既存テスト。拡張を読み込んだChromeのfixtureで操作と画面を確認し、実YouTubeの確認結果を分けて記録する。

既存テストは必要な作業領域を明示的に開くように更新する。作品や評価コアの検証内容は維持する。`main` とルートの `dist` は変更しない。

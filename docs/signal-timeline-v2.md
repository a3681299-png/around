# Signal Timeline v2

## 実装前の設計

起点は `21312c0`（DesignDocument v8 / Runtime 1.1）。main と通常版 dist は変更しない。

- Host は既存のマスクと同じポインター購読を使う。位置と採取時刻を入力に渡す。Runtime は DOM や実時計を読まない。
- シグナルの導出を純粋関数へ集約する。X/Y は画面または配置アンカー内の比率、距離は基準矩形の対角線に対する比率、角度はマウスから基準中心への度数、速度は CSS px/s。レイヤー距離の基準は手動配置の中心とし、評価結果を自己参照しない。
- キーの横軸は入力範囲で正規化する。値は不透明度（0〜1）、X/Y の加算オフセット（CSS px）、回転の加算オフセット（度）。1つの対象プロパティにつき有効なルールは1本。異なるプロパティは同時接続できる。合成方法を保存し、未対応の合成を黙って解釈しない。
- `motion` は素材形式に依存しないレイヤー設定。直接・遅延・速度／加速度付き追従、停止半径、移動方向への回転を持つ。手動配置とキーの評価後に追従オフセットを加える。グループの移動・回転は子へ剛体変換として適用し、子のエフェクトも維持する。
- Runtime 状態はポインター履歴と各レイヤーのオフセット・速度・向きを持つ。遅延は指数応答、追跡は小さい時間刻みで加減速する。非表示タブでは積分せず、長時間停止後の追いつき計算には上限を設ける。
- 描画は評価済みの配置を使う。選択枠も同じ評価結果へ追従する。直接編集は保存された基本変形への操作を保ち、動作プレビューと区別する。
- DesignDocument v9 へ純粋移行し、v1〜v8 の読み込みを維持する。旧テイクと開発用記録も読み込む。アセット保存方式・権限は変更しない。
- 履歴依存の動作を録画するときは、評価に使った入力を間引かず保存する（上限3600件／4MiB／3分は維持）。通常の波形記録は20Hz。これにより記録点の再評価を保証し、補間位置のプレビューと区別する。テイクは作品と別保存のまま。
- ライブ／テイク／単一シグナルのプレビューは排他的に供給する。シークは初期状態からの入力履歴を疎なチェックポイントで再評価する。旧来のスクロール投影は維持し、マウス信号の波形・投影を拡張する。

## 段階と検証

1. 純粋なシグナル導出・加算キー・モーション評価・移行と単体テスト。全体テスト後コミット。
2. Host／DOM描画／共通Studio UI を接続。各形式、グループ、マスク、直接編集、保存・破棄・Undo を回帰検証してコミット。
3. 録画・速度信号・シーク・波形・入力分離を完成。決定性と実際の操作フローを検証してコミット。
4. 全体テスト、性能計測、実YouTube確認。fixture と実サイトの証拠を区別して結果を追記。

拡縮、ばね物理、経路探索、3D、複数ルールの合成は今回実装しない。

## 使い方

1. 素材を追加して、一覧または画面上で選ぶ。PNG・GIFなどの既存素材とグループを同じように扱う。
2. プロパティの「モーション」で「マウスを追いかける」をONにする。初期値は加速追従、最高400px/s、遅延180ms、停止距離48px。
3. 「直接追従」「なめらかに遅れて追従」「加速して追いかける」を切り替える。加速追従では最高速度と加減速、全方式で停止距離と向きを設定できる。画像の前方が違う場合は角度補正を使う。
4. キーで制御する場合はSignal Timelineを開き、「対象」「入力」を選んで接続する。キーをドラッグするか、入力値・オフセット・補間を数値で編集する。入力範囲も変更できる。
5. 録画ボタンでページ上の操作を記録し、停止後に時間表示で確認する。シーク／逆再生中はライブ入力を遮断する。「ライブ入力に戻る」で実ページの入力を使う。
6. 作品は上部の保存、操作記録は「テイクを保存」で別々に保存する。保存済みテイクはライブラリから再読込できる。

録画中に作品を変更すると、その時点で録画を終了する。途中までの入力は残す。キー操作のUndo／Redoと、作品全体の保存・破棄は既存Editor Coreを使う。

## 入力と単位

| 入力             | 基準・単位                                                                          |
| ---------------- | ----------------------------------------------------------------------------------- |
| スクロール       | ページの移動可能範囲に対する0〜100%。移動不可なら0%                                 |
| マウスX/Y        | 画面、またはレイヤーの配置アンカー内の比率。アンカー外では0〜100%を超える生値も扱う |
| レイヤーへの距離 | マウスと**保存された基本位置**の中心との距離。配置基準の対角線を100%とする          |
| アンカーへの距離 | 配置アンカーの中心との距離。同じ対角線基準                                          |
| 対象への角度     | マウスから基本位置／アンカー中心を見た角度。右0°、下90°、範囲−180〜180°             |
| マウス速度       | 位置の採取時刻から計算したCSS px/s。最後の入力から100ms後には0として評価            |

画面アンカーの素材で「配置アンカー」を選ぶと画面基準になる。プレイヤー基準にしたい場合は、素材の「基準」をプレイヤーへ変更する。参照が消えた場合は描画を止め、見つかった時点で再評価する。

不透明度は0〜1の置換。X/YはCSS px、回転は度数の加算オフセット。キーは横軸を入力範囲内の0〜1として持ち、縦軸は対象の実単位を保存する。不透明度と異なる位置・回転の値を、0〜1へ無理に丸めない。同じプロパティへの有効なルールは1本まで、別プロパティは併用できる。`blend` は不透明度の `replace`、変形の `add` を検証し、未対応モードは拒否する。

## モジュールと評価順序

| モジュール                                                | 責務                                                              |
| --------------------------------------------------------- | ----------------------------------------------------------------- |
| `signals/keyframes.ts`, `keyframe-schema.ts`, `motion.ts` | データ型・上限・信頼できないJSONの検証                            |
| `world/signals.ts`                                        | アンカー／基本位置からの座標変換と速度の導出                      |
| `world/motion.ts`                                         | 点を目標とする追従計算。DOMや素材形式、マウス取得処理に依存しない |
| `world/transforms.ts`                                     | 基本配置→キーのオフセット→追従→親子の変換を合成                   |
| `world/takes.ts`, `take-signals.ts`, `signal-preview.ts`  | 履歴再評価・シーク・波形／ゴーストの導出・数値入力のプレビュー    |
| `host/signals.ts`, `world-session.ts`, `timeline.ts`      | 共通の入力購読、採取時刻、RAF、録画時計、排他的な入力切替         |
| `renderers/dom/scene.ts`, `effects.ts`                    | 評価済み配置とマスクを既存DOM/CSSへ反映。選択枠も同じ配置を使用   |
| `editor/motion-panel.ts`, `studio/signal-timeline.ts`     | 共通Studio UI。編集処理はEditor Coreへコマンドで渡す              |

`WorldState.motion` はコントローラーごとのオフセット・速度・向きと、最後のポインター採取値を持つ。固定の作品配置を書き換えない。設定変更でも現在位置を引き継ぐ。遅延は指数応答、加速追従は最大1/240秒の刻みで計算し、1回の評価で積分する時間は250msまで。長い中断の後に何秒分も一度に走らせない。

グループは子の基本配置から基準矩形を作り、親の移動・回転を子へ合成する。個別のキーとマスクは残す。直接ドラッグ中は動作の入力を固定し、画面上の差分を基本配置へ戻す。ロックされた子のあるグループではモーション設定を保護する。グループ解除は、追跡と位置・回転の接続をOFFに戻してから行う。

タブ非表示・動きを減らす設定では追従の積分を止める。停止範囲に入って落ち着くとRAFを止める。テーマOFF／強さ0%ではセッションと入力購読、描画を撤去する。画面外でも追跡で戻ってくる素材は計算を継続する。

## 保存と再現性

DesignDocument v9、World Runtime 1.2.0。v1〜v8は純粋なパーサーでv9へ移行する。旧データは読み込みだけでストレージへ書き戻さず、保存時に新形式を使う。アセットDBとasset IDは変更しない。v8のfixtureはv7の既存fixtureと`21312c0`の実装にあるルール形式から作成した回帰用データであり、実ユーザーから採取した保存データではない。

テイク形式v1は維持し、Runtime 1.1のテイクも受け入れる。保存するものは数値入力と再評価の初期状態であり、作品のキーフレームや画像原本はテイクへ入れない。ページ本文・URL・フォーム文字列・認証情報も記録しない。

通常の連続記録は20Hz。追跡や速度信号のように履歴が必要な作品では、評価に使った入力を間引かず記録する。予算は3600入力／最大3分／4MiB文字相当、保存8件／合計16MiB文字相当。追跡中は件数上限へ先に達することがある。32入力ごとの状態キャッシュから前向きに評価し直すことで、逆シークでも履歴を復元する。同じ初期状態・作品・入力履歴・Runtimeバージョンで、同じ数値評価を得る。

ゴーストは入力値を通過した位置の表示用データ。独立したキーとして保存しない。スクロールはページ高さ変動を含めて投影し、マウス信号は記録点間で投影する。角度の±180°の折り返しは直線で結ばない。記録点間の曲線表示は近似であり、実際の再生は入力履歴を使う。

再現対象は位置・向き・不透明度・マスクなどのRuntime評価。YouTubeの映像／DOM全体やGIF等のコマ位相は再現しない。記録時のviewportとアンカーを評価・配置に使うため、異なるウィンドウ幅では一部が画面外になる場合がある。

検証と性能、未確認の組み合わせは [検証結果](signal-timeline-v2-verification.md) を参照。

# 作品と設定のバックアップ

設定画面の「作品と設定のバックアップ」から専用ページを開く。.aroundbackup 1ファイルで、別のChromeプロファイル・別の拡張IDへ移せる。追加権限・外部サーバー・downloads APIは使わない。ファイルは利用者が保存する。

## 対象

| 含めるもの                                                 | 保存元                                           |
| ---------------------------------------------------------- | ------------------------------------------------ |
| 保存済み作品                                               | chrome.storage.local の around.design.\<siteId\> |
| 原本素材すべて                                             | around-assets / assets                           |
| 保存済みテイク                                             | around-signal-takes / takes                      |
| 表示設定・制作モード                                       | chrome.storage.local の既知の設定キー            |
| Studioの配置・タイムライン・ガイド設定、設定ウィンドウ位置 | 既知の制作UI設定キー                             |

編集中の下書き、Undo/Redo、タブ番号、接続状態、chrome.storage.sessionの接続復旧情報、実行中のleaseは移さない。操作前に作品とテイクを保存し、編集タブとStudioを閉じる。元のプロファイルは残す。

## 操作

1. 元の拡張の設定画面から専用ページを開き、表示される拡張IDを記録する。
2. 「バックアップを書き出す」を押す。検証後にダウンロードが始まる。ブラウザーの保存操作を完了する。「検証済みバックアップを保存」のリンクから保存し直すこともできる。
3. 移行先の専用ページでファイルを選ぶ。表示設定を移したくなければ、適用のチェックを外す。
4. 「内容と衝突を確認する」を押し、作品・素材・テイクの件数と作成日時を確認する。
5. 「確認したバックアップを読み込む」を押す。直前にも全検証と衝突確認をやり直す。
6. YouTubeとStudioを再読み込みし、作品・保存テイク・テーマ設定を確認する。旧拡張を整理するのは確認後にする。

## 検証と衝突

- 形式・バージョン・既知のフィールドだけを許可する。JSONのUTF-8・長さ・SHA-256、素材数、原本の合計サイズ、ファイル末尾まで確認する。
- 各作品は parseDesign、各テイクは parseSignalTake に通す。作品の保存形式v1〜v11は変更しない。
- 各原本のサイズとSHA-256を確認し、通常取り込みと共有する validateAssetBytes で形式/MIME、GLB/VRM構造、モデル内テクスチャ、画像のデコードを検証する。動画コンテナー・Lottieの制限も従来どおり。再利用する既存素材も、メタデータとSHA-256を確認する。
- 作品が参照する原本がファイル内に揃っていること、レイヤーと素材形式が合うことを確認する。作品データからJSを実行しない。
- 原本は1個32MiB（GLB/VRMは64MiB）、合計256MiB・128個。保存テイクは8個・JSON合計16,777,216文字（UTF-16コード単位）。テイク単体の従来の制限も維持する。
- バックアップのJSONは80MiB、ファイル全体は336MiB。作品と設定は復元先の既存データを合わせてChrome Local Storageの10MiB以内とする。制作UI設定は64KiB以内、作品は16サイト以内。書き出しにも同じ検証を適用する。
- 同じ素材ID（内容ハッシュ）は既存原本を再利用する。素材名が違う場合は移行先の名前を残す。作品・テイクは同じID・同じ内容なら再利用し、同じID・異なる内容は全体を拒否する。同じサイトの異なる作品も拒否する。自動で改名・上書きしない。
- 「設定を適用する」を選んだ場合だけ、既知の表示設定とファイル内の制作UI設定を置き換える。移行先だけにある作品・テイク・設定は消さない。
- 元のタブのleaseは復元しない。保存作品の原本は作品の参照で保持する。未参照の原本も失わないよう、復元時だけ backup-library の保管lease（tabId=-1）を付ける。通常の素材上限に含める。未参照素材の管理UIは今回は追加していない。

SHA-256は破損・不一致の検出であり、作成者を保証する署名ではない。チェックサムを作り直したファイルでも、型・形式・素材・作品・テイクの検証は省略しない。バックアップは暗号化しない。

## 失敗時

形式・破損・上限・衝突による拒否では保存先を書き換えない。Service Workerが専用ページの実在するトップレベルClientを確認し、他の拡張ページ・YouTube・サブフレームからの操作は拒否する。専用ページはWeb Accessible Resourcesに含めない。

Chrome Storageと2つのIndexedDBをまたぐ単一トランザクションはない。全検証後に原本、テイク、作品・設定の順で追加する。ディスク不足・Worker終了などのI/O障害では、**新しく追加した原本・テイクだけが残る場合がある**。既存作品・テイク・原本は置き換えない。同じファイルをもう一度確認して読み込めば同じIDを再利用する。設定適用を選んだ場合の既存設定の置き換えは利用者の明示操作として行う。

書き出し中に作品・設定が変わった場合も拒否する。復元と同時に編集しない。ページを閉じて応答を受け取れなかった場合は、同じファイルで再度確認する。元の拡張とバックアップは移行先の確認が終わるまで保持する。

## テスト

tests/backup-data.spec.ts で形式・型・バイト上限・SHA-256・破損・MIME・参照欠落・衝突・送信元を検証する。tests/backup.spec.ts は実際の書き出し、別プロファイルの別拡張IDへの復元、作品データ・原本・テイク・設定・画面の完全一致、繰り返しの冪等性、破損時に変更しないことを実物のChrome APIで確認する。素材は自作fixtureだけを使う。

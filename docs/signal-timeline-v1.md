# Signal Timeline v1

## 起点と責務

起点は実験ブランチ `9c9cd88`。現在のHost入力、純粋なWorld Runtime、DOM Renderer、Editor Core、共通Workbenchを拡張する。mainと通常版distは変更しない。Chrome権限と依存パッケージは追加しない。

- **作品ルール**: DesignDocument v8の `signalRules[]`。対象レイヤー・プロパティ、駆動元、座標系、入力範囲、キーフレーム、補間、評価・平滑化・合成方針を持つ。v1はページYスクロール進捗、opacity、往復追従、平滑化なし、置換。時間を特別扱いせず、ソースの追加で拡張する。v1では同じプロパティへの複数の有効ルールを拒否し、未対応の合成を推測しない。
- **Runtime**: 生のscroll位置とスクロール可能範囲から進捗を計算する。入力時刻に関係なく同じ位置を同じカーブで評価する。UI、DOM、時計、乱数へ依存しない。グループと子のopacityは既存の階層で合成し、マスクも維持する。
- **Editor Core**: ルール変更を既存の編集コマンドと履歴へ接続。ドラッグはbegin/endで1操作。レイヤーの削除・複製・グループ解除でルール参照を整合させる。ロックを尊重する。
- **Studio UI**: 同じWorkbenchへ折りたたみ式のSignal Timelineを追加。パネル内に置き、YouTubeへ領域を追加しない。シグナル空間の横軸は進捗%、縦軸は不透明度%。テイク表示の横軸は記録時間。両方にズーム・横スクロール・再生ヘッドを用意する。
- **Hostとテイク**: 明示的な録画だけを許可。既存World入力検証・記録を再利用し、連続値は20Hz、出来事・状態遷移は境界でも記録する。3分・3600サンプル・4MiB文字相当のいずれかで停止。時刻、順序付きイベント、マウス・生scroll・範囲、viewport、意味的アンカーだけを保持する。ページ本文、URL、文字入力は記録しない。テイクは作品と別のIndexedDBへ保存し、素材を複製しない。保存は8件・合計16MiB文字相当までとし、超過時に既存テイクを自動削除しない。
- **入力切替**: live / recording / playback / pausedを明示。再生・シーク時は記録入力だけをRuntimeへ渡す。実サイトへ操作を再送しない。シークと逆方向は初期状態から必要な入力を再評価し、状態を復元する。終了・OFFで購読と再生処理を止め、ライブへ戻す。
- **投影**: テイク中に各キーの進捗値を通過した時刻を求める。往復では複数のゴーストを表示する。ゴーストは派生表示で、作品にもテイクにもキーとして保存しない。

## 段階

1. **ルールエンジン**: 厳格なv8移行・検証、純粋な補間、raw scroll入力、DOM反映、速度非依存・既存機能の回帰。
2. **キーフレームエディター**: カーブとキーの直接編集・数値入力・線形/イージング、Core履歴、保存・破棄、Studio共通UI。
3. **録画・再生**: 制作用Hostセッション、テイクの独立保存、通信、波形、入力隔離、再生・停止・シーク。
4. **投影と仕上げ**: 時間/シグナル表示切替、ゴースト、スクリーンショット、決定性・負荷測定、実YouTubeの一連操作。

各段階で型チェック・lint・ビルド・既存全自動テストを実行し、成功を確認してコミットする。実サイト検証はfixtureと分けて記録する。未対応のモードや素材形式の追加、タイムライン上の映像編集、式・任意スクリプトの実行は行わない。

## 互換性

v1〜v7は純粋なparseDesignでv8へ再構築する。ルールなしの見た目を維持する。Runtimeは1.1へ更新し、旧開発用記録はルールのない入力として読み込む。新テイクは別形式で、作品の配布に同梱を要求しない。既存アセットDBは変更せず、テイク専用DBを用意して素材のlease・Undo中の保持と干渉させない。

## 操作

1. テーマをONにしてChromeサイドパネルを開き、画像・アニメーションまたはグループを選ぶ。
2. 下端の **Signal Timeline** を展開し、**スクロールに接続**。0%で透明、50%で不透明、100%で透明の3キーが入る。実ページのスクロールが同じ進捗なら、操作速度に関係なく同じ値になる。
3. ダイヤをドラッグして進捗と不透明度を編集。数値入力、補間選択、空白のダブルクリックまたは＋でキー追加、Deleteで選択キーだけを削除できる。ドラッグはUndo 1回。ルール接続中の手動不透明度は非表示になる。
4. 黄色のヘッドやキーを操作するとシグナル空間のプレビューへ切り替わる。**PREVIEW** 表示中は実ページの入力を混ぜない。ライブアイコンで **LIVE** に戻すと実スクロールへ追従する。
5. 録画ボタンで明示録画し、ページを操作して停止。テイク（時間）表示の緑線が記録した進捗、紫線が現在の不透明度ルールの投影。半透明のダイヤは同じキーの通過位置で、クリックすると元のキーを編集する。独立したキーとして保存しない。
6. 再生／一時停止、停止、ヘッドのドラッグ、秒の数値入力でテイクをプレビュー。逆再生・0.5×・1×・2×を選べる。ページ自体のスクロールやクリックは再送しない。
7. 上部の保存は **作品ルール**、タイムラインの **テイクを保存** は **操作記録**。テイクはライブラリから読み込み・削除でき、作品の保存・破棄・Undoには混ぜない。作品の配布にテイクは不要。

横ズームとスクロール、上端の高さ調整、折りたたみに対応。設定はワークスペース側へ保存する。公式パネルと独立Studio、従来インページStudioは同じUI・Coreコマンドを使う。クイック編集のコンパクトなページツールバーは重複するタイムラインを持たない。

## モジュール

| 境界          | 主なファイル                                                                                    | 責務                                                              |
| ------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 作品・検証    | `signals/keyframes.ts`, `signals/keyframe-schema.ts`, `design/schema.ts`                        | v8の宣言的ルール、v1〜v7移行、上限・参照・未対応モードの拒否      |
| World Runtime | `world/keyframes.ts`, `world/takes.ts`                                                          | 純粋な補間、raw入力の正規化、記録シーク・状態復元、派生ゴースト   |
| Host          | `host/signals.ts`, `host/timeline.ts`, `host/world-session.ts`                                  | 遅延購読、明示録画、時計・可視性、入力切替、1フレーム内の評価集約 |
| Editor Core   | `editor-core/session.ts`, `editor/groups.ts`                                                    | 共通ルールコマンド、Undo、保存・復旧、複製・削除時の参照整合      |
| Studio        | `studio/signal-timeline.ts`, `studio/timeline-transport.ts`                                     | キー編集、波形・投影、テイク操作。Chrome APIを使わない            |
| 通信・保存    | `studio/protocol.ts`, `browser/studio-{client,host}.ts`, `browser/take-{storage,repository}.ts` | 認証済み通信、薄いテレメトリー、テイク専用IndexedDB               |

`world/takes.ts`は32入力ごとの状態キャッシュと同じジオメトリの配置再利用で逆方向・シークを復元する。フレームの丸ごとキャッシュはしない。ゴーストはrawスクロール位置と範囲を補間して交点を求めるので、ページ高さが変わる場合も単純な進捗の線形補間に置き換えない。投影キーの描画は最大256個、純粋な計算は4096個まで。紫の投影曲線は201点の表示用サンプリングで、Runtime評価や元のテイクを間引かない。静的グラフはテレメトリーごとに作り直さない。記録入力の時計で評価している間はWorld側のフェードRAFを自己予約せず、一時停止の不要な連続評価を防ぐ。

## 対応範囲と制約

- v1はページY進捗→選択レイヤー／グループの不透明度、往復追従、平滑化なし。線形・ease-in・ease-out・ease-in-outに対応。1対象に有効な置換ルールは1件。最大48ルール、各64キー。同時に全レイヤーのレーンを並べるUI、他プロパティ、一方通行・一度だけ・複数ルール合成は次段階。
- テイクは3分／3600入力／4MiB文字相当、保存は8件／合計16MiB文字相当。連続値の20Hzとは別にイベントや永続状態の境界も保持するので、頻繁な状態遷移では件数上限へ早く到達する。超過時は録画を止め、保存済みテイクを勝手に消さない。
- 非表示タブで録画停止・再生一時停止。エディター終了やOFF／強さ0%で入力の上書き、評価タイマー、追加購読を解除する。切断からの復旧は既存セッションを利用し、明示保存したテイクは専用DBから再読込する。未保存テイクをブラウザー再起動から復旧する保証はない。
- 再現性の対象はRuntimeの数値評価。YouTube映像、DOM全体、ブラウザー標準GIFなどのコマ位相は録画・再現しない。テイクを別の画面寸法で再生すると、録画されたアンカー／viewportを評価へ使用する。サイトと配置の描画は現在のライブ画面に残るため、異なる画面幅での見た目全体の一致は保証しない。
- ルールの入力範囲・座標系・平滑化・合成はデータに明示するが、v1 UIの新規接続はページ全体0〜100%を使う。未対応の挙動を実行できるように見せるボタンは置かない。作品内の式やJavaScriptは評価しない。

## 段階ごとの検証

- Stage 1: 型チェック・lint・ビルド成功。全264件の最終実行は256成功／8件opt-inスキップ、2 workers、5.5分。初回全体回帰でv8を拒否する旧期待値と未購読時の解除を検出し、修正後に全件を再実行した。速度・往復・ゼロ範囲・グループとマスク・基底opacity 0からの復帰・ルール参照・旧データを検証。実YouTube検証はUI完成後に別途行う。
- Stage 2: 型チェック・lint・ビルド成功。全267件は259成功／8件opt-inスキップ、2 workers、5.7分。公式パネル、インページ、独立Studioで同じコマンドによるキー編集を確認。ドラッグ1操作のUndo、キーだけのDelete、ロック、保存・破棄・再読み込み、ズーム・高さ調整を検証。接続中の不透明度は手動値と区別して表示する。
- Stage 3: 型チェック・lint・ビルド成功。全274件は266成功／8件opt-inスキップ、2 workers、5.7分。明示録画、波形、再生・逆再生・シーク、ライブ入力隔離、別DBでの保存とブラウザー再起動後の復元、容量超過時の原子性を確認。録画開始時に既存の光フェードがリセットされる不具合を追加テストで再現・修正し、途中状態を含むサンプルごとの評価一致を検証した。非表示タブで録画を停止・再生を一時停止し、OFFでタイマーと入力購読を解除する。実YouTubeはStage 4で別途検証する。
- Stage 4: 最終の型チェック・lint・ビルド成功。全281件は272成功／9件opt-inスキップ、2 workers、5.7分。派生ゴースト、入力範囲とページ高さの変化、旧v7復旧、通知の最終値、停止中のフェードRAFを検証。実YouTubeではGIFのキー追加から録画・別保存・逆再生・再接続まで成功し、既存の動画操作・グループマスク・全画面・SPAも別フローで確認した。[スクリーンショット・性能・制約](signal-timeline-verification.md)を参照。

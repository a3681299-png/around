# G1.4 描き直しのない絵の保護の再確認

2026-11-04、Claude Code。対象ブランチ `codex/creator-editor-spike`。比較元は G1.3 の最後 `20ffdc3`。

## 問題

`docs/g13-bound2-verification.md`「長く入力しない条件」。ポインターが動いたときだけ描き直す絵で、操作部品が mutation なしで動き、次の入力が1.4秒後だと、部品が約1.1秒絵に隠れ続けた。

信用の上限（`TRUST_MS`＝200ms＋一周204ms＝404ms）は `source.capture()` が呼ばれたときにしか判定されない。絵の描き直し（`guard.sample()`）がなければ読み取りもなく、既に描いた絵の切り抜きは古いまま残る。

## 直し方

1. `OperationSource` に `trustExpiresIn()` を足す。最後の読み取りが今の答えで、最も古い組の確認が `TRUST_MS` を過ぎるまでの ms を返す（読み取りが無い・汚れている＝既に別の経路で読まれる、ときは `undefined`）。
2. `operation-guard` の `commit()` の最後で、次を満たすときだけ、期限の時刻に1回だけタイマーを予約する（予約済みなら足さない）。
   - guard が有効（`setActive(true)`）で `destroy` されていない
   - タブが表（`!doc.hidden`）
   - 絵が見えている：commit に渡された絵のうち、止められていない（返す集合に入っていない）・不透明度が0でないものが1つ以上ある
3. タイマーが来たら、上の条件をもう一度確かめ、`source.capture({ coalesce: true })` を呼ぶ。これで追いつきの確認（全組の比較）が走る。
   - 返った読み取りの `geometry` 世代が、最後に描いたときの読み取りと違えば `invalidate(true)`：まず絵を隠し、次のフレームで新しい切り抜きで描き直す（既存の層の変化と同じ経路）。
   - 同じなら何もしない（描き直しを起こさない）。そのまま次の期限へ予約し直す。
4. タブが裏になったら予約を消す（`visibilitychange`）。表に戻ったときは、復帰の最初の読み取りが追いつき確認をする（G1.3 で確認済み）ので、そこからの commit で再び予約される。

## 仕事の量

- 何も動いていない・絵が見えているときだけ、約404msに1回、全組の矩形比較（読み取った部品の `getBoundingClientRect`）が1回走る。描き直しは起こさない。
- 絵が毎フレーム描かれている間は、読み取りが期限内に起きるので期限が来ず、タイマーは毎回後ろへずれるだけ（`clearTimeout`/`setTimeout` を毎フレーム回さないよう、予約は期限の時刻を見て必要なときだけ張り直す）。
- 絵がない・全部止められている・タブが裏・guard が無効のときは予約しない。

## テスト（先に入れて、今のコードで落ちることを確かめる）

- `tests/g14-idle-recheck.spec.ts`
  - Codex の再現：`g13-sparse-visual` の条件で次の入力を 1,400ms・1,500ms に遅らせる。移動から 404＋34ms を過ぎて隠れているフレームが0、1,000ms の画像で部品全体がネイティブ表示と一致。
  - 仕事の量：guard を模擬ページで直接作り、読み取りの回数を数える。絵なし・全部止められた・タブが裏では、1.5秒の待ちで読み取り0回。見えている絵ありでは、期限ごとに読み取りがあり、動きがなければ `invalidate` は呼ばれない。
- 守りを壊した確認：開発用フラグ `WW_NO_IDLE_RECHECK=1`（`scripts/build.mjs` の既存のラベル方式で `WW_IDLE_RECHECK:` を落とす。出力は `.work/` の中だけ）で予約を止めたビルドを作り、足したテストが落ちることを確かめる。

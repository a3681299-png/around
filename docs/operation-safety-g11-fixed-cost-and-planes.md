# G1.1 固定費の修正、ページ追従層、雰囲気レイヤー（v12）

2026年10月24日。作業先は `codex/creator-editor-spike`。前回の[候補探索の差分化](operation-safety-g11-incremental-discovery.md)に続く記録。

## 合否の物差し

フレーム全体のp95は、検査なしでも約8〜120msの間で揺れるため、合否には使わず参考値として記録する。合否は**再取得のないフレームの拡張CPU時間（1フレームあたり）**で判定する。

- 検査なしとの差が中央値 +0.5ms以内、p95 +1ms以内なら合格。
- 拡張のRAFコールバック時間をフレームごとに合算する。そのフレームの開始時刻以降に始まった幾何の再取得があるフレームは、別の群（再取得あり）に分ける。
- 起動直後は別に記録する。

集計は `scripts/g11/analyze.mjs` の `extensionCpuQuietFrameMs`、`extensionCpuRecaptureFrameMs`、`verdict`。

## 固定費の内訳（G11_CPUPROFILE）

| ------------------------------------------------------------------------------------------------------------ | -------------: | -------------------------------- |
| `overlaySlot`：1回の描画で2回、うち1回は自分の書き込み後に祖先の computed style を読み、スタイル再計算を強制 |          760ms | 修正                             |
| `capture`：キャッシュ済みでも呼ばれるたびに約400行の `isConnected` を確認                                    |          564ms | 修正                             |

## 直した点

保護の強さ（世代確認、入力直前の同期再取得とヒット先の照合、縦方向の保護帯、安定待ち）は変えていない。

- 保護領域とクリップのパスは、不変のスナップショットと編集状態ごとに1回だけ計算する（`protectionClip`）。`--around-decoration-clip`、`data-around-safety`、レイヤーの可視属性は、前回と同じ値なら書かない。
- `guardPaint` は可視面と保護範囲を、スナップショットごとに事前計算する。全レイヤー×全操作面の比較自体は残す。変更前の実装の凍結コピーと、乱数60回分の入力で結果が一致することをテストした。
- `overlaySlot` は、同じタスクの中でだけ使い回す（マイクロタスクで破棄）。1回の描画の中では1回だけ読み、次のタスクでは必ず読み直す。
- `capture` は、`isConnected` の確認の代わりに、未配送の変更記録を `observer.takeRecords()` で取り込む。変更があれば取り直す。
- 保護処理は、1回の描画で最後に適用するレイアウトに対して1回だけ行う。エフェクトの更新が同期的に適用しなかった場合は `finally` で必ず行うので、描画される前に保護処理が済むことは変わらない。
- `publish` は、入力が前回と同じオブジェクトならJSON化を省く。

### 確認1：`takeRecords()` が消費する記録

- `takeRecords()` は、`createOperationSource` の中で作る操作面専用の observer（`operation-source.ts`、外部に公開しない）に対してだけ呼ぶ。
- Fのページ変更の分類（`features.refresh` など）は、別の observer インスタンス（`youtube.ts`、`youtube-player.ts`、`youtube-comments.ts` ほか）を使う。MutationObserver の記録の待ち行列は observer ごとに独立しているので、それらの記録は消費しない。
- 取り出した記録は、observer のコールバックと同じ `handle`（`collect` と `relevant`）で処理する。違いは通知の時点だけで、listener への通知はマイクロタスクへ遅らせる。これは observer のコールバックが走るのと同じ時点で、描画の途中でガードを呼び直さない。
- テスト：同じタスクの中で取り除いた操作面が次の同期読み取りに反映され、通知はタスクの後に届く。

### 確認2：`overlaySlot` の判定が古い間の保証

最初の修正では、スナップショットごとに最大1秒使い回していた。この間は**保証されなかった**。

- 作者のレイヤーは `pointer-events:none` なので、入力直前の照合は本物の操作面に当たって通過する。
- 遮蔽検査（`guardPaint`）が使う「合成先が確認できているか」も、同じ古い判定から来る。
- そのため、CSSOMだけ（MutationRecordが出ない）で祖先に transform が付くと、描画先の基準がずれたまま、最大1秒描画を続ける経路があった。

この経路を、変化のない iframe 文書の上で、構築済みスタイルシートだけを変えるテストで示した。修正前は失敗し、修正後に通る（`a stylesheet-only change to an overlay ancestor is seen by the next frame without any DOM mutation`）。現在は使い回しを同じタスク内に限っており、描画はどれも、その描画のタスクで読んだ値を使う。これは変更前の G1.1 と同じ強さである。

## ページ追従層

- プレイヤー基準のルートは、まず従来の映像内の描画先（videoSlot）に置く。
- 映像内の描画先が使えないとき（小さいプレイヤー、メニュー、中央の操作、結果ページなど）は、文書と一緒にスクロールする描画先（`#around-page-decorations`）に置く。従来は、このとき固定層で縦帯ごと除外していた。
- ページ追従層では、ページと一緒に動く操作面は現在の保護範囲（矩形と4pxの余白）だけを除外する。画面に固定された操作面は、縦方向の全経路を除外する。内側でスクロールする領域の中の操作面は、その領域の枠全体を除外する。sticky の祖先を持つ操作面は、その列を縦方向に全部除外する。
- 合成順で前に残ることが確かめられた操作面（native-above）は除外しない。
- ページ追従層の描画先が使えるのは、合成先が確認でき、全画面でなく、文書が横スクロールせず、親が画面に固定されていない場合だけ。
- 重なり順は、雰囲気 < ページ追従 < 固定層の順。作者の順序でこれより下に来てしまうルートは、固定層の通常の描画として扱う（クリップされる）。グループの部分木は分けない。
- 固定層は従来の縦帯を維持している。

5状態の描画できる面積（1920×1080、別に計算し直した和集合と全状態で一致）。

| 再生ページ上端     | 27.29% |       85.20% |      217 |
| シアター           |  0.00% |       81.01% |      395 |

| コメント欄         | 27.08% |       93.40% |      395 |

## 雰囲気レイヤー（DesignDocument v12）

- 追加した作品データは `renderMode?: 'normal' | 'atmosphere'` だけ。保存時は、通常を省略で表す。v1〜v11は v12 へ移行し、すべて通常のまま振る舞う。グループとその中のレイヤーは同じ描画モードにする（部分木を分けないため）。
- 全ての雰囲気レイヤーを1つの描画先（`#around-atmosphere-decorations`）にまとめ、その描画先全体に上限の不透明度をかける。そのため、何枚重ねても、グループの不透明度やマスクがどうでも、合成の実効アルファは上限を超えない。マスクと、グループ内の重なり順はそのまま保つ。
- 上限は **33%**（`ATMOSPHERE_ALPHA_CAP`）。エンジンが持ち、作品には保存せず、作者は解除できない。
- 雰囲気の描画先では、ぼかし・フィルター・影をCSSで無効化する。クリックは受け取らない。編集用のハンドルは、クリップされる固定層に残す。
- 合成先が確認できないときは、描画を止める。全画面では、従来どおり全てを1つの描画面にまとめ、通常のレイヤーとして扱う。

### 上限の決め方

YouTubeの文字色と背景色に、最悪の一様な色の層を不透明度 a で重ねたときのコントラスト比を計算した。

|    a | ライト主要 #0f0f0f/#fff | ライト補助 #606060/#fff | ダーク主要 #f1f1f1/#0f0f0f | ダーク補助 #aaa/#0f0f0f |
| ---: | ----------------------: | ----------------------: | -------------------------: | ----------------------: |
| 0.30 |                    7.23 |                    3.20 |                       6.64 |                    4.12 |
| 0.33 |                    6.46 |                    3.02 |                       5.96 |                    3.79 |
| 0.40 |                    5.02 |                    2.63 |                       4.67 |                    3.13 |

主要な文字4.5:1以上と、補助文字3:1以上を、ライト・ダークの両方で保てる最大値は0.333。初期案の40%は主要な文字の4.5:1は保つが、ライトの補助文字が2.63:1まで下がる。

実YouTubeのスクリーンショット（拡張の描画ではなく、同じ不透明度で全面に一様な色の層を重ねたもの）：[ライト・なし](screenshots/operation-g11-atmosphere/light-none.png)、[ライト・白33%](screenshots/operation-g11-atmosphere/light-white-33.png)、[ライト・白40%](screenshots/operation-g11-atmosphere/light-white-40.png)、[ダーク・なし](screenshots/operation-g11-atmosphere/dark-none.png)、[ダーク・黒33%](screenshots/operation-g11-atmosphere/dark-black-33.png)、[ダーク・黒40%](screenshots/operation-g11-atmosphere/dark-black-40.png)。黒・マゼンタの組み合わせも同じフォルダーにある。33%では主要な文字は両方のテーマで読める。40%ではライトの補助文字（登録者数・再生回数など）が目に見えて薄くなった。

## 未検証・残り

- 起動直後の拡張CPU時間は、中央値の差が +0.65〜0.9ms で、定常の基準（+0.5ms）を上回る。
- Chromium 153での再計測。
- 動きのある作品での連続60秒。
- 雰囲気レイヤーを実際に使った状態での、ライト・ダークのスクリーンショット（今回は一様な色の層で代用）。
- ページ追従層の、非同期スクロール中の見た目。保護は、スクロールの通知で直ちに描画を隠す従来の仕組みに頼る。

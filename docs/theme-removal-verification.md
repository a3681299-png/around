## 同じプロファイルでの更新

それぞれ別の新しいプロファイルを使い、そのケースの更新前後ではプロファイルと拡張フォルダを固定した。古いスイッチと強さは撤去前のフォームで操作した。未操作のケースでは古い ON/OFF キーが存在しないことも確認した。作品ありのケースは旧版で読める `'retro'` の作品を保存した。

| 更新前                        | 更新後の作品 | 更新後のスイッチ | 新しい保存キー                           |
| ----------------------------- | ------------ | ---------------- | ---------------------------------------- |
| テーマ ON・強さ0%・作品あり   | 出ない       | OFF              | `false` を保存。その後の読み直しでも OFF |
| テーマ ON・強さ37%・作品あり  | 出る         | ON               | 未保存。古い `true` を引き継ぐ           |
| テーマ OFF・強さ37%・作品あり | 出ない       | OFF              | 未保存。古い `false` を引き継ぐ          |
| スイッチ未操作・作品なし      | 作品なし     | ON               | 未保存。新しい既定値を使う               |
| スイッチ未操作・作品あり      | 出る         | ON               | 未保存。新しい既定値を使う               |

旧キーは更新によって消去・書き換えされなかった。旧版で書き出したバックアップは、未操作のケースでは旧版の既定値 OFF を含むため、**そのバックアップの設定も復元すると OFF** になる。更新時にキーが存在しない場合の ON と、明示されたバックアップ値の復元は別の挙動で、どちらも確認した。

Chrome のコマンドライン読み込みだけでは開発者モードが OFF のことがある。このまま管理画面の再読み込みを押すと拡張が無効になるため、テストでは開発者モードを ON にしてから再読み込みする。初期の検証コードの失敗はこの操作手順と、再読み込みで閉じる設定タブを使い続けたことによるもので、製品の移行失敗ではなかった。

## OFF後に残るもの

証拠：`theme-removal-boundaries.spec.ts`。比較記録は `theme-removal-verification/` に置く。これは模擬ページ上の網羅監査で、実サイトの後片付け確認と分けている。

| 対象                                                          | 6ce22ce の OFF／緊急OFF | 撤去後の OFF／緊急OFF |
| ------------------------------------------------------------- | ----------------------- | --------------------- |
| 設定ボタン（`data-ww-settings-button`）                       | 1                       | 1                     |
| 閉じた設定パネル（Shadow DOM 内のUIスタイルとイベントを含む） | 1                       | 1                     |
| 非表示の素材取得 iframe（`data-ww-asset-reader`）             | 1                       | 1                     |
| document/window の拡張側リスナー                              | 9                       | 9                     |
| ルートのインライン変数                                        | 空                      | 空                    |
| 作品のスタイル・描画面・サイト／編集用の印                    | なし                    | なし                  |

9本は document の `fullscreenchange`・`yt-navigate-start`・`yt-navigate-finish`・`yt-page-data-updated`、window の `popstate`・`pagehide`・`resize`・`pageshow` 2本。設定入口が SPA や動画に付き直すための処理、素材取得とページ復帰の処理に当たる。ボタンや Shadow DOM、iframe 自身のイベントと `chrome.*` の購読はこの9本に含めていないので、全リスナーの総数が9という意味ではない。

`src/content/index.ts` は設定入口と素材取得ホストを文書の寿命で所有し、`page-controller.deactivate()` は作品の描画とサイト購読を止める。`assetReader.destroy()` は文書全体の cleanup 側にあり、OFFでは呼ばれない。撤去前後で DOM とリスナーの観測結果は完全一致した。初めて素材を表示する前は iframe はまだ作られない。

これは**全ゼロという条件への不一致（素材表示後に毎回）**として報告する。見た目や操作の破綻は観測していない。入口を残す方針と寿命の設計に関わるため、検証担当では変えなかった。全ゼロを必要とするなら、OFF中の入口を拡張側だけに限定するか、再開時に素材取得ホストも作り直す方式を決め、SPA・再開・保存中の素材取得と併せて検証する必要がある。

## G1 の2件

- `operation-editing-input`：覆う要素が検索欄の矩形を動かさないので、最初から横取りとする変更は妥当。`operation-guard` は入力時に検査し、geometry の世代が変わった場合と、同じ位置で宛先が違う場合を分けている。MutationObserver による一時停止の記録、最初の自動復帰、3回後の停止と再開、再び覆ったまま押すと停止する判定を維持している。実サイトでも同じ経路を確認した。
- `operation-safety`：文言への依存を外し、`stopped: ''` を待つ変更は妥当。250msは200msの読み取り集約窓を越えるためで、5回のリサイズに対する「clip と safety への書き込みが0」の判定は同じ。ただし元の修正は60回の待ちの後に停止状態を検査しておらず、止まったまま書き込みがない場合を通す余地があった。**計測開始時の停止状態が空であることを必須**にし、この余地を閉じた。

最初の反復は19件成功・1件が context 終了時にタイムアウト（test本体の assertion 失敗なし）。リサイズだけを再度10回回して10件成功した。途中に既存のテスト用 Chrome 終了補助が働いた回もある。時間延長やリトライは足していない。

`operation-live.spec.ts` も追加で実行した。指定された横取り・再開のテストとは別で、シーク・音量・kキー・全画面を、作品を追加する前と後で比べるもの。この追加確認は**安定して成功していない**。

この結果だけでは、撤去による製品の入力阻害とも、テストのタイミングの問題とも決められない。失敗したドラッグの入力先や、失敗した k キーの受信とフォーカスの記録は足りていない。成功した回だけを使って「操作は変わらない」とはしない。`operation-live` には入力先・矩形の診断と、最初の比較を OFF にできる `WW_LIVE_OPERATIONS_OFF=1` を追加したが、既定の判定は弱めていない。

影響は**操作が破綻する可能性×条件がそろうと（自動テストでは3回とも再現、人の操作では未確認）**。wwt-verify の「原因がはっきりした小さな製品の不具合」という修正条件には達していないため、製品を推測で直していない。指定されたサイドパネルの横取り検知・停止・再開は成功しているが、この追加の汎用操作検査は未確定として引き継ぐ。なお、AGENTS.md の「3回まで」は修正の試行に対する規則であり、テスト実行回数の上限ではない。

次の切り分けは、同じ読み込み待ち・同じ動画の条件で、人の操作による OFF → ON・作品なし → ON・画像作品ありを比べること。シーク20%→35%、音量30%→65%、プレーヤーをクリックしてからkで停止／再生を試す。人の操作でもON・作品なしだけ壊れるなら、入力受信先・activeElement・動画の seeking/readyState と製品のリスナーを同時に記録し、ページ制御の起動条件を調べる。自動操作だけなら、診断で入力先と準備状態を確定してからテストを直し、10回の反復で確認する。

## 消し残しと画面

`retro` は旧作品の許可、旧設定の移行、旧バックアップの厳格な検査のための参照だけが製品コードに残る。`palette`・`window-chrome`・`bbs-comments` も旧バックアップの検査用の一覧に残る。ここを消すと互換性か不正値の拒否を壊すため、消し残しとはしない。「表示設定」はソースコメントに残るが、画面の文言にはない。

同じフォルダへの上書きビルドでは、旧 `assets/fonts/` のファイル自体はディスクに残った。現行の新しい出力先には存在せず、現行 manifest の公開素材にも載らない。更新後のページが旧フォントを読む参照もない。生成先を掃除しないビルドの残骸であり、今回これを削除する製品修正はしていない。

画像は [screenshots/theme-removal-verification/](screenshots/theme-removal-verification/) に保存した。ポップアップ、動画内設定、バックアップの明暗6枚と、G1 の停止・再開・サイドパネルを開いて目視した。明暗切替直後の166msの背景色遷移は撮影時だけ完了させ、途中の白いボタンを安定した暗色画面と取り違えないようにした。

依頼で除外された UX1、group-editor の画素判定、G1.2 は変更していない。既存の検索画面画像では、薄紫のカードに白い文字が乗る件を説明どおり確認した。今回、別の条件で生じた新しい同種の不具合は確認していない。

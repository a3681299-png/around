# レトロテーマの撤去：調査と計画

対象ブランチ：`codex/creator-editor-spike`（調査時点の先頭 `cddb3eb`）。この文書は調査と計画だけで、コードは変えていない。

## 結論の要約

- レトロテーマの見た目の部分（`src/themes/retro/`・窓の飾り・日替わりの飾り・掲示板風コメント・自動配色・表面の質感・ピクセル書体）は、まとめて消せる。消せる製品コードは約 **2,900 行**、フォントの素材が約 **1,400 行**（6ファイル）
- ただし `src/themes/controller.ts` は、名前は「テーマ」でも、実際には**ページの上の描画全体のまとめ役**になっている。作品（DesignDocument）の描画・画像とモデルの描画・G1 の保護・タイムライン・ページの変化の購読が、すべてここから起動している。このため**仕組みごと消すことはできない**。テーマの部分（CSS の差し込み・変数・features）だけを抜き、`src/host/` に「ページの制御」として残す
- **保存データの形式は変えずに済む**。DesignDocument の版は上げない。ただし、壊れないようにするための手当てが3つ要る（下の「3」）
  - 撤去後も `baseThemeId: 'retro'` の作品を受け付ける
  - 古いバックアップの `strength`・`palette`・`features` を、拒否せず読み捨てる
  - 強さ 0% で OFF にしていた人の扱い
- **G1 の判定の仕組みは、レトロテーマに頼っていない**。レトロテーマが動かしていたのは、YouTube の部品の位置だけ。G1 は位置を毎回測り直しているので、撤去で正しさは変わらない。変わるのは次の2つ
  - 窓の飾り専用の保護（下のステータスバーが操作部品を避ける仕組み）が、要らなくなる
  - 時計が毎秒書き換えていた自前の要素がなくなる。そのぶん、ページの変化の監視が軽くなる
- テストのうち、レトロテーマの見た目だけを確かめているもの（9ファイル・約1,900行）は消す。ほかは、主に「ON かどうか」の印を `data-ww-theme` から別の印へ替える書き直しで済む

## 2. テーマの仕組みを残す必要があるか

**仕組み（テーマを登録して選ぶ部分）は消せる。まとめ役は消せない。**

`createThemeController()` は、引数でテーマを1つ受け取る。その上で、次をすべて起動して持っている。

| 持っているもの                                                                    | テーマとの関係                                                                             |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `createDesignRenderer`（着せ替えの CSS）                                          | なし。`html[data-ww-design][data-ww-site]` の下に出す。テーマの属性を見ない                |
| `createImageRenderer`（画像・モデルの層）                                         | なし                                                                                       |
| `createOperationGuardHost`（G1）                                                  | なし。ただし、動かす条件 `guardWanted()` に `strength > 0` が入っている                    |
| `createTimelineHost`                                                              | なし                                                                                       |
| `site.connect(followPage)`（ページの変化の購読）                                  | なし。ただし、`followPage` の中でテーマの CSS の付け直しと `features.refresh()` をしている |
| `createFeatureController`（表示オプション）                                       | テーマそのもの                                                                             |
| `<style id="web-world-themes-style">`・CSS 変数・`data-ww-theme`・`--ww-strength` | テーマそのもの                                                                             |

作品が `baseThemeId: null` のときは、もうテーマを使わない道ができている（`render()` の「Independent designs」の分岐）。撤去は、**すべての作品をこの道に通し、もう一方の分岐を消すこと**に当たる。新しい道は書かない。

撤去後の形：

- `src/themes/` をなくし、まとめ役を `src/host/page-controller.ts`（名前は案）へ移す。引数から `theme` を外す
- `render()` と `followPage()` から、テーマの分岐・CSS の付け直し・`features.refresh()` を消す
- `validateDesign()` の「このサイトまたは基底テーマには対応していません」の検査は残し、`baseThemeId` が `null` か `'retro'` のどちらかであることを確かめる形にする（下の「3」）。受け付ける範囲は今と同じで、検査は弱くならない

作品の描画と G1 は、テーマの仕組みに頼っていない。両者がテーマに触れているのは、上に挙げた3か所だけ：`strength` を条件に使うこと、`followPage` の中の付け直し、`validateDesign` の基底テーマの検査。

## 3. 保存データ

### chrome.storage の設定

| キー                                                                                        | 使い道                                  | 撤去後                                                                                         |
| ------------------------------------------------------------------------------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `webWorldThemes.enabled`                                                                    | 「テーマを使う」。**拡張全体の ON/OFF** | 残す。作品の表示とエディターの入口を決める主スイッチ。名前と表示は変える（決めてもらうこと 2） |
| `webWorldThemes.creatorMode`                                                                | 制作モード                              | 残す                                                                                           |
| `webWorldThemes.strength`                                                                   | 強さ。**0% は OFF と同じ扱い**          | 読まなくする。ただし 0% の人の扱いが要る（下）                                                 |
| `webWorldThemes.noiseStrength`                                                              | 粒子の強さ                              | 読まなくする                                                                                   |
| `webWorldThemes.palette.{hue,saturation,brightness}`                                        | 自動配色                                | 読まなくする                                                                                   |
| `webWorldThemes.features.<10項目>`                                                          | 表示オプション                          | 読まなくする                                                                                   |
| `webWorldThemes.safety.emergencyOff`                                                        | 緊急OFF                                 | 変えない（`src/storage/safety.ts`。作品・Undo・バックアップから独立）                          |
| `webWorldThemes.design.*`・`webWorldThemes.studio.*`・`webWorldThemes.settings.position.v1` | 作品・エディターの配置・設定の位置      | 変えない                                                                                       |

- 読まなくなったキーが残っていても、壊れない。`readSettings()` は決まったキーだけを読む。`watchSettings()` は知らないキーの変化を捨てる
- 残ったキーを消すかどうかは、決めてもらうこと 4
- **危ないところ：強さ 0%**
  - 今は `enabled && strength > 0` のときだけ、作品の描画とエディターが動く
  - 強さを 0% にして OFF にしていた人は、`strength` を読まなくなると、撤去の更新で突然作品が表示される
  - 案：撤去の版で一度だけ、`strength === 0` なら `enabled = false` を書いてから `strength` を読まなくする（`chrome.runtime.onInstalled` の更新時）
  - 別の案：`strength` を「表示の ON/OFF」の一部として、読み続ける

### バックアップの形式（`format: 'web-world-themes-backup', version: 1`）

- `settings` は `UserSettings` をそのまま持つ。`parseBackupSettings()` は、決まった項目以外があると**バックアップ全体を拒否**する（`backupObject()`）
- そのため、`UserSettings` から項目を消すときに、検査の許可の一覧からも消すと、**撤去前に作ったバックアップがすべて復元できなくなる**
- 方針：
  - 読むとき：`strength`・`noiseStrength`・`palette`・`features` を、今と同じ範囲の検査（数値の範囲・真偽値・既知の項目名）にかけてから捨てる。検査は弱めない。不正な値の入ったバックアップは、今と同じく拒否する
  - 書くとき：残る項目だけを書く。`version` は 1 のまま。古い版の拡張は、足りない項目を既定値で補う（`{ ...DEFAULT_SETTINGS, ...supplied }`）ので、新しいバックアップも古い版で読める
  - 古い版の拡張で新しいバックアップを復元すると、表示オプションは既定値（窓の飾り ON など）に戻る。これは許容でよいと考える
- 強さ 0% の古いバックアップを撤去後に「設定も復元」したときの扱いも、上の 0% の扱いに合わせる
- テスト：撤去前の版で作ったバックアップの実物を fixture にして（`tests/fixtures/backups/`）、撤去後に復元できることを確かめる

### DesignDocument

- **形式は変わらない。版も上げない**。`baseThemeId` は `string | null` のまま、検査も `isDesignId` のまま
- 既存の作品の多くは `baseThemeId: 'retro'` を持つ。新しい作品は、エディターが `DEFAULT_THEME`（`'retro'`）を渡して作っている。`null` は録画の作品（`world/recording.ts`）と着せ替えの検証用の作品だけ
- 撤去後は、`'retro'` も `null` と同じ描画にする。中身（rules・decorations など）はそのまま残り、往復しても `'retro'` は書き換えない（互換の fixture `tests/fixtures/designs/*.json` はそのまま通る）
- 見た目は変わる。レトロテーマの上で着せ替えた作品は、YouTube の素の見た目の上に重なる。作品のデータは壊れない
- 新しい作品の `baseThemeId` を `null` にするか、`'retro'` のままにするかは、決めてもらうこと 3。`null` にしても、`null` は版1から受け付けているので、古い版の拡張でも読める
- 「このサイトまたは基底テーマには対応していません」の検査を `null | 'retro'` にしないと、既存の作品がすべて読み込めなくなる。**ここは撤去で最も壊しやすい箇所**で、テストで先に押さえる

## 4. G1 への影響

### レトロテーマが YouTube の部品に何をしていたか

窓の飾り（`window-chrome`、既定で ON）は、YouTube の部品の**位置**を変えている。

- 上のツールバー：`--ytd-masthead-height` を、飾りの2行ぶん高くする。`#masthead-container` を固定し、`ytd-page-manager` を下げる
- 下のステータスバー：`body` に下の余白を足し、サイドバーの下端を上げる
- プレーヤー：最大の高さを、タイトルバーとステータスバーのぶん小さくする（大きさを計算し直すのは YouTube 自身。動画を切り抜いたり拡大縮小したりはしない）
- 全画面では、どれも 0 に戻す

ほかの表示オプションは、色・角・文字・コメントの見た目を変えるだけで、位置は変えない（掲示板風のコメントは、番号の要素を足す）。

### G1 の計算・保護の範囲に入っているか

- 入っていない。操作面は `youtube-operations.ts` が YouTube の本物の部品から毎回測る。窓の飾りのような自前の要素（`id` が `web-world-themes` で始まる）は、操作面からも、ページの変化からも、入力の照合からも除かれている（`operation-source.ts`・`operation-guard.ts`・`youtube.ts` の `owned`）
- G1 は、レトロテーマで動いたあとの位置をそのまま測る。撤去で位置が変わっても、測った結果が変わるだけで、判定の正しさは変わらない
- `guardWanted()` の条件に `strength > 0` が入っている。`strength` をなくすなら、ここから外す（`enabled` だけにする）

### 撤去で変わること

| 変わること                                                                                          | G1 から見た意味                                                                                                                                                                                                                              |
| --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 下のステータスバーが、プレーヤーの操作帯を避けて高さを測る仕組み（`chrome-safety.spec.ts`）が消える | 窓の飾りが操作部品を隠さないための、レトロテーマ専用の保護だった。飾りがなくなるので、保護も要らない                                                                                                                                         |
| 時計（毎秒の書き換え）・日替わりの飾り・掲示板の番号付け・小窓の色の監視がなくなる                  | ページの監視（`MutationObserver`）に届く自前の変化が減る。今は自前の変化として捨てているが、捨てる前の処理は動いている。拡張の CPU 時間は減る見込み（測って確かめる）                                                                        |
| 位置の基準が YouTube の素の配置になる                                                               | G1 のテストのうち、レトロテーマの上で座標を決めているものは、点の取り直しが要るかもしれない（`clearestPoint()` で選んでいるものは影響なし）                                                                                                  |
| 計測の基準値                                                                                        | 計測のハーネス（`scripts/g11`・`scripts/ui1`・`scripts/ui0c`）は、`enabled: true, strength: 100` で、表示オプションを既定（窓の飾り ON）のまま測ってきた。**過去の基準値はすべてレトロテーマ込み**なので、撤去後に測り直して新しい基準にする |

G1.2（接近の判定がページ全体の効果を止める件）は、レトロテーマと関係がない。撤去で直りも悪化もしない。

## 5. 表示設定に残るもの

今の表示設定（ポップアップと、動画の中のアイコンから開く欄が同じものを使う）：

| 欄                                                              | 撤去後                                          |
| --------------------------------------------------------------- | ----------------------------------------------- |
| エディターを開く／別ウィンドウで開く                            | 残す                                            |
| 制作モード                                                      | 残す                                            |
| 表示テーマ「YouTube / レトロ」・テーマを使う                    | ON/OFF だけ残す（名前は決めてもらうこと 2）     |
| エフェクトの強さ                                                | 消す（強さ 0% の扱いは「3」）                   |
| 自動配色（プリセット・色相・彩度・明るさ）                      | 消す                                            |
| 表面の質感（粒子の強さ）                                        | 消す                                            |
| 表示オプション（10項目）                                        | 消す                                            |
| 操作性と緊急停止（緊急OFF・描画を再開・停止キーと操作チェック） | 残す（`settings/safety-controls.ts`。変えない） |
| 作品と設定のバックアップ（リンク）                              | 残す                                            |

残るのは、**ON/OFF・制作モード・エディターの入口・緊急OFF と操作チェック・バックアップのリンク**の5つ。

画面として要るかどうか：

- **要る**と考える。理由は3つ
  1. 緊急OFF は、エディターを開けない状態（エディターが壊れた・開きたくない）でも押せる必要がある
  2. 制作モードが OFF の人は、拡張アイコンを押すとこの画面が出る。最初に ON にする場所がほかにない
  3. 動画の中のアイコンから開く欄は、エディターを開く前の入口になっている
- ただし「表示設定」という名前は、見た目の設定が残らないので合わなくなる。「WWT」や「かんたん設定」などへの改名が考えられる（決めてもらうこと 5）
- 欄が5つになるので、ポップアップの高さは今のおよそ3分の1になる

## 決めてもらいたいこと

1. **タグを付けるコミット**：今の先頭（`cddb3eb`、この文書の push 後ならその次）でよいか。タグは push してよいか
2. **ON/OFF と強さ 0%**
   - 「テーマを使う」は撤去後、拡張全体の ON/OFF になる。名前の案は「作品を表示する」「WWT を使う」。既定値は今の OFF のままでよいか
   - 強さ 0% で OFF にしていた人を、撤去の更新のときに一度だけ OFF へ移すか（推奨）、`strength` を読み続けるか
3. **新しい作品の `baseThemeId`**：`null` で作るように変えるか（推奨。意味のない `'retro'` が増え続けないため）、`'retro'` のままにするか。どちらでも、既存の作品は書き換えない
4. **読まなくなった保存キー**（強さ・粒子・配色・表示オプションの計 15 キー）：残すか（推奨。小さく、害がなく、戻すときに使える）、撤去の更新で消すか
5. **表示設定の画面の名前と置き場所**：画面は残す（緊急OFF と最初の入口のため）。名前を「表示設定」のままにするか、変えるか
6. **レトロテーマ専用の保護のテストを消すこと**：`chrome-safety.spec.ts`（ステータスバーが操作帯を避ける件）は、G1 の考え方に近いテストだが、守る相手（窓の飾り）がなくなるので消す。それでよいか
7. **ピクセル書体の素材**：フォントとライセンスも一緒に消してよいか（タグからは戻せる）

## 1. スクロールに合わせた不透明度のずれ

### 見立て

「ページの高さが中身だけ伸びたとき、スクロールの値を読み直すきっかけが来ない。前は道具の帯の描き直しがきっかけになっていた」

### 確かめたこと

| 確かめ方                                                                                                                                                            | 結果                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 変更後のビルドで、スクロールの値を読んだ時刻と値をページに一時的に記録し（`src/host/signals.ts`、あとで消した）、ずれたときに今の値と比べた（本物の YouTube、6 回） | 3 回ずれた。ずれたときも、最後に読んだ値（位置・範囲）は今の値とぴったり同じだった。読み直しは古くなっていない。`html`・`body` は 26px で、中身だけ伸びる作りなのは見立てどおり              |

### 分かったこと

- ずれの原因はスクロールの値の読み直しではない。**操作面の保護（G1）**が「ポインターが操作部品に近づいた」と判定し、ページ全体のシグナルの効果を止めていた（`src/host/operation-guard.ts` の `stepProximity`。止まっているポインターでも、その下に操作部品が来れば「近い」）
- テストはポインターをページの上に置いたまま、スクロールさせる。YouTube の操作部品（リンクやボタン）が、スクロールでポインターの下へ来ると、効果が止まる
- **変更前に 5 回とも通っていたのは偶然**。サイドパネルを開くとき、ページに道具の帯を作ってフォーカスを移していた。保護は「拡張自身の UI への入力」でポインターの位置を忘れる作りで（`operation-guard.ts` 180〜189 行）、そのあとページの上のポインターを知らなかった。変更前のビルドでも、ポインターをページの上に置けば同じようにずれる（上の表の 3 行目）
- 3 回目の変更で「表に出た」のは、テストの手順（`openSidePanelFromIcon`）でポインターをページの上へ動かすようにしたから。製品の後退ではない

### 選んでほしいこと

効果を止めるのは G1 の判定なので、直し方は翔太が決める。

| 案                                       | 中身                                                                                      | 気になる点                                                                                                                                                                            |
| ---------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A：今のまま（テストだけ合わせる）        | G1 の判定は変えない。テストは、ポインターをページの外（サイドパネルの側）へ出した形で測る | 人がページの上でホイールでスクロールすると、ポインターが YouTube のリンクやボタンの上を通るたびに、スクロールに合わせた効果がページ全体で止まる。作品の中心の機能として、これでよいか |
| B：止める範囲を狭める（G1 の変更）       | 「近づいている」とき、近づいた操作部品に重なる層の効果だけを止め、離れた層は止めない      | 操作性の 3 段階の「操作が破綻する」を防ぐ仕組みを変える。判定と G1 の e2e・実サイトの確認を足す必要がある。安全の確かめを弱めないことを、この形で示す必要がある                       |
| C：スクロールだけ例外にする（G1 の変更） | スクロールに合わせた効果は、「近づいている」ときも止めない                                | 操作部品の上にある層の透明度がスクロールで変わる。G1 の考え（近づいたら作品が引く）と合わない                                                                                         |

僕の考えは B。A では、作品の中心の機能が普段のスクロールで止まりがちになる。C は G1 の考えから外れる。B は「近づいた所だけ引く」ので、操作性の保護と作品の両方を保てる。ただ G1 の設計の変更なので、決めてもらってから行う。

# World Runtime

開始点: `1d23ec0`（DesignDocument v6）。既存の見た目、配置座標、編集履歴、素材ID、保存キーを維持する。通常版の `main` / `dist` は変更しない。

## 調査と境界

現在の `design/image-renderer.ts` は配置の評価とDOM描画を、`effects/controller.ts` はシグナルの購読・フェード計算・CSS反映を兼ねている。`media/controller.ts` は素材の非同期デコードと再生時刻を管理する。編集履歴と保存はこれらの外側にある。

| 境界 | 担当 | 今回の扱い |
| --- | --- | --- |
| Host (`sites/`, `host/`) | サイト固有の監視、セマンティックアンカー、ブラウザーイベント、時刻、可視性、シグナル | DOMから数値の入力を作る。セレクターはRuntimeへ渡さない |
| World Runtime (`world/`) | 座標、グループ階層、マスク、宣言的な接続、フェード、再生時間、評価状態、記録の検証・再生 | 純粋関数。DOM、ブラウザーAPI、現在時刻、乱数生成に依存しない |
| Renderer (`renderers/dom/`, `media/`) | 評価値から既存のDOM/CSSへ反映、素材ロード・デコード・フレーム描画 | 描画方式と非同期デコーダーを維持。次のバックエンドも数値の評価結果を受け取れる |
| Editor / Storage | draft、選択、Undo/Redo、保存、IndexedDBの素材・lease | 保存形式や履歴の契約を変えない。評価状態は作品データに書き戻さない |

既存の公開モジュールには互換用の再exportを残す。依存方向はHost/RendererからRuntimeへ向ける。RuntimeからHost/Rendererは参照しない。

## 段階と検証

1. **Phase 0**: 既存の純粋な幾何・階層・マスク・フレーム計算、Hostのアンカー・入力、DOM描画を移す。計算式とライフサイクルは変更しない。境界テストと既存の全テストを通してコミットする。
2. **Phase 1a**: 時刻付き入力と前回状態からシーンを評価するコアを作る。配置・グループ、次にマスクを接続する。旧実装との数値比較と切り戻しモードを用意し、それぞれ回帰テストを行う。
3. **Phase 1b**: 素材の再生時間を純粋な計算へ移す。デコードの非同期完了と描画はRenderer側に残す。明示的な開発用記録・再生、決定性・互換性テストとベンチマークを追加する。
4. 全体テスト、型チェック、lint、実験用ビルドを実行し、通常版のSHAとdistのハッシュが変わっていないことを確認する。

## 評価契約

`evaluateWorld(scene, previousState, input) -> { state, frame }`

作品は検証済みのv6レイヤーとグループ。入力は単調な時刻と経過時間、ビューポート、登録済みアンカーの矩形、pointer/videoの値と状態、既知のイベント、タブ可視性・reduced-motion、および素材の準備状態と再生メタデータを含む。必要ならseedを渡せるが、今回の機能は乱数を使用しない。

シーン評価の出力はレイヤーとグループのワールド座標、親に対する描画座標、サイズ、回転、不透明度、可視性、マスク中心・半径・ぼかし・強度、動画の状態。メディアの時間評価は別の純粋な入口で再生時間・終了状態・フレーム番号を返す。CSS、DOM要素、デコーダー、コールバックを出力に含めない。フェードや再生状態は前回状態に保持し、入力や作品を変更しない。同一Runtimeバージョンと同一の初期状態・作品・入力列に対して同一の出力を得る。

シグナルは既存の「値・状態・出来事」を維持し、接続は既存の `source -> transform -> target` を使う。新しい式言語や任意コードは導入しない。状態機械は現在のvideo/再生/フェードに必要な状態に限定し、汎用ノード編集UIは作らない。

## 記録と再生

開発者が明示的に開始・停止するメモリー内の記録を用意する。自動開始、常時保存、外部送信は行わない。記録対象は評価に必要な許可済みの数値、真偽値、レイヤー/アンカーID、既知のイベントと初期状態・作品だけに限定する。ページ本文、URL、フォーム、キー入力、認証情報、素材バイト列を含めない。上限を設け、読込時もバージョンと値を検証する。

再生は記録した入力を評価コアへ順に与える。保証対象は評価結果であり、YouTube映像、DOM、非同期デコード完了時刻の再現ではない。編集セッション中の作品変更は記録を止めるか、作品のスナップショットを明示的に扱い、勝手に編集履歴と混ぜない。

## 性能とリスク

32メディア・16グループ、親子マスク、動画状態の遷移を含む固定入力で、旧計算と新計算の結果を比較してから1評価の時間を計測する。ウォームアップ後の中央値・p95・繰り返し数と環境を記録する。DOMレイアウト、GPU、デコードの計測とは区別する。

主なリスクは親から子への可視性伝播、背景タブ復帰時の時間、非同期素材準備、アンカー消失、編集中の再評価。購読数とRAFの停止、OFF/0%の撤去、SPAとスクロール、保存/破棄/Undo/Redoを既存fixtureテストで確認する。実YouTubeのDOM変更、広告、フルスクリーンや実機CPU/GPUはfixtureだけでは保証しない。

今回は新しい描画ライブラリー、サンプラー、タイムライン、3D、ライティング、権限、バックエンドを追加しない。将来はHostが新しいサイトの数値入力を、Rendererが同じ評価出力の別の描画を担当する。

## Phase 1aの結果

配置と階層を `evaluateLayout`、親子共通のマスクを `evaluateEffects`、時刻付き入力からの評価を `evaluateWorld` として接続。動画状態とイベント、フェード状態は作品とは別に保持する。Hostのライフサイクルは `host.lifecycle` イベントでフェードのリセットを指示し、外部で評価状態を書き換えない。消えたレイヤーの評価状態も除去する。

`WW_WORLD_MODE=legacy|compare|runtime` をビルド時に指定できる（既定runtime）。legacyは旧DOMマスク制御へ戻す。compareは旧draw/paintの数値参照と新結果の差を例外として検出し、新結果を描画する。旧経路は実YouTube検証まで一時的に残す。通常ビルドでは重複評価しない。

標準runtimeビルドの関連44件（カード・グループ・マスク・保存・破棄・Undo/Redoを含む）成功、compareビルド18件成功。32メディア/16グループと固定180入力の新旧比較、決定性、不変性、アンカー消失、背景復帰、reduced-motionを追加検証。型チェック・lint・ビルド成功。マスク強度と親の不透明度は別に評価し、CSSで合成する従来の挙動を維持した。

### 開発用記録

実験用worktreeで次の開発ビルドを作り、拡張機能と対象タブを再読み込みする。

```powershell
$env:WW_WORLD_DEVTOOLS = '1'
$env:WW_WORLD_MODE = 'runtime'
npm run build
```

画像などを最低1枚配置した状態で、DevToolsの**拡張機能のisolated world**から呼び出す（ページ側のworldには公開しない）。

```javascript
__wwWorldRuntime.startRecording();
// マウス移動、再生/一時停止、スクロール、ウィンドウサイズ変更などを行う
const recording = __wwWorldRuntime.stopRecording();
const json = JSON.stringify(recording);
const replay = __wwWorldRuntime.replay(json); // DOMを操作しない純粋な再評価
__wwWorldRuntime.status();
```

自動開始・保存・通信はない。記録は最大3600入力、10分、JSONで8M文字。描画に必要な作品スナップショット（名前とasset IDを含む）と初期評価状態、数値の入力だけを保持する。ページ本文、ページURL、認証情報、フォーム値、キー入力、素材のバイト列は取得しない。クリックは座標と種類だけ。作品変更で記録を停止し、記録用の購読も解除する。OFF/0%でAPIとメモリー上の記録を撤去するため、必要な記録は先にstopして手元へ取り出す。

通常ビルドへ戻すときは `WW_WORLD_DEVTOOLS` を削除して再ビルドする。開発用の新しいChrome権限やメッセージ受付はない。

### 再現性の範囲

記録は `evaluateWorld` に渡した評価入力のスナップショット列であり、未評価のすべての生イベントを保存する仕組みではない。同じ初期状態・作品・入力列・Runtimeバージョンなら、配置・グループ・マスク・video状態の評価結果を復元する。入力型に必要な時刻、delta、環境、アンカー、既知イベント、任意のseedがあり、今回seedを使う機能はない。

メディアの時間計算も純粋関数に移したが、既存の非同期素材準備・30fpsメディアRAFとエフェクトの必要時RAFは維持した。今回の記録にはデコーダーの完了やメディアRAFの全tickを含めない。GIF/WebP/Lottieの描画フレーム、YouTube映像、DOM全体の完全再現は保証しない。将来サンプラーの準備状態とtickを同じ入力列へ統合するときに、記録形式とRuntimeバージョンを更新する。状態機械も現時点ではvideoのplaying/pausedと既存フェード・再生終了状態に限る。

### 互換性・単体検証

`tests/fixtures/designs/` の6データは元コミットのテストから取得し、当時のパーサーで受理されたもの。現行パーサーでv6へ移行して評価し、元JSON・素材ID・カード設定・ロック・再生・エフェクト・子IDが保たれることをテストする。未知のv7は拒否し、入力は変更しない。

記録の単体テストはmid-fade開始、JSON復元、同一評価結果、容量停止、作品変更、未知のイベント/余分な個人情報フィールド/不正座標/バージョンの拒否を含む。ブラウザーテストは通常ビルドから同一ソースの開発モードをisolated worldへ再注入し、fixture操作の記録・再生、ページworldへの非公開、購読解除とOFF撤去、legacy切り戻しを確認する。

### 性能計測

`npm run benchmark:world` で再測定できる。32メディア/16グループの180入力を、新旧の数値結果一致を確認してから20周ウォームアップ・50周測定（各9000評価）。測定順を交互にし、時間取得と集計はRuntime外で行う。旧版は `1d23ec0` のdraw/paint計算を同等の戻り値へまとめた参照で、実DOM込みの旧拡張そのものではない。共有の幾何・マスク数学は変更していない。

初回の結果は `docs/performance/world-runtime.json` に記録する。Windows / Node 24.16.0 / i7-13650HXで、可視性混在の中央値は旧47.4µs→新45.4µs（p95は59.8→55.3µs）、レイヤーのvisibleフラグを全ONにした条件は旧52.7µs→新49.6µs（p95は95.2→92.4µs）。DOM、CSS適用、GPU、デコード、ブラウザーのスケジューリングは含まない。小さな差なので高速化の保証とはしない。

### 実際の描画コールバックの比較

`tests/world-performance.spec.ts` は同じMV3のisolated worldでlegacy/runtimeを順に再注入し、32メディア/16グループの同一pointer列を与える。legacy→runtime→runtime→legacy、各15フレームのウォームアップ後80フレームを測定し、各方式160標本。48個のマスクCSSが同じ結果になることも検証した。

Chromium 153.0.8010.12のfixtureでは、中央値 **旧0.2ms→新0.3ms**、p95 **旧0.3ms→新0.5ms**、平均 **旧0.199ms→新0.319ms**。数値評価・CSS書込・可視性通知を含む実コールバックのCPU時間で、非同期レイアウト/paint、GPU、デコード、入力dispatch、RAF待ち時間は除く。ブラウザータイマーの精度の影響もある。数値コアだけの比較と異なり、この条件では負荷の増加を観測した。結果は `docs/performance/world-runtime-browser.json`。

次は実YouTubeで切り戻し可能な状態のまま確認し、pointer更新時に変わらない配置評価を再利用してコールバックの負荷を減らす。その後に素材準備とメディアtickの記録統合を検討する。既存の2つのRAF経路と非同期デコーダーを統合する変更や、別描画バックエンドへの移行は今回行っていない。

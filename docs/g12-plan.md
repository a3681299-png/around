# G1.2：止める範囲を絞る（調べと設計）

依頼（翔太、2026-11-02）：G1 の「近づいたら止める」を、ページ全体から「近づいた操作部品に重なる層」だけに絞る（方向 B、`docs/ui0d-3.1.md`）。守る力は弱めない。今回はコードを変えず、調べた結果と設計だけを書く。

対象：`codex/creator-editor-spike` の `557b978`。行番号はこのコミットのもの。

## 結論（先に）

- 「操作部品が隠れない・押せなくならない」を守っているのは、接近の判定ではない。**最後の切り抜き（compositor の clip）・入力のときの照合・作品が入力を受けない作り**の3つで、どれも層の位置や動きに関係なく効く。接近の判定は「狙っている部品のところで、作品が動かない」ための追加の決まり。だから、止める範囲を絞っても、3つの保護は1つも弱めずに済む
- 止める単位を、真偽値1つ（`environment.safeInteraction`）から、**Host が決めた「止める層の集合」**（`environment.heldLayers`）に変える。どの層が重なるかは Host（`operation-guard.ts`）が、前のフレームで実際に描いた矩形と、近い操作部品の矩形から決める。world の評価は渡された層だけを基本状態に戻す（純粋なまま、WorldState は変えない）
- 一度止めた層は、**止める原因になった操作部品が「近い」でなくなるまで**（今と同じ 72px・350ms のヒステリシス）放さない。層が自分の動きで重なったり外れたりしても揺れない
- 作品データ（DesignDocument）の形は変わらない。版上げは要らない。録画（テイク）は形が変わるので、ランタイムの版を 1.4.0 に上げ、古いテイクは今までどおりに再生する
- 作業は3回に分ける。合格は、`signal-timeline-live` と `operation-live` を判定を変えずにそれぞれ 10 回続けて通すことと、拡張 CPU/フレームの基準（中央値 +0.5ms・p95 +1ms 以内）

## 2. 重なる層を決めるのに要る情報と、その取り方

### 層が今描かれている範囲

描画のたびに、`renderers/dom/scene.ts` 409〜470 行が、層ごとの `PaintFootprint`（`bounds`・`outset`・`composition`・`dynamic`）を `safety.commit()` に渡している。`bounds` は**効果をかけたあと**（シグナル・追従・グループの回転を含む）の、ビューポートの座標の矩形。ガードはこれを `paints` として持っている（`operation-guard.ts` 434 行）。

| 層の種類                                             | `bounds` で足りるか                                                                                                                                                             |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 画像・アニメーション（画面・ページ・プレイヤー基準） | 足りる。`outset` は今 0（影・ぼかしの広がりは切り抜きの側で扱う）。`outset` を足して使う                                                                                        |
| 効果で動く層                                         | 足りる。前のフレームで描いた位置が入っている                                                                                                                                    |
| グループの子                                         | 足りるが、止めるときは**ルート（グループ）単位**にする。親の追従・規則が子を動かすため。`PaintFootprint` にルートの ID を足す（今は `scene.ts` の中で `parentId` を引いている） |
| 3D の層                                              | 層の箱の中に canvas を置いて描くので、`bounds`＝描く範囲。モデルが箱からはみ出さないことは、1回目で `three/models.ts` を確かめる（**未確認**）                                  |
| 画面全体の層（ビューポートいっぱいの絵）             | `bounds` が画面全体なので、どの部品に近づいても重なる。その層だけは今と同じく止まる。ほかの層は止まらない                                                                       |
| 雰囲気の層（atmosphere）                             | 不透明度の上限 0.33 で、もともと部品の上を横切ってよい（`operations.ts` 126〜139 行）。止める対象から外すか、今と同じく重なれば止めるかは決めてもらいたい（下の D7）            |

### 文書全体を検索しないで得る方法

- 層の範囲：上の `paints`。描画のたびにすでに作っている配列で、DOM を読まない
- 近い操作部品：`stepProximity` が今も回っている、`capture()` の差分の一覧（G1.1 の incremental discovery）。新しい読み取りはない
- つまり、**入力のたびに足す仕事は、配列どうしの矩形の比較だけ**。`querySelectorAll`・`getBoundingClientRect` は増えない（AGENTS.md の「繰り返さない設計」を守る）

`world/layout-index.ts` は、準備済みのレイアウトで ID から層を引く表（`layoutEntry`）。今回の判定には要らないが、world の中で「止める層の集合」から子孫・規則の対象を引くときに使える。

## 3. 効果で動く層が、あとから重なるとき

| 場面                                                 | 扱い                                                                                                                                                                                                        |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 動いている層が、近い部品の上に入ってくる             | 次のフレームで、前のフレームの `bounds` が重なるので止める。1フレームの遅れの間も、絵は最後の切り抜きで部品から切り取られ、入力は受けない（作品は `pointer-events` を持たない）。隠れる・押せないは起きない |
| 止まった層が基本状態に戻ったら、部品から外れた       | **放さない**。止めた原因の部品が「近い」でなくなる（72px・350ms）まで止めたまま。外れたから再開、また重なって止まる、の揺れが起きない                                                                       |
| 止まっているポインターの下へ、スクロールで部品が来る | 今と同じく、その部品は「近い」。ただし止まるのは、その部品に重なる層だけ                                                                                                                                    |
| スクロールで部品が、画面に固定の層の下に来る         | ポインターが近くになければ「近い」ではないので止めない。部品は切り抜きで守られる（`scrolls` の縦帯・`pageEnvelope` のとおり）                                                                               |

### 重なりの判定に使う矩形（追加の依頼の3）

- 止めるかどうかを**決めるとき**：前のフレームで描いた矩形（効果をかけたあと）に `outset` を足したもの
- **一度止めたあと**：矩形では放さない。止めた原因の部品が「近い」でなくなったときにだけ放す（部品ごとのヒステリシス）
- 効果をかける前の矩形（作者が置いた位置）は判定に使わない。理由：作者の位置が部品の上でも、今そこに描いていない層を止める理由がない。逆に、今の矩形で止めて、戻った位置で放す、をすると揺れる。この2つを「決めるときは今の矩形、放すときは部品の状態」で分ける
- 揺れが残る場合：止める→放す→また重なる、の1周は、最短でも 350ms＋層が部品まで動く時間。シグナルで部品の上を行き来する層では起こりうる。テストで回数を数える（7）。多いときは、放したあと短い間（例：350ms）だけ、同じ部品で止め直さない形を足す。どちらにするかは D4

## 4. 拡張の UI に入力したときにポインターを忘れる作り

**訂正**：`docs/ui0d-3.1.md` の「`operation-guard.ts` 180〜189 行」は、今は保護の印を描く処理。ポインターを忘れる処理は `operation-guard.ts` 254〜263 行（`activity` の中の `owned`）にある。拡張の要素（`id` が `web-world-themes` で始まる）への入力で、ポインター・操作中・近さをすべて捨てる。

**残す**。理由：

- ポインターが拡張の UI（エディター・動画の中のアイコン）の上にあるとき、ページの部品に近づいてはいない。プレビューの数値を作者の値で見せるのが目的で、今もその役目は要る
- 絞ったあとは、ページの上の普通のポインターが、部品に重なる層しか止めない。忘れる作りに頼って「たまたま通る」テストはなくなる（`signal-timeline-live` が通らなかった原因はここではなく、ページ全体を止めていたこと）
- 1つだけ変える：忘れたあと、ポインターがページへ戻ってきた最初の `pointermove` から、普通に判定し直す（今もそうなっている。テストで確かめる）

## 5. `pointer-events: none` の操作部品が、照合で横取りと数えられる件

場所：`operation-source.ts` 431〜466 行（`validate`）。クリックの点を含み、見えている候補のうち、`elementFromPoint` の結果がその候補でないものを「横取りされた」と数える。`pointer-events: none` の部品はクリックを受けないので、点が当たらず、下の要素が返る。これを横取りと数え、止めてしまう。

直し方：見えているかを調べるのと同じ所で、**点にある候補だけ**、`getComputedStyle(row.element).pointerEvents === 'none'` なら数えない。`pointer-events` は継承されるので、祖先で none にした部品もこの読み取りで分かる。点にある候補だけを読むので、読み取りは1クリックに数件。

守る力が弱まらないことの確かめ：

- 拡張は、YouTube の要素に `pointer-events` を書かない（`src/sites/`・`src/design/`・`src/renderers/` を検索して確認。書くのは自分の描画の要素だけ）。着せ替えの項目にも `pointer-events` はない。だから「拡張が none にして押せなくした部品」を見逃すことはない
- 拡張の要素が上にかぶさって押せない部品は、`pointer-events` が auto のままなので、今までどおり数える

接近の判定（`stepProximity`）では、`pointer-events: none` の部品も今のまま「近づく相手」に含める。見えている部品の上で作品が動くと狙いにくいことは、押せるかどうかと関係ないため（D8）。

## 6. 将来の「よける」の入口

G1.2 では作らない。作り直しにならないよう、次の形にしておく。

- Host から world へ渡すのは、真偽値ではなく **「止める層」と「その層が避けるべき矩形」**：`environment.approach = { layers: { [layerId]: PlacementFrame[] } }`（キーは止める層、値は近い部品の矩形）。G1.2 の world は、キーにある層を基本状態に戻すだけで、矩形は読まない
- 「よける」は、world の追従（`world/motion.ts` の `followMotion`）が、この矩形を障害物として目標を曲げる形で足せる。決めるのは Host とエンジンで、作品データからは選べない（作品が保護を外せない、の決まりのとおり）
- どの層が「止まる」か「よける」かの方針は、エンジンの表（層の種類ごと。例：キャラ＝よける、ほか＝止まる）にする。作品データに項目を足すのは、そのとき改めて決める（足すなら wwt-design-version の手順で版上げ）
- 「よける」でも、守る力は同じ3つ（切り抜き・照合・入力を受けない）が受け持つ。よける動きは見た目の決まりで、安全はそれに頼らない

### 実サイトの2つを、判定を弱めずに通す

**`signal-timeline-live`**（今はおよそ半分落ちる）：

- 原因は、止まったポインターの下をスクロールでリンクが通るたびに、ページ全体が止まること（`docs/ui0d-3.1.md`）。B ではリンクに重なる層だけが止まるので、GIF の層がポインターの下になければ止まらない
- **まず確かめること（1回目の最初）**：テストの GIF（画面基準、取り込みの中心に置かれる）と、ポインターを置く点（`openSidePanelFromIcon` の `clearestPoint`）が重なるか。重なる場合、B でも GIF は正しく止まる（近づいた所は引く）。そのときはテストの判定は変えず、ポインターを置く点を「部品からも、テストする層からも離れた点」に変える。これは手順の直しで、判定はそのまま。ただし、ポインターの点を変えることを「判定を変えない」と見てよいかは D9 で決めてもらう
- 合わせて、上の ① と同じ判定（部品の近くでも、離れた層は止まらない）を実サイトに1つ足す

**`operation-live`**（`docs/theme-removal.md` で保留）：

- 原因は製品ではなく、YouTube の配置の切り替え（読み込みの 0.8〜1.3 秒後）と、headless の Chromium でシークの後の再生が拒まれること。どちらも拡張なしで同じ
- `.work/oplive-wip.patch`（状態で待つ・シークを最後に・音量の枠の広がりを待つ・失敗した段階の記録）に、**配置の確定を待つ条件**を足す：`ytd-watch-flexy` に配置の属性が付き、`#movie_player` の矩形が2回の読み取りで変わらないこと。待ち時間を延ばす・リトライを足す・判定を緩めることでは通さない
- G1.2 の変更の前に、このテストを今のビルドで 10 回通るようにする（2回目の最初）。G1.2 の変更の前後の比較ができるようにするため

## 8. 性能の見積もり

数え方：YouTube の操作部品の候補はおよそ 200 件（`docs/operation-safety-g11-performance-checkpoint.md` の最初の調べで 216 件）。層は最大 32 個、グループは最大 16 個（`IMAGE_LIMITS`・`GROUP_LIMITS`）。

| 処理                             | 今                                                                              | G1.2                                                                                             | 増える量の見積もり                                                   |
| -------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| 入力のたび（`pointermove` など） | 候補を順に見て、近い部品が1つ見つかれば終わる（`some`）。近くないときは全部見る | 近い部品を全部集める（いつも全部見る）。そのあと、層 ≤48 個 × 近い部品（多くて数個）の矩形の比較 | 近いときだけ、候補の残りぶん。200 件の線分の判定で数マイクロ秒の程度 |
| フレームごと（`sample`）         | 同じ判定を1回                                                                   | 同じ判定を1回＋上の矩形の比較＋止める層の集合が変わったかの比較                                  | 数マイクロ秒                                                         |
| world の評価                     | 真偽値を見る                                                                    | 層ごとに集合を引く（`Set.has`）                                                                  | 無視できる                                                           |
| フレームの数                     | 近い／近くないが切り替わったときに1回描き直す                                   | 止める層の集合が変わったときに1回描き直す。リンクの上を順に通ると、切り替わりが増えうる          | **ここが一番の心配**。集合が変わったときだけ描き直す、を守る         |

DOM の読み取り・書き込みは増えない（5 の `pointer-events` の読み取りは、クリック1回に点の候補ぶんだけ）。

合否の基準は AGENTS.md と wwt-perf のとおり：拡張 CPU/フレームの中央値の増分が +0.5ms 以内、p95 の増分が +1ms 以内。場面は起動直後・定常・SPA 遷移直後に分ける。ハーネスは `scripts/g11/`。**新しく、ホイールでスクロールしながらポインターがリンクの上を通る場面を足す**（G1.2 で判定の回数が一番増える場面のため）。

## 止める範囲を絞っても、守る力が弱まらないこと

操作性の3段階の「操作が破綻する（押せない・ずれる・ドラッグが狂う・操作面が隠れる）」は、次の4つが、層の位置や動きと関係なく防いでいる。G1.2 はこのどれにも手を入れない。

| 守っているもの       | どこ                                                                                    | 層の動きと関係ないこと                                                                                                                                       |
| -------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 最後の切り抜き       | `world/operations.ts` の `protectionClip`・`pagePaintRegions`、描画の面ごとの clip-path | 操作部品の保護範囲を、描画の面から切り取る。切り取りは面全体にかかり、層がどこへ動いても、影・ぼかしを含めて部品の上には描けない。止めない層にもそのまま効く |
| 作品は入力を受けない | `scene.ts` の `pointerEvents`（見ているときは false。編集のハンドルだけ）               | 動いている層の上をクリックしても、入力は下の本物の部品へ届く                                                                                                 |
| 入力のときの照合     | `operation-source.ts` の `validate`、`operation-guard.ts` 278〜285 行                   | クリック・キー・フォーカスのたびに、その場で読み直し、点の要素が部品でなければ描画を止める（3回で止めたまま）。層の位置を前提にしない                        |
| 変化の最中は描かない | `operation-guard.ts` の `HOLD`（`deferredFor`）                                         | 部品が動いている 200ms の窓の間は、すべての描画を止める                                                                                                      |

接近の判定は、この4つに足した「狙っている部品のところでは、作品が動かない」という見た目の決まり。G1.2 の後も、**ポインターが近づいた部品に重なる層は、今と同じ条件・同じ時間で止まる**。止まらなくなるのは、その部品に重ならない層だけ。重ならない層は、切り抜きの外で、部品と別の場所に描かれているので、部品の見え方・押しやすさに関わらない。

弱まりうる所と、その手当て：

- 1フレームの遅れ（3）：動いて入ってきた層が止まるまでの1フレーム。その間も切り抜きと照合は効いている。テストで2フレーム以内を確かめる
- ポインターのない「近い」（D2）：止める範囲を、その部品に重なる層に絞る案では、キー操作のときに離れた層が動き続ける。キー操作は点に届くものではないので、押せる・押せないには関わらない
- 画面全体の層・雰囲気の層：今と同じく止まる（雰囲気の層は D7）

## 設計の形

```
operation-guard（Host）
  入力・フレーム → 近い部品の集合（部品ごとのヒステリシス）
  前のフレームの paints（効果のあとの矩形） × 近い部品 → 止める層（ルート単位、部品が離れるまで放さない）
  → environment.approach = { layers: { id: 近い部品の矩形[] } }   ← 作品からは渡せない
world（純粋）
  transforms：approach.layers にある層（とその子）を対象にした規則・追従を飛ばす
  models：approach.layers にある 3D の層だけ止める（D5）
  evaluate：ほかの層は今のまま
world-session
  プレビュー・テイクの上書きがあるとき：上書きの評価の最後の1回に、ライブの approach を入れて計算する
  reduced-motion：今のまま（上書きを捨てて全体を基本状態に）
scene.ts
  止めた層だけに flatten の記録（native.approach）
```

### 録画との互換（追加の依頼の1）

- 今：`world/recording.ts` 72・126〜128 行で、`environment.safeInteraction`（真偽値）が録画の入力に入る。テイク（`world/takes.ts`、`format: 'ww-signal-take'`・`formatVersion: 1`・`runtimeVersion` は 1.3.0／1.2.0／1.1.0）にも、録画した間の Host の制限がそのまま入る。テイクを再生すると、録画のときに部品へ近づいたフレームは、全体が基本状態で再現される
- テイクは作品データ（DesignDocument）に入らない（`signal-timeline-live` が `design` に `takes` がないことを確かめている）。IndexedDB（`browser/take-repository.ts`）とバックアップ（`backup/schema.ts` 186 行）に入る。**作品データの版上げ（wwt-design-version）は要らない**
- 新しいテイク：Host の制限（`safeInteraction`・`approach`）を**録画に入れない**。制限は再生のときに、そのときのライブの値をかける（今も 178〜181 行でライブの制限が優先している）。ランタイムの版を 1.4.0 に上げる
- 古いテイク（1.3.0 以前）：`safeInteraction: true` は「全部の層を止める」と読む。記録済みのタイムラインは今までと同じフレームで再生される（追従・3D は履歴で値が決まるので、読み方を変えると再生が変わる）。どちらにするかは D6
- 古いビルドが新しいテイクを読む向き：新しいテイクに新しい項目を入れないので、`parseWorldInput` の「知らない項目は拒否」に当たらない。ただし `runtimeVersion` 1.4.0 は古いビルドの許可の一覧にないので読めない。これは今までの版上げと同じ扱い
- 互換の確かめ：変更前のビルドで録画したテイクとバックアップを `tests/fixtures/` に置き、変更後に読み込んで、同じ位置のフレームが一致することを unit で確かめる（履歴由来の fixture。テーマ撤去の `pre-removal.wwbackup` と同じ形）

### プレビュー・テイクの再生との混ぜ方（追加の依頼の2）

- 今：`world-session.ts` 178〜181 行。`safeInteraction` が真なら、上書きのフレーム（プレビュー・テイク）を捨てて、ライブの入力で全体を計算し直す
- G1.2：上書きのフレームを作る評価の**最後の1回**に、ライブの `approach` を入れる。1回の評価の中で、止める層は基本状態、ほかの層は上書きの値になる
  - テイク：`createTakeSampler(...).at(position, approach)`。履歴（チェックポイント）は制限なしで進め、最後の1回の評価にだけ制限をかける。チェックポイントにライブの状態を混ぜない
  - シグナルのプレビュー：`previewSignalInput` の入力の `environment` に入れる
- `reducedMotion` は今のまま（上書きを捨てて、全体を基本状態で計算）。全部の層にかかる制限なので、混ぜる必要がない

### ポインターの位置がない「近い」（追加の依頼の4）

| 原因                                 | 止める範囲（案）                                                                                                     |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| フォーカス（部品にフォーカスがある） | その部品に重なる層                                                                                                   |
| ドラッグ・capture                    | その部品に重なる層。ネイティブのドラッグ型（シークバー・音量）は、今と同じく、その部品に重なる層を最後まで止める     |
| `pointerdown`（操作中）              | 押した点にある部品に重なる層。点に部品がなければ、押した点の近く（40px）に重なる層                                   |
| `keydown`（操作中）                  | フォーカスのある部品に重なる層。**フォーカスがページ（body）にあるとき**（YouTube の k・j・l など）をどうするかは D2 |

### 余白と待ち（追加の依頼の5）

40px（入るとき）・72px（出るとき）・350ms は、**部品ごと**に持つ（ポインターと部品の距離の決まりのため）。層ごとには持たない。層は「近い部品に重なっているか」だけで決まり、近い部品のヒステリシスをそのまま受け継ぐ。値はエンジンの定数のままで、作品からは変えられない。層と部品の重なりに余白を足すか（重なるときだけか、40px 以内なら止めるか）は D3。

### 3D の層の resetDynamics（追加の依頼の6）

`world/models.ts` の止め方（99・121・203 行）は、止めた 3D の層だけに効かせる。止めない 3D の層は、再生・視線・揺れを続ける。

ただし、今の止め方は**再生の時刻を 0 に戻す**（121 行で状態を作り直す）。キャラがページを歩き回る作品では、部品に近づくたびにキャラのアニメーションが最初からになる。止め方を「時刻を 0 に戻す」のままにするか、「その場で止めて、離れたら続きから」にするかは D5（揺れの reset は、どちらでも残す）。

# ページ変更時の描画処理（依頼F）

基準コミットは `28d594a`。作品形式・Chrome権限・通常版distは変更しない。

## 固定した計測条件

- DOM変更：ローカルYouTube fixture、1920×1080、保存済みのカード装飾ルール1本、既定のfeatures。
  プレイヤー内の時刻テキストを60回変更し、各回2RAF待つ。CDP `Performance.ScriptDuration` の差を記録する。
  旧版と新版を同じChromeで交互に5組実行する。待機・描画・GPUの時間は含めない。
- World：Eのスクロール32本×64キーの計測をそのまま再利用する。
  検索を使う距離・角度についても32本×64キー、anchor/layer各座標系の計測を追加する。
  いずれも閾値でテストを落とさず、前後を別Nodeプロセスで交互に5組実行する。

変更前の予備計測では、60回のテキスト変更に対してテーマ変数の計算・作品のコンパイル・features.refreshが
それぞれ約120回発生した。スクリプト時間は1組の同一コード比較で57.9ms／67.8ms。
これは計測系の動作確認であり、変更の効果を示す比較値ではない。

## 分離する処理

設定・作品の変更では、従来の全体反映を維持する。ページ変更では既存styleの再接続、表面の更新、
素材の配置基準と選択状態の更新を行う。テーマ変数の再計算・作品のコンパイル・素材一覧の再設定は行わない。
文字だけの変更ではfeatures.refreshも呼ばない。構造の変更・遷移・mode・全画面では、
既存の機能が新しいDOMへ追従するためのrefreshを残す。

| 処理                                   | update / updateDesign  | ページ変更                     | 理由                                                    |
| -------------------------------------- | ---------------------- | ------------------------------ | ------------------------------------------------------- |
| テーマ変数・strength・基底テーマの有無 | 全体反映               | 実行しない                     | 設定と作品だけで決まる                                  |
| 基底styleの生成・内容                  | 全体反映               | 外れた既存要素の再接続のみ     | headなどの差し替えには追従する                          |
| features.update                        | 実行                   | 実行しない                     | 有効設定は変わらない                                    |
| features.refresh                       | 実行                   | 構造・遷移・mode・全画面で実行 | 新しいネイティブ要素の発見と既存機能の配置に必要        |
| 作品の検証・CSSコンパイル              | 従来と同じ検証後に実行 | 実行しない                     | 入力境界の検証は維持し、ページ追従では検証済みCSSを使う |
| 作品style                              | 全体反映               | 既存要素・適用属性の復旧のみ   | 再コンパイルせず同じCSSを再利用                         |
| 素材一覧の設定                         | images.update          | 実行しない                     | 作品の内容は変わらない                                  |
| 素材の配置・基準・全画面の親           | update内の描画         | images.refresh                 | 文字の折返しでもジオメトリは変わりうる                  |
| 編集中の選択・基準の通知               | 実行                   | 実行                           | 編集側が接続状態とジオメトリの変化を確認する            |

YouTube Adapterが変更を分類する。文字の変更でも従来どおりカード・durationの表面判定を行う。
`web-world-themes-`から始まるIDを持つ拡張機能の所有領域の更新は、featuresの構造refreshを要求しない。
これにより、features自身の更新から全体refreshを繰り返す経路も止める。
modeObserverは引き続き`dark`を監視し、全画面の属性・イベントも専用の通知として処理する。
配色は既存CSSのmodeセレクターで切り替わるため、設定由来の変数を再生成する必要はない。

## スクロールとWorldの対応表

スクロール入力はイベント内でレイアウト値を読まず、次のRAFで採取する。
従来のWorld Hostには、その採取通知からさらに描画RAFを予約する経路があった。
DOM Rendererの配置更新が先に評価するケースでは遅れが隠れるが、Host単独の固定入力で1フレーム遅れを再現した。
採取時のRAF時刻を渡し、その場でWorldを評価・反映する。既に予約された評価は取り消して重複を防ぎ、
非表示時の停止と、配置更新側の既存の合流処理は維持する。

`world/layout-index.ts`のWeakMapに、レイアウトごとのID対応表を一度だけ作る。
Signal RegistryのentryForと、点のlayerEntryが同じ表を使う。新しいレイアウトには別の表を作り、
過去のレイアウトや解決できなかったIDの結果を持ち越さない。作品形式や点の意味は変更しない。

## 交互計測の結果

本体の変更後は`d0b53ab`。Windows、Node 24.16.0、Chrome 153.0.8010.12、Core i7-13650HXで計測した。
重いテストと同時には実行していない。

| 対象                                                 | 変更前の中央値 | 変更後の中央値 |
| ---------------------------------------------------- | -------------: | -------------: |
| DOMの文字更新60回：スクリプト合計                    |       87.791ms |        6.644ms |
| World：32本×64キー、距離・角度／anchor               |       0.0458ms |       0.0370ms |
| World：32本×64キー、距離・角度／layer                |       0.0532ms |       0.0359ms |
| World：32本×64キー、スクロール→不透明度（Eと同条件） |       0.0317ms |       0.0319ms |

DOMは5回のスクリプト合計の中央値。Worldは各回1,000サンプルの中央値を5回集め、その中央値を掲載した。
DOMはAB/BAを交互、Worldは既存比較スクリプトと同じABを5組実行する。
DOMの最大は92.710→7.439ms。60回の更新中のテーマ変数の計算・コンパイル・features.refreshは
121〜122回→0回、テーマ変数の書き込みは4,356〜4,392回→0回だった。

スクロール経路はレイヤー検索を使わず、今回の対応表による短縮はない。
Eの0.0225→0.0323msと比べ、現在は同程度の0.0319msであり、旧専用経路との差約0.0094msは残る。
今回、そのために汎用評価の意味を変えたり、別の専用経路を追加したりしていない。

生データ：[DOM](measurements/f-page-changes.json)、[Worldスクロール](measurements/f-world-scroll.json)、
[World距離・角度](measurements/f-world-lookups.json)。最大値と各組の値も含む。

## 回帰テスト

- 文字の小さな変更を繰り返しても、テーマ変数・features.refresh・コンパイルが0回であること。
  時刻からLIVEへの変更でも、durationの表面判定を更新すること。
- 外れたstyleを同じ要素のまま復旧し、新しいカードに作品CSSが適用されること。
- 従来の全体反映経路をテスト専用bundleで接続し直し、新経路と比較する。
  Home・設定変更・作品変更・遷移・dark・light・全画面・全画面解除・独立作品の9状態で、
  同一ブラウザーのスクリーンショットが完全一致した。時刻と日替わり表示だけを両方で同じようにマスクする。
- スクロール後の最初のRAF内で、実際の素材の不透明度が進捗から計算した値と完全一致すること。
  World Host単独でも次フレームの予約を残さないこと。旧Hostに戻すと固定入力のテストは失敗する。
- シグナルと点で対応表を共有し、繰返し時にID一覧を再走査しないこと。別のレイアウトには結果を持ち越さないこと。
- sameSignalRuleの全フィールドを型の必須キー表で列挙し、各値の変更を検出すること。
  仮のoptionalフィールドをSignalRuleに足す検証でも、比較対象の更新漏れを型チェックが拒否した。

型チェック・lint・unit 291件と関連e2e 6件は成功。全e2eとCIの結果は完了報告に記載する。

# UI0-d 3 回目：浮かぶエディターとページの中の Studio を消す

`docs/ui0d-plan.md` の 3 回目。浮かぶエディター（F）、ページの中の Studio（I）、サイドパネルのときにページに出ていた道具の帯（toolbarOnly）を消した。エディターはサイドパネル（S）と別ウィンドウ（W）の 2 つだけになった。

あわせて、2 回目の報告のあとの指示（翔太、2026-10-31）を行った。

- 止めていた side-panel のテストを A（書き直す）で直し、通ることを確かめてから消す作業に入った
- サイドパネル（幅 360px 前後）の 1〜4

最後に、Codex の検証のための「1〜3 回目で変えたことの一覧」を付けた。

## 進めた順番

1. 止めていたテスト（`side-panel.spec.ts`「panel tools replace floating tools …」）を書き直した。外したのは仕切りの判定だけで、道具の置き換え・フォーカス・操作の判定はタブの 1 列で書き直した。書き直しで製品の不具合が 3 つ見つかり、直してから通した（下の「見張り役のテストで見つかった不具合」）
2. F・I・道具の帯を消した。消したあとも、見張り役のテストがそのまま通ることを確かめた
3. F・I で開いていたテストを、W・S へ移すか、止めた（下の「テスト」）
4. サイドパネルの 1〜4 を行い、見張り役のテストに判定を足した

## 設計書（README・計画）と違う判断

- **操作チェックの出し方**：指示は「表示設定の中か、制限があるときだけ」。制限があるときだけ見出しに出す方にした。表示設定（ポップアップの窓）からページの保護範囲の表示を切り替えるには、新しい通信の道が要るため。その結果、制限がないときは「操作面の保護範囲を表示」を押せない。前の帯ではいつでも押せた。必要なら、表示設定の中に通信の道を足す案がある
- **表示設定の英語**：「緊急OFF」の OFF と、表示テーマの名前「YouTube」は残した（翔太の言葉どおりの語、サイトの名前）。テーマの名前 retro は「レトロ」にした
- **ヘッダーの「使い方」**：サイドパネルではヘルプのメニューにだけ残した（同じものが 2 か所にあった。360px に収めるため）

### 実サイトで見つけたこと

- **アイコンから S を開いたあと、シグナルの効果が止まったままに見える**（`signal-timeline-live` が 5 回中 3 回失敗、変更前のビルドでは同じ手順で成功）
  - 原因の調べ方：模擬ページで毎回再現させ、ページの描画（`world-session.ts`）に一時的な記録を入れて流れを見た（記録は消した）。描画は正しい入力で走っていたが、操作面の保護（G1）の「近づいている」が続いていて、シグナルを止めていた
  - 原因：動画の中のアイコンはプレーヤーの操作部品の中にある。押すとフォーカスがそこに残り、保護は「操作部品にフォーカスがある」と数える。変更前は、ページに道具の帯を作るときにフォーカスを帯へ移していたので、たまたま解けていた
  - 実際の Chrome では、サイドパネルがフォーカスを取り、ページはフォーカスを失う。保護はページがフォーカスを持つときだけフォーカスを数えるので、解ける。テストで動かすパネルはフォーカスを取らないので、解けなかった
  - 扱い：製品は変えていない（ページへフォーカスを奪わない今の形が正しい。G1 の判定も弱めない）。テストの開き方（`openSidePanelFromIcon`）に、人がパネルへ移るときの動き（アイコンからフォーカスを外し、ポインターを操作部品から離す）を足した。模擬ページの `side-panel.spec`「scroll keyframes」に、プレビューからライブに戻して保存したあと、スクロールしなくても不透明度がページの位置どおりになる判定を足した
  - 確かめていないこと：本物のサイドパネルを人の手で開いたときの、フォーカスの移り方（自動のテストでは再現できない）。気になるなら、アイコンを押したあとフォーカスをアイコンから外す処理を製品に足す案がある
- `side-panel-live`：道具の帯が全画面で隠れる判定（`data-fullscreen`）が残っていた。帯ごと無くなったので「ページにエディターの物が無い」にした
- `page-marks-live`：F の終了の確認（破棄／保存しない）を押していた。別ウィンドウの「編集を終了」はすぐ終わるので、押してから窓を閉じる形にした
- 実サイトのテストを回している途中に、別のテストを同時に回し、テスト結果のフォルダを取り合って `skin-ui11-live` が記録ファイルのエラーで落ちた。1 つずつ回し直した
- **残っている揺れ（後回し、翔太の判断待ち）**：`signal-timeline-live` の「スクロールに合わせた不透明度」が、上の対処のあとも 5 回中 2 回ずれた（ずれ 0.059 と 0.567。止まったままの 1 ではない）。変更前のビルドは同じ手順で 5 回とも成功。見立て：本物の YouTube は、スクロールのあと読み込みでページの高さが変わる。スクロールの値はスクロールと大きさの変化の通知で読み直すが、`html`・`body` の箱の大きさが変わらずに中身だけ伸びると通知が来ず、古い値のまま残る。変更前は、ページに置いていた道具の帯の描き直しが、ページの変化として読み直しを起こしていたと見ている（確かめていない）。影響は「見た目が少しずれる」×「スクロールのあと高さが変わったとき」。直すなら、スクロールの値を読み直すきっかけ（ページの変化の通知）を見直す。中核（`src/host/signals.ts`）に触れるので、この回ではしていない
- **`signal-motion-editor` が揺れた（2 回目に足した手順の競合、製品側にも後回しの不具合）**：最後の全件で 1 回、繰り返すと 3 回中 1 回失敗。開き直したエディターで、レイヤーがロックされたまま「未保存」になっていた
  - 原因：エディターのページは、復旧用の保持（`chrome.storage.session`）を 180ms まとめてから非同期に書く（`studio/app.ts` の `persist`）。テストは、ロックを「元に戻す」を押した直後に窓を閉じていた。「元に戻した」書き込みが終わる前に窓が消え、ロックした時点の保持が残り、開き直しで戻された
  - 1 回目の対処（元に戻したことを画面で確かめてから閉じる）は効かず、2 回目（保持が消えるのを待つ）は待つ条件が誤り（保持は保存済みでも履歴のために残る）、3 回目（保持の中の下書きでロックが外れるのを待つ）で 10 回続けて成功した
  - 製品の不具合として後回し：人が操作の直後 0.2 秒以内に窓を閉じると、その操作の前の下書きが次に開いたときに戻る。「操作が少し不便」×「まれ」。直すなら、窓を閉じるとき（`pagehide`）に保持の書き込みを待てないので、操作ごとの書き込みを遅らせない形を考える。2 回目からある動きで、この回の変更が原因ではない
- `skin-ui11-live` の調査の 1 件は、変更後で 2 回続けて止まり（画面は白紙、手前の手順の記録なし）、手順ごとの記録を入れて回すと 5 回続けて 15 秒前後で通った。変更前は 1 回で成功。原因は特定できていない

### 全体の形（3 回目のあと）

- エディターは拡張のページ `studio/index.html` だけ。Chrome のサイドパネル（S、`?surface=sidepanel&target=N`）か、別ウィンドウ（W、`?target=N`）で開く
- 並び方は窓の幅で決まる：720px 未満はタブで 1 列、以上は素材・キャンバス・プロパティとレイヤーの作業台。S かどうか（背景の安全の確認と、Chrome が閉じる × の有無）は並び方とは別
- ページ（YouTube のタブ）の content script は、エディターのページから Port（`studio-host.ts`）で受けた操作を Core に渡し、ページの上の印・クリック・キー・ドロップを受ける。ページの上にエディターの UI は出ない。W のときだけ「別ウィンドウで編集中」の印が出る
- 入り口：拡張のアイコン（制作モード ON）・Alt+Shift+E・ポップアップと動画の中の表示設定の「エディターを開く」（S）／「別ウィンドウで開く」（W）・動画の中のアイコン（制作モード ON で S、開けなければ W。OFF なら表示設定）

### 検証で特に見てほしいところ

- **ページに残る処理**：`controller.ts` は、エディターのページがつながっているあいだだけページの上で働く（`editing()` は `remoteOwner` があるときだけ）。つながりが切れると印とイベントの受け口を外す。下書きと履歴は Core に残り、次につないだページが引き継ぐ
- **S を閉じたあと**：前は道具の帯がページに残り、編集が続いていた。今はページは編集の状態を外し（印・クリックの横取りなし）、下書きは残る。開き直すと続きから
- **操作チェック**：制限がないときは、保護範囲の表示を切り替える場所が無い（上の「設計書と違う判断」）
- **実サイトのテスト**：F・I から移した実サイトのテストは、この回に回した分だけ確かめている（下の「テスト件数」）

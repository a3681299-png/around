# UI1：UIの着せ替え

作者がYouTubeの本物のUI部品をクリックで選び、自分で描いた絵に着せ替える。本物の要素はそのまま機能させ、クリック・ホバー・キーボード操作・文字は変えない。作者が描くのは枠と背景まで。アイコンの差し替えは次の段階で扱う。

## 方式

- 既存の `surface-style` ルールを広げる。作者の絵を要素の上に重ねて追従させる方式は取らない。
- 本物の要素に CSS の `border-image`（`fill` 付き）で9スライスを当てる。`border-image` は当たり判定とレイアウトに関与しない。Chromium で `border-style:none`、`border-width:0` のまま描かれ、要素の大きさが変わらないことを確認した。
- 書き込むプロパティは `border-image-source/slice/width/outset/repeat` の5つと、エンジンが読みやすさのために決める `color`（白か黒）だけ。`background-color` は、作者が明示した色（既存の style ルールと「小さいとき：色だけ」）のときだけ。大きさ・余白・位置・`display`・`pointer-events`・`transform`・`z-index`・`outline` は書かない（`tests/skin-data.spec.ts`・`skin-verification-data.spec.ts` で検査）。
- **元の背景は消さない**（UI1.1）。絵の透明な部分からは YouTube の背景が見える。UI1 では背景を透明にしていたため、登録ボタンの白い文字が白いページに残った（1.13:1）。
- 作品データには検証済みの数値・素材ID・状態名だけを保存する。CSS はエンジンが組み立てる。URL は拡張が作った object URL（`blob:` と UUID の形）だけを埋め込む。それ以外の値なら、その部品は本物の見た目のまま残す。

### 枠を描く位置（UI1.1）

`border-width:0` のまま描くと、枠は要素の内側に入る。中身が縁まである部品では重なる。実物の9部品で3つの方式を比べた（`scripts/ui1/methods.mjs`、検証用素材 `frame-light.png`、描く幅6px）。

| 方式                                       | 結果                                                                                                                                                                                                    |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (a) `border-image-outset` で外側へ         | 動画カードとコメント入口は8領域すべて見え、文字にも重ならない。ボタン類は隣との隙間が1〜4pxしかなく、5部品で隣の操作部品へはみ出した                                                                    |
| (b) `pointer-events:none` の前面の擬似要素 | 動画カードは前面に置いてもサムネイルの方が上に描かれた（3/8）。`position:static` の部品（関連動画のカード、コメント入口）は配置の基準を変える必要がある。高評価ボタンは YouTube 自身が `::after` を使う |
| (c) アダプターが「描く要素」を指定         | 枠と中身の重なりは、どの子要素を選んでも解消しない（サムネイルも文字も部品の中にある）                                                                                                                  |

選んだ方式：**部品ごとにアダプターが決める**。作品データには入れない。

- 動画カード：外側へ最大4px（`outset: 4`）。カード同士の隙間は実測で8px以上（関連動画）なので、両側から4pxずつでも重ならない。
- コメント入口：外側へ最大8px（`outset: 8`）。文字が左端から始まる（padding 0px）。実測の空きはアバターまで12px、上24px、下・右32px。
- 残りの7部品：内側（従来どおり）。文字までの余白はボタン11〜16px、説明欄12px。

外側の幅を超える分は内側に描く。`outset` は描画だけで、当たり判定・大きさ・位置・Tab順は変わらない（`tests/skin-live.spec.ts` と `skin-verification.spec.ts`）。

### 文字の読みやすさ（UI1.1）

絵と切り位置・作者の色・作品・明暗のモードが変わったときだけ（毎フレームではない）、エンジンが文字の色を決める。

1. 見えている同じ種類の部品を最大8個選び、それぞれの本物の文字色と背景を読む。文字色は、部品自身と、アダプターが `ink` で指定した子孫（自分で色を決めている子）のすべての色。読む間だけ、ルートに `data-ww-ink-off` を付けてエンジンの色を外す（作品やモードが変わったときだけで、毎フレームではない）
2. 素材の縮小コピー（最大96px）の中央の領域を、それぞれの部品の本物の背景（部品と祖先の背景を重ねたもの）の上に合成し、輝度の暗い5%・明るい5%・平均を出す。平均だけでは、明るい中に暗い線がある絵を見逃す
3. どの部品でも、本物の文字色が暗い端・明るい端の両方に 3:1 以上なら変えない。1つでも下回るなら、全部品で読める方の白か黒を `color` で書く（明暗のモード・状態ごと。CSS は部品の種類ごとなので1色）。選択中のチップ（黒地に白）と未選択のチップ（灰地に黒）のように、同じ種類でも色が違う部品があるため
4. 白でも黒でも 4.5:1 に届かないときは、編集画面に「読みにくいかもしれません」を出す（警告だけ、強制しない）

`color` が届くかは部品ごとに実物で確かめた（`scripts/ui1/methods-entry.ts` の `ink()`）。チップ・登録・高評価・低評価・アクションは部品自身の `color` で文字とアイコンが変わる。動画カード（サムネイル上のバッジを除く文字）、説明欄、コメント入口、検索欄は、子が自分で色を決めるので、アダプターの `ink` でその子にも書く。

独立検証で、検索欄のクリア「×」は親SPANのネイティブの `color` を継承し、暗い絵／ライト表示と明るい絵／ダーク表示で約1:1になることが分かった。`07f7d46` で入力・placeholder・SVGへ `color` を届け、文字ノードを持たない入力やSVGも判定に含めた。`fill` は変更しない。実YouTubeの4組合せで虫眼鏡と「×」は18.88〜19.26:1。`fill` を直接固定するアイコンには、この方法だけでは届かない。

## 作品データ（DesignDocument v13）

`SurfaceStyleRule.skin`（省略可）を追加した。

| 項目                 | 内容                                                                        |
| -------------------- | --------------------------------------------------------------------------- |
| `states.normal`      | 必須。`SkinFrame`                                                           |
| `states.<状態>`      | 任意。`hover`・`focus`・`selected`・`pressed`・`disabled`。省略時は通常の絵 |
| `SkinFrame.assetId`  | 素材ID（`asset-` ＋ SHA-256）                                               |
| `SkinFrame.slices`   | 上下左右の内側の幅。元画像のpx、0〜512の整数                                |
| `SkinFrame.center`   | `stretch`（伸ばす）／`repeat`（繰り返す。CSSでは `round`）                  |
| `SkinFrame.scalePct` | 枠の太さの倍率。10〜400%の整数。描く幅 = slice × 倍率                       |
| `compact`            | 任意。小さすぎるとき `{kind:'color', color}` または `{kind:'frame', frame}` |

- 上限：ルール16件（従来どおり）。着せ替えに使う素材は文書全体で32個まで。素材はPNG・WebPの静止画像で一辺1024px以内、切り位置の合計は画像の幅・高さ以内（保存・検証時に素材のメタデータと照合）。
- v12→v13 は1段の純粋な移行。v12以前の `rules` に `skin` があれば、その段で拒否する（ルールは全段を素通りするため、この1か所で v1〜v12 を覆う）。
- `chain-expected.json` に `history-v12.json`（v12の `renderMode` テストが最初に `parseDesign` へ渡した入力）を追加した。期待値は変更前の `29b8d5b` のパーサーで取得した。全15件で移行後の結果が版番号以外一致することを確認している。
- `css-expected.json` に、変更前の `29b8d5b` のレンダラーで組み立てた全 fixture の CSS を固定した。変更後のレンダラー（旧ターゲット・新 YouTube ターゲットの両方）で、全件バイト単位で一致する。
- 素材の参照（保持・掃除・バックアップ・Studio の復旧）は `designAssetIds()` にまとめ、着せ替えの素材も含める。

## 部品（SiteAdapter）

`src/sites/youtube-targets.ts` に、意味のある固定ID・セレクター・状態の条件を閉じ込めた。作品に保存するのは状態の名前だけ。条件は `&` を1つ含むセレクターで、エンジンが `&` を部品の印（`[data-ww-surface~="…"]`）に置き換える。

| ID                  | 部品                       | 状態（通常以外）                                             |
| ------------------- | -------------------------- | ------------------------------------------------------------ |
| `video-card`        | 動画カード                 | ホバー・フォーカス（内側）・押下                             |
| `subscribe-button`  | チャンネル登録ボタン       | ホバー・フォーカス・登録済み・押下・無効                     |
| `like-button`       | 高評価ボタン               | ホバー・フォーカス・高評価済み（`aria-pressed`）・押下・無効 |
| `dislike-button`    | 低評価ボタン               | 同上                                                         |
| `action-button`     | 共有などのアクションボタン | ホバー・フォーカス・オン・押下・無効                         |
| `search-box`        | 検索欄                     | ホバー・フォーカス（内側）                                   |
| `filter-chip`       | 絞り込みチップ             | ホバー・フォーカス・選択中のカテゴリ・押下                   |
| `description-panel` | 説明欄の枠                 | ホバー・展開中                                               |
| `comment-input`     | コメントの入力欄           | ホバー・フォーカス（内側）                                   |

G1の操作面の連番IDは使わない。部品の印は既存の surface 走査（MutationObserver＋rAF でまとめる）に相乗りしており、着せ替えのための別の監視はない。

**印は使うときだけ付ける**（UI1.1）。作品のルールが名前を挙げた部品と、着せ替えツールを開いている間はすべての部品に印を付ける。それ以外では、部品のセレクターを走査の照合に加えない。固定した実 YouTube の DOM で走査1回を交互に測ると、9部品のセレクターは検索結果で +1.6ms（8.9→10.5ms）、動画ページで +1.8ms（10.3→12.1ms）かかっていた。起動直後には全体の走査が数回あるため、着せ替えを使わない人にも負担が出ていた。動画カードの印は UI1 以前からあり、常に付く。

## CSS の組み立て

- 状態の条件は `:where()` の中に入れ、すべての状態のルールの詳細度をそろえる。優先順は記述順で、通常 → ホバー → フォーカス → 選択中 → 押下 → 無効。
- ID の重み2つ分のガード（`:not(#ww-skin-a):not(#ww-skin-b)`）で、ID を含むテーマのセレクターより上に置く。
- 強制プレビューは `html[data-ww-skin-force="部品:状態"]` の1属性で切り替える。プレビュー中の部品だけ自然な状態のルールを外し、指定した状態の絵（なければ通常の絵）を表示する。要素ごとの処理はしない。その状態の新しい絵を読み込んでいる間も通常の絵を出す（何も描かれない瞬間を作らない）。プレビュー用のルールは着せ替えツールを開いている間だけ組み立てる。
- 文字色のルールは `html[data-ww-mode="light|dark"]` ごとに、絵と同じ状態の順で並べる。値は `#ffffff` か `#000000` だけを受け付ける。
- すべてのルールは部品の印（`[data-ww-surface~="…"]`）をキーに持ち、条件は `:where()` の中に置く。ブラウザーがルールを属性ごとに振り分けられる。
- 小さすぎる判定は `ResizeObserver` で、部品の border-box が通常の絵の描く枠（左右・上下の合計）より小さいときだけ要素に `data-ww-skin-compact` を付ける。`compact` を設定した部品があるときだけ監視し、大きさが変わったときしか動かない。新しい部品の登録は文字だけの変更では行わず、構造の変更か遷移のときだけ行う。

## 編集画面

ツールバーの「UIを着せ替え」（U）で開く。クイック編集では、着せ替えの欄がレイヤー・プロパティの欄と入れ替わる。ページ内 Studio では右のインスペクター列を使い、キャンバスと素材の列は残す。

- 選ぶ：マウスを乗せた部品を紫の枠で強調し、「部品名・ページ上にN個 クリックで選択」を出す。部品に該当しないボタン・リンク・入力欄・アイコン・サムネイルには灰色の点線と「未対応」を出す。クリックしてもページは遷移しない。
- 同じ種類の部品は、ページ上のすべてを紫の点線で囲む。パネルに「ページ上のN個に同時に反映されます」と出す。
- 部品の一覧：見つからない部品は「見つかりません（どこにあるか）」、絵の読込中・失敗はその理由を出す（G1の「制限中」と同じ考え方）。一覧から選ぶこともできる。
- 絵の取り込み：パネルの枠へドロップ、クリックで選択、またはページの部品の上へドロップ。既存の素材の取り込み（検証・保存・lease）を使い、レイヤーではなく着せ替えの枠に入れる。
- 取り込んだ絵の確認（UI1.1）：画像の大きさ、絵が描かれている範囲、描く枠の上下・左右の合計（外側へ描く部品はその幅も）、ページ上で一番小さい部品の大きさを出す。枠の合計が部品の高さ・幅を超えて中央が消えるとき、絵が1つの切り位置の中にしかないとき（UI1 の petal.png のような絵）、枠が文字までの余白より太いときは、理由を添えて警告する。
- 切り位置の初期値：各辺の1/3（最大64px）。枠の太さの初期値は、描く枠が部品の典型の大きさの半分以内に収まるように5%刻みで下げる。96px の検証用素材なら、登録ボタン（36px）で25%、動画カードで100%。
- 読みやすさ：エンジンが文字の色を白か黒に切り替えたときは、その色とコントラストを状態のタブの下に出す。白でも黒でも 4.5:1 に届かないときは「読みにくいかもしれません」と出す。
- 9スライス：素材のプレビューの上に上下左右のガイドがあり、ドラッグで動かすと本物のページにすぐ反映される。ドラッグ全体で Undo 1回分。矢印キー（Shift で10px）と数値入力も使える。
- 状態：状態ごとのタブ。部品固有の名前（登録済み・選択中のカテゴリなど）を出す。絵のない状態は「通常の絵を使っている」と示し、専用の絵を入れるか、通常の絵をもとに編集できる。「ページ上でこの状態を表示」で、ホバーや押下をしなくても本物のページで確認できる。プレビュー中は選択の枠を消す。
- 大きさ：部品の典型サイズの小・通常・大の3つを、エンジンと同じ値でパネル内に描く。ページ上の実際の大きさも出す。「小さすぎるとき」で、枠のまま縮める／色だけ／簡略版の絵を選び、ページ上で小さいときの見た目を強制表示できる。
- Undo・Redo・保存・破棄は既存の編集コマンドに乗る。プレビューの状態は表示だけの状態で、作品にも履歴にも入らない。

## 性能（実YouTube）

2026-10-26、Windows・Chromium（Playwright 同梱）、1920×1080、未ログインの新規プロファイル。部品の多いページとして検索結果（`lofi hip hop`、カード19件）を使った。`scripts/ui1/measure.mjs` で、起動直後（遷移から6秒）、定常（8秒待ってから0.5秒ごとにスクロールする6秒）、SPA遷移直後（動画を開いてから6秒）を分けて測った。

- 合否：拡張の CPU 時間（1フレームあたり）。拡張のコールバック（rAF・タイマー・Mutation/Resize/IntersectionObserver・イベント・読込時の実行）を、フレームごとに合計した値。中央値の増分 +0.5ms 以内、p95 の増分 +1ms 以内。
- フレーム全体の値（Chrome trace の AnimationFrame）は参考値。
- 計測ビルドは `scripts/ui1/build.mjs`。製品のソースは書き換えず、content script の前後に計測用のコードを足すだけ。

### UI1.2 着せ替えありの起動性能（`41e7f68`、2026-10-28）

起動直後に着せ替え9部品を足すと p95 が +2.70ms だった（UI1.1 検証）。CPU プロファイルで、全文書の走査と `matches()` の呼び出し（`scan`/`mark`/`owned`/`videoCardContainer`）と、文字色の判定（`getComputedStyle`・画素の輝度計算）が重いと分かった。直したのは次の3つ。

1. **セレクターの索引**（`src/sites/surface-index.ts`）：行ごとに「右端の複合セレクターの id / class / タグ」で引き、要素ごとに試すセレクターを1個前後に絞る。結果は全行を順に試す従来の方法と一致（`tests/surface-equivalence.spec.ts`、実 YouTube でも差 0）。
2. **部品の先読み**：`setDesignParts` を `connect` の前に呼び、起動時の全文書走査の重なりをなくした。後から部品が増減したときは、その部品のセレクターだけで1回検索する。
3. **文字色の判定を起動の山から外す**：
   - 前回の白/黒の結果を `chrome.storage.local`（`webWorldThemes.skinInk.v1`、最大4件、バックアップ対象外）に保存し、起動時はそれで描く。作品データには入れない。保存値は厳密に検証し、`#ffffff`/`#000000` 以外は捨てる（`src/design/ink-cache.ts`）。
   - 保存結果があるときは、本来の判定をアイドル時（`requestIdleCallback`、最長4秒）に行って確かめる。保存結果がない・別のアドレスへ移った・部品が初めて現れたときは、これまでどおり直ちに判定する。
   - 判定そのものも軽くした：祖先の背景色を1回の判定で共有、同じ（素材・スライス・背景）は1回だけ計算、輝度は256段階の表、並べ替えは型付き配列。

### UI1.1 独立検証（対象 `2c93579`、2026-10-28）

## 未対応・制限

- Studio のウィンドウとサイドパネルからは着せ替えを編集できない（ツールを表示しない）。素材のプレビューと取り込みはページ内のパネルで行う。
- ログインが要る状態（登録済み・高評価済み・低評価済み・展開後のコメント入力）は、翔太が手動で確かめる。部品のセレクターと状態の条件は、未ログインの実YouTubeで確認できた範囲で決めた。
- 角丸：`border-image` は `border-radius` で切り抜かれない。`mask-image` の試作では角を丸められたが、フォーカスの枠や子要素まで切れ、スタッキングコンテキストも作るため入れていない。角を丸く見せたいときは、絵の角を透明にして描く。
- 動画ページの「横のパネル」の配置（`split-scroll`＋`using-fixed-panel`）では、説明欄が横のパネルのタブに移り、`ytd-watch-metadata #description` が見えない。この配置での説明欄の DOM は未確認（UI1.1 の実サイト確認で1回だけ出会い、6回の再読込では再現しなかった）。
- `fill` を直接固定しているアイコンには、エンジンの `color` だけでは届かない。検索欄の現在の虫眼鏡とクリア「×」は、SVGの `color` で補正できることを確認済み。
- 読みやすさは、見えている同じ種類の部品を最大8個まで調べて判定する。それより下にある部品は、同じ種類の文字色と背景だと見なしている。

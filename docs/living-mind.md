# フェリスの心と、物としての UI（2026-11-12、ノート PC、Claude Code）

`feat/living-onboarding`。翔太の方針の 5 つの軸（UI との物理的な相互作用・自律 AI・仮想デスクトップの進化・人格とアニメーション・2D と 3D の融合）を、1 つの出来事に全部が連動する形で実装した。狙いは「フェリスがいることで、Web の体験そのものが変わる」こと。

演出の芯は 1 つ：**デスクトップはフェリスの遊び場で、フェリス自身がそれを使う**。何も操作しなくても、フェリスは机に座ってデスクトップを自分で開き、気分に合う壁紙を選び、ボールを出して追いかけ、窓の上に飛び乗って足をぶらぶらさせる。見ている人は、その窓を掴んで運んだり、投げ落としたり、フェリスをなでたりできる。

（追記：このあと視点とデスクトップの見た目を作り直した。[living-shell.md](living-shell.md)。心と演出役は同じ。）

## 1. 最初の 1 分（何も操作しないとき。seed 1 の実測）

|     秒 | 起きること                                                                                     | 連動するもの                                               |
| -----: | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
|  0〜18 | ベッドへ行き、寝転んでスマホを見る                                                             | 布団の沈み、スマホの光                                     |
| 18〜27 | スマホを置き、机へ行って座る                                                                   | 椅子のたわみ                                               |
| 27〜32 | **デスクトップを自分で開く**。壁紙の窓を開き、気分の壁紙にし、自分の窓を前に出し、ボールを出す | 手前からの光が部屋を満たす。モニター・照明・窓の色が変わる |
| 32〜39 | 部屋の手前まで来て、**画面を内側からコンコン叩く**                                             | 手の位置から波紋が広がる                                   |
| 39〜51 | 窓の縁に触る。ボールへ駆け寄って打つ（転がる間は目で追う）                                     | 窓とボールは慣性で滑り、端で跳ね返る。光と影が付いて動く   |
| 51〜65 | 窓の上に**飛び乗って座る**（♪）。足をぶらぶら                                                  | UI より手前に描かれる。窓は重みで沈む                      |

そのあとは、心（下の 2）が選ぶ。同じ seed なら同じ 1 日、訪れるたびに seed が変わる。

## 2. 心（`src/characters/mind.ts`、純粋な関数）

固定の 1 日の流れ（`life-script.ts`）はなくした。小さな Utility AI が、次にすることを点数で選ぶ。

| 要素     | 中身                                                                                                                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 欲求     | げんき（`energy`）・たいくつ（`boredom`）・きょうみ（`curiosity`）・かまって（`social`）。していることに応じて増減する（遊ぶと疲れ、寝ると戻る。何をしていても退屈と興味はじわじわ戻る） |
| 感情     | よろこび・ふきげん・おどろき・こんらん。出来事で上がり、時間で消える                                                                                                                     |
| 短期記憶 | 直近 12 件の出来事。「投げ落とされたのは 2 回目か」などで反応が変わる                                                                                                                    |
| 長期記憶 | `affinity`（見ている人との仲。−1〜1）と訪問回数だけを `localStorage` に置く（数値だけ。なでると上がり、何度も投げると下がる）                                                            |
| 選び方   | 11 の行動それぞれの点数（欲求・感情・世界が今それを許すか）＋決まった数列からの小さな揺らぎ。直前にしたことは点が下がる                                                                  |

行動：寝る／ベッドでスマホ／パソコン（机でデスクトップを使う）／床でひと息／すねる／ボール遊び／窓を調べる／押しのける／引っぱる／窓に座る／画面を叩く。

出来事と反応の例：

- **投げ落とされる**：仲が良くて 1 回目なら「びっくり＋うれしい」。2 回目からは不機嫌になり、床に座って背を向けてすねる（💢、尻尾を左右に打つ）。なでると機嫌が直る
- **掴もうとした物を直前に取られる**：最初は「？」。3 回続くと怒る
- **寝ているところを起こされる**：窓が飛んできて起きると不機嫌。なでて起こすのは優しい起こし方として許す
- **行けない所にボールが止まる**：3 秒ほど試して「？」と諦める

LLM は使っていない（必要にならなかった）。

## 3. 演出役（`src/living-room/director.ts`、純粋な関数）

心が選んだ行動を、毎フレームの指示（どこにいるか・何に手を伸ばすか・スマホ・気持ち・吹き出し・デスクトップへの操作）に変える。体の段階とデスクトップが今差し出している物（手が届く窓の縁、座れる窓の上、ボール）を見て決める。

- スマホはベッドに置く物にした（机はパソコン）。ベッドを離れる前に、イヤホンを外してスマホを置く
- 自分で開いたデスクトップは、寝る前に自分で閉じる。見ている人が開いた物は閉じない
- 見ている人が掴んでいる物は奪わない（待って見ている）。飛んでいる物は、遅くなるまで目で追う

## 4. 物としての UI

| こと                               | 実装                                                                                                                                                                                                                                                        |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 投げられる窓とボール               | `desktop/physics.ts`：離したときの速さで滑り、進む向きに傾いて戻り、画面の端で跳ね返る。ボールはほとんど減速しない。`desktop/view.ts` が動かす                                                                                                              |
| フェリスが触る・押す・引く・打つ   | 窓の縁やボールの位置を、視線が手の高さを通る点として部屋の座標にし、そこへ歩いて手を伸ばす。手が着いた瞬間に、画面上で窓に速度を与える                                                                                                                      |
| 窓に座る・運ばれる・投げ落とされる | `approach.ts` に `toPerch`・`perchUp`・`perch`・`perchDown`・`tumble`・`dazed` を足した。座る点は、窓の上辺を通る視線の上で、部屋の床の上にある一番低い点。窓が動けば一緒に動く。窓が 1250px/秒を超えると振り落とされ、2 回転して床に落ち、しばらく目を回す |
| 画面を叩く                         | 部屋の手前でカメラへ手を伸ばし、手が着いた位置から DOM の波紋を出す                                                                                                                                                                                         |
| なでる                             | 部屋のフェリスをクリック                                                                                                                                                                                                                                    |

## 5. 2D と 3D の融合

- **UI より手前のフェリス**：窓に乗っている間と落ちている間は、フェリスだけを透明な背景で先に描き、その絵を UI の上に重ねたキャンバス（`#front`）へ写す。そのあと部屋をフェリス抜きで描く。WebGL のコンテキストは 1 つ、体を描くのは 1 回のまま
- **UI に付いて動く光と影**：窓とボールそれぞれの下に、その色の光だまり（`screen-glow.ts` の枠を 5 つに増やした）と、床の柔らかい影を置く。画面上の位置から毎フレーム部屋の座標を出すので、ドラッグしても投げても付いて動く。前に出ている窓はフェリスも照らす
- 手前からの光（`ui` の層）とモニターの光（`screen` の層）は前回のまま

## 6. 人格の見え方

部屋は引きで見るので、顔だけでは伝わらない。3 つで見せる。

| 手段                   | 中身                                                                                                                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 吹き出し（`emote.ts`） | 頭の上の小さな丸い吹き出し：Zzz・！・？・♪・💢・♡・…。キャンバスに図形で描く（画像なし）                                                                                               |
| 体（`living-body.ts`） | 眠い：頭が沈んで舟をこぐ、目が半分閉じる。不機嫌：あごを引き肩が上がる、耳が寝る、尻尾を打つ。混乱：首を左右に大きくかしげる。驚き：体が伸び上がり腕が開く、耳が立つ。眠り：目を閉じる |
| 行動                   | すねて背を向ける、押しのける、諦める、寝る                                                                                                                                             |

「住人」の窓に、今していること・気分・4 つの欲求のメーターを出す（心が見える）。

## 7. 確かめた結果（ノート PC・Chromium 画面の外・本物の GPU・144Hz）

録画と画像は `C:\wwt-private\Felis_v0.8.1\work\living-mind\`（リポジトリの外）。

- 何もしない 180 秒：スマホ → パソコン → 画面を叩く → 窓を調べる → ボール → 窓に座る → パソコン → 叩く → スマホ → 調べる → パソコン → 寝る。エラー 0
- 手を入れる：窓に座ったフェリスを運ぶ → 投げる → 「！」で振り落とされる → 目を回す → なでると「ごきげん」。エラー 0
- 公開用（フェリスなし）：開く・閉じる・ボール・壁紙でエラー 0。止まっている間は描画 0 回
- 負荷（フェリス入り、180 秒の中央値）：体の処理 0.74ms、描画呼び出し 1.25ms、フレーム間隔 12.7ms。前回（デスクトップ開）は体 0.82ms・描画 1.31ms。合否の計測ではない
- unit 700 件通過（3 件スキップ）。新規 14 件（`tests/living-mind.spec.ts`：心・演出役・窓の物理・窓に座る段取り）
- 身体の e2e（`living-room-body-live`）は足の固定の検査で 0.094m（基準 0.06m 未満）。前回・前々回と同じ値で、今回の変更による悪化ではない

テストが見つけた製品側の不具合を 1 つ直した：行動が切り替わるフレームだけ、ベッドの外で「スマホを使う」指示が出ていた。

## 8. 自分で決めたこと

- LLM は入れない。Utility AI と数値の記憶で、固定ループからは抜けられた
- 窓は部屋の中の板にしない（DOM のまま）。物らしさは、慣性・傾き・跳ね返り・沈み・光と影・フェリスの手で作る
- 手前に描くのは「乗っている・落ちている」間だけ。床にいる間は部屋の中（ガラス越しに曇って見える）
- 1 日の速さは実時間の数十倍（遊ぶと 3 分ほどで疲れ、1 分足らずの昼寝で戻る）。眺めていて変化が続くことを優先した

## 9. 残り・気になる所

- 窓の上では「座る」動作を使っているが、引きの画では立っているように見えることがある。窓の上辺に腰を合わせているので、脚は窓の手前に下がる
- 引っぱる・押すは、手が着いた瞬間に窓へ速度を与えるだけ。掴んだまま歩く動きはない
- ボールが家具の上に止まると諦める。自分で窓を引き寄せるなどの解決はしない
- すねる・眠い・混乱の体の表現は、近くで見ないと分かりにくい。吹き出しが主な手がかり
- 縦長の画面では、窓が部屋を覆って手が届く場所が少ない
- `localStorage` が使えない環境では、仲と訪問回数を覚えない（動作は同じ）
- フェリスカム（顔のアップを窓に映す）は作っていない。表情を見せる次の一手の候補

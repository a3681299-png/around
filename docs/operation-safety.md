# G1 操作性の保証

G0の[空間設計3節](spatial-design.md#3-操作性の保証g1)を、YouTubeと既存v11作品へ適用する。
作品の保存形式、Chrome権限、素材の検証経路は変更しない。mainと通常版distは更新しない。

## 契約と検査の担当

| 担当              | 実装                          | 役割                                                                                         |
| ----------------- | ----------------------------- | -------------------------------------------------------------------------------------------- |
| SiteAdapter       | `sites/youtube-operations.ts` | ネイティブの操作面と、利用できる合成先を列挙する                                             |
| Hostの取得        | `host/operation-source.ts`    | DOMの実体・文書世代・幾何世代を保持し、不変の数値スナップショットだけを公開する              |
| Worldの数値ガード | `world/operations.ts`         | 評価後の範囲・不透明度・入力奪取・影等の広がりを検査する                                     |
| Commit Host       | `host/operation-guard.ts`     | 反映前と重要な入力前に、発行元・世代・実DOM・elementFromPointを照合する                      |
| Renderer          | `renderers/dom/scene.ts`      | 最終出力をクリップし、停止したメディアを休止する。安全な上下関係を確認できない合成は停止する |
| 信頼されたUI      | `settings/safety-controls.ts` | 緊急OFF、手動再開、Studioの保護範囲とレイヤー別の制限理由を表示する                          |

操作面は `id / owner / generation(documentId,geometry) / kind / shape / protectedEnvelope / availability / policy / compositionCapability` を持つ。
availabilityには出現・表示・無効・フォーカス・テキスト編集中・ドラッグ中・pointer capture中を含める。
policyは固定平面、遮蔽の禁止/許可、ネイティブだけが入力を受ける指定である。
作品にこの契約を変更するフィールドやコマンドはない。freezeしただけの偽スナップショットも、Hostの発行記録にない限り受け付けない。
DOM・入力文字・押されたキーの内容はWorldやStudioへ渡さない。
全画面ではブラウザーが表示するfullscreen要素の内側だけを操作可能として扱う。外側のコメント等に残る矩形を、表示中の操作面やヒット照合の対象と取り違えない。内側の操作部は引き続き同じ検査を通す。

## YouTubeで保護する操作面

| IDの系統                            | 対象・kind                                      | 保護範囲                                                               |
| ----------------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------- |
| `player.video`                      | プレイヤー全体、gesture                         | クリックはネイティブのまま。映像中央への非操作の描画は許可             |
| `player.controls.top`               | 上部のタイトル・操作部、click                   | プレイヤーの上端から64 CSS px、全幅。自動で隠れても予約                |
| `player.controls.bottom`            | 下部のシーク・音量・ボタン、drag                | プレイヤーの下端から112 CSS px、全幅。隠れても予約                     |
| `player.seek.*` / `player.volume.*` | シークバー・音量、drag                          | 実矩形＋4 CSS px。親・座標・ネイティブのドラッグ処理を変えない         |
| `search.*`                          | 検索欄、text-input                              | searchbox全体＋4 CSS px                                                |
| `comment.*`                         | コメント入力、text-input                        | composer/実入力欄＋4 CSS px                                            |
| `navigation.*`                      | ガイドの主要リンク・マストヘッドのリンク、click | 実矩形＋4 CSS px                                                       |
| `control.*`                         | ボタン、button role、入力、slider等             | 実矩形＋4 CSS px。range/sliderはdrag                                   |
| `menu.*`                            | サイトのメニュー、dialog、listbox、select       | 表示中は保守的にviewport全体。OSのselectが開く間は合成未対応として停止 |
| `native.focus`                      | 一覧で分類できなかったフォーカス先              | 実矩形＋4 CSS px。未知の操作先に装飾をかぶせない                       |
| `composition.unavailable`           | 未対応のDOM構造・包含ブロック                   | 作者の描画を停止し、ネイティブの表示を残す                             |

通常の装飾はytd-app直下、全画面ではfullscreen要素直下の専用ノードに置く。ネイティブの親やstyleを書き換えない。
その合成先との共通の祖先までstacking contextを確認し、ネイティブが確実に前に出る面では、その上下関係を使う。
それ以外は最終出力のclip-pathで除外する。ネイティブUIを読み戻した画像や偽の操作面で置き換えない。
shadow内の `all:initial!important` は外側のinline指定より強いため、clipとz-indexはshadowの宣言が参照するHost専用CSS変数で渡す。
実際の拡張に不透明な画像を取り込むテストで、computed clip/z-indexと操作部のピクセルを確認する。

### スクロール、プレイヤーの分離、狭める見込み

スクロールする操作面について、画面に固定された装飾へ現在の矩形だけで穴を開けない。
ネイティブが常に上になると確認できない面は、その横幅の**縦方向の移動範囲全体**を除外する。
これにより、主スレッドが描画を待っている間のコンポジタースクロールでも穴が取り残されない。代わりに、装飾の欠ける範囲は広い。
左右・viewport・表示面・合成能力が変わったときは、observer内ですぐ所有描画を隠し、安定してから再開する。

映像と操作部は分離できる。プレイヤー基準の作者レイヤー/グループは、プレイヤーと一緒に動く専用描画先を使い、上下64/112 CSS pxを常にクリップする。
同じmediaノードとグループの部分木を移し、デコーダー・マスク・グループ不透明度を保つ。専用描画先は1つとし、作者のz-indexと同順位の順序を維持する。
全画面では画面基準を含む全ルートを同じ描画先へ集め、配置基準が異なっても重なり順を保つ。全画面ではない固定配置のプレイヤーでは、別の部分合成を使わず画面側の単一描画先へ戻す。
通常表示の映像への描画はクリックを受けない。明示的な編集モードでは、同じクリップの内側の作者レイヤーとハンドルだけが編集入力を所有する。
その間もシーク・音量・上下の予約領域を除外し、中央に別のネイティブ操作部品が現れたらこの合成先を使わない。
保護範囲で欠けたハンドルはStudioのプロパティから編集できる。

**G1.1での拡張（画面基準の作品の編集）：** 明示的な編集モードの間に限り、画面基準の作品とハンドルも映像の中央で編集入力を所有する。プレイヤー基準の作品が映像内の描画先を使えずページ追従層へ回った場合も同じ。
対象は確認できた中央（上64/下112 CSS pxの帯を除く `occlusion: 'allow'` の範囲）だけで、メニュー・エラー・広告が出ているとき、全画面ではない固定配置のプレイヤー、全画面では作らない。
画面固定層とページ追従層の保護領域は、この中央だけを開け直し、保護対象の面（上下の帯、シーク、音量、中央に現れた本物の操作部品を含む）を**現在の矩形**（ページ追従層ではページ上の範囲）で切り抜く。中央の外は従来どおり。通常表示（編集モード外）と雰囲気層は変えない。
中央に本物の操作部品（再生前の大きな再生ボタンなど）が出ても中央の所有はなくさず、その部品だけを切り抜いて入力直前の照合でも拒む。映像内の描画先（プレイヤー基準の作品）は、重なり順の都合から従来どおり中央の部品があると使わない。
理由：画面基準のまま映像の上に作品を置いて調整する制作手順は、作品を保存する前にプレイヤー基準へ移さなければ操作できず、実サイトの制作試験（editor-ux・studio）でも映像の上でドラッグできなかった。
中央の部品で所有ごと外していた最初の版では、自動再生されない（再生前の大きな再生ボタンが出る）実サイトで編集できなかった（studio・studio-workspace）。
中央では移動範囲全体を除外しないため、非同期スクロールの間は固定層のハンドルが古い位置のまま帯や操作部の上へずれることがある。
そこで編集ハンドルへの押下は、ジェスチャーを始める前に操作面を新しく読み直し（キャッシュも合成待ちの窓も使わない）、押した点の下に保護対象の面があれば、ジェスチャーを始めずに描画を停止する。次の押下は本物の操作部へ届く。
DOMの変化・リサイズ・スクロールイベントを伴わない移動（transformアニメーション）で帯をハンドルの下へ動かす試験で、この照合がないと編集が入力を奪い、照合があると奪わないことを確認した（`tests/operation-safety.spec.ts` の stale screen-plane handle）。
他のプレイヤー内ボタン、広告、エラー、メニューを検出した場合も、操作面の保護を優先する。

デモ2に必要な「脚が映像に少し垂れる」ための非操作描画は中央領域で可能。
ただし初版は上端64 pxを全幅で保護するため、**上縁をまたぐ胴体と脚を一続きに描く配置はまだ制限される**。
狭める候補は実際の上部ボタン/タイトル/フォーカス枠の領域と、下部のpreview・字幕設定・volume展開領域である。
自動表示、広告、字幕、キーボードフォーカス、シアター/ミニ/全画面で各領域を測り、スクロールと同じ合成先で保護できた部分だけ狭める。
G1で未確認の領域を安全と仮定して上端の予約を外すことはしない。

## 停止・復帰と環境設定

緊急OFFは作品・設定のON/OFFより優先するHostの禁止状態で、`webWorldThemes.safety.emergencyOff` に保存する。
Alt+Shift+Q、設定画面、Studio/サイドパネルから実行できる。候補Xは隔離Chromeで未割当だったため、実割当を確認できたQを採用した。
任意の環境で競合しないという保証は置かず、実際の割当または未割当をUIに表示し、chrome://extensions/shortcutsで変更できる。
手動OFFは、明示的な「描画を再開」まで保持する。設定の変更・バックアップ復元・作品のシグナルでは解除しない。
OFF時は既存の終了処理で所有描画、購読、デコーダー、原本参照、WebGLを解放する。作品・保存・未保存編集・Undoは維持する。

幾何世代やヒット先が合わなければ即時停止し、350 ms以上安定していて入力中でなければ再開する。
ヒット先の照合は、クリック点を含む操作面のうち、見えているもの（接続中・大きさあり・`visibility` が `hidden` でない。スナップショットの `availability.visible` と同じ条件）だけを対象にする。YouTubeはホバーで出すボタンを隠したまま配置しているため、見えない操作面の上のクリックを不一致に数えない（G1.1.1）。見えている操作面を別の要素が覆ってクリックを受けた場合は、これまでどおり不一致として止める。
WebGLコンテキスト喪失では3Dレイヤーだけを停止する。同じレイヤーの破綻やヒット不一致が3回繰り返された場合は自動復帰を止め、理由と、エディターの操作チェックにある「描画を再開」の案内を出す（G1.1.1。以前はページの再読み込みが必要だった）。
「描画を再開」は失敗の回数を0に戻すだけで、判定は変えない。同じ横取りが起きればすぐ止まり、3回続けば再び自動復帰を止める。作品のデータからは呼べず、編集を持つエディターの接続からだけ受け付ける。
単なるDOM交換を、繰り返す不正なヒットと同じ回数制限に含めない。

止めたときの文は、デザインシステムの Copy に従い、何を守ったかと直し方を1文ずつにする（`SafetyStatus.stopped` と `remedy`）。クリック点に作品の層があれば、直し方にその層の名前を出す。世代・照合などの内部の言葉は出さない。

開発用に `WW_GUARD_TRACE=1`（出力先は `.work` の下だけ）でビルドすると、照合が合わなかったときの「予想したクリック先」と「実際のクリック先」を、ページのDevToolsのコンソール（拡張の content script の文脈）に `[Web World Themes G1]` で出す。

```bash
WW_GUARD_TRACE=1 WW_BUILD_OUT=.work/guard-trace npm run build
```

記録の処理は `WW_GUARD_TRACE` ラベルの中にあり、通常のビルドと計測用ビルドは `dropLabels` で落とす（`tests/skin-build-flags.spec.ts` で確認）。

接近は本物の未変形の矩形とポインター線分を使い、40 pxで安全側へ入り、72 pxを越えて350 ms安定すると戻す。
フォーカス・ドラッグ・capture・キー操作中も安全側に置く。演出で動いた位置は使わない。
接近中は作者の動き、追従、signalによる変形、3Dの姿勢/視線を基本状態へ戻す。
マスク等の見た目の効果は最終クリップで保護し、接近だけで既存のマウスマスクの意味を変えない。

prefers-reduced-motionはHostのmatchMediaからinput.environmentへ渡す。動き・追従・揺れ・signalによる点滅を作者の基本状態へ戻す。
アニメーションメディアは既存の静止経路を使い、VRMの揺れはresetし、進行を0にする。マウスマスクの中心も基本位置に戻す。
動画の再生/停止による表示の条件は保持し、フェード時間を0にする。
Timelineの再生・録画プレビューにも、現在のHostの制限が優先する。

`user.idle.duration` は秒単位の数値シグナルとして登録する。Hostが最後の操作時刻だけを保持し、内容は記録しない。
非表示中は0とし、再表示時を起点にし直す。アイドル演出で操作面の保護を外せるコマンドはない。

## Studioの表示

「停止キーと操作チェック」から保護範囲をON/OFFできる。自動復帰を止めたときだけ、操作チェックに「描画を再開」が出る。レイヤー一覧の「制限中」と詳細一覧に、操作面ID・クリップ/停止/平面化の理由・直し方を出す。
復帰したら表示も解除する。接続が切れたらオーバーレイを外す。
`enforced`（エンジンが止めた箇所）と `advice`（表現への助言）は別の表示にする。G1でコントラスト等の新しい助言判定は追加しない。
保護範囲表示自体はクリックを受けず、作品のデータ・履歴・復旧checkpointへ混ぜない。

## G0との差と今回追加しないもの

- 停止キーは上記の実割当結果からQにした。
- アルファ画像の不透明ピクセルの証明は行わず、0より大きい不透明度の作者描画を最終出力で保守的にクリップする。半透明を重ねた回避も許さない。
- 現在の矩形に合わせた画面全体の穴抜きは採用せず、ネイティブの上下関係・縦方向の保護範囲・プレイヤーと一緒に動くクリップを組み合わせた。
- 既存v11に3D空間・新カメラ・rig・IK・クリップ割当・コマ打ちの項目を加えない。第4節の追記は後段の設計のみ。
- 未対応の合成は作者の描画を止める。未知のネイティブ操作を偽の操作に置き換えて救済しない。

レビュー修正として、バックアップの足りない設定は既定値で補い、供給された値の型/未知項目は引き続き厳格に拒否する。
書き出せない作品のエラーにはサイトIDを含める。エディターのショートカットはYouTube以外では何もしない。
commandsからURLが得られないChromeでは、自拡張の最上位YouTube contentからの認証済み通知を使い、遷移したタブの認可を破棄する。
Service Worker再起動直後でその通知がない場合だけ、自拡張contentの応答を確かめる。その場合、Chromeのユーザージェスチャー制約により既存の独立Studioへのフォールバックになることがある。

## 検証と性能

2026-10-23、Windowsで `npm run typecheck`、`npm run lint`、unit **320件（11.2秒、lintと並行実行）** が成功した。
unitには不透明なクリック透過描画、影の広がり、未対応の合成、編集所有領域でも解除できないシーク保護、接近の線分とヒステリシス、idle、作品からの解除拒否、reduced-motion、VRMの揺れのresetを含める。

e2eは通常対象の既存212件とG1追加11件で、Chromeの実入力、ネイティブキー、全画面、保存・破棄・Undo/Redo・Studio復旧を検証する。
新しい主な試験は次のとおり。通常の全e2eとCIの最終結果は変更の完了報告と[当該ブランチのActions](https://github.com/a3681299-png/web-world-themes/actions?query=branch%3Acodex%2Fcreator-editor-spike)を参照する。

- 不透明PNGを正式な取り込み経路で追加し、通常/プレイヤー内の両方の描画先でシークバーのスクリーンショットが完全に一致する。native rangeのドラッグとキー、検索/コメント入力、全画面の結果も作品なしと一致。5回連続成功。
- 数値スナップショットのDOM交換/偽造、反映前の世代不一致、停止後の安定待ち、3Dだけの反復停止、停止中の他の2D描画を確認。
- 全画面で画面/プレイヤー基準の不透明な2枚を重ね、z-indexを入れ替えた両方向のピクセルが正しいことを確認。修正前は一方の描画先が常に前になり、この試験が失敗した。
- 操作面を横切って離れた後、追加のpointermoveなしでヒステリシスから復帰する。
- 緊急OFFで描画・テーマを外し、未保存の作品とUndoを保持する。通常設定の変更では解除されず、手動再開で戻る。
- Studioの制限バッジ、詳細理由、保護範囲、緊急OFFを実際の拡張で確認。

G1の保護範囲へ絵を置く旧テストは、遮蔽の専用試験と、保護範囲外でのマスク/グループ/編集精度の試験に分けた。比較の精度、Undoや保存の検証、既存の安全検証は緩めていない。
座標だけで始めていたドラッグは、Hostの一時停止が終わり、elementFromPointが編集対象（または選択中の同じグループ）を指すことを待つ。forceクリックや既存タイムアウトの延長は使わない。
親の移動でpointer captureが失われる不具合は、更新時に既存のプレイヤー内ノードを別の親へ往復させない修正で解消した。
全画面の外のコメント欄に矩形が残り、素材を誤って停止するケースは、ブラウザーが実際に提示する全画面の範囲とavailabilityを合わせて修正した。
不透明レイヤーのピクセル比較は、fixtureのポスターから最初の映像への切替と競合していた。`requestVideoFrameCallback`でデコード済みの映像を待ってから一時停止し、比較の完全一致は維持した。
静止中のRAF数の試験では、分の切替による拡張の時計更新が3回の別UI処理を混ぜていた。時計を1分進める固定入力で同じ3回と時計のDOM更新だけが再現した。試験内の壁時計だけを固定し、タイマー・`performance.now`・フレームは実時間のままにした。Hostの停止解除も明示的に待ち、静止中/ポインター移動時の余分なRAFが0という比較は緩めていない。時計の表示更新自体は従来どおりである。

### 実サイト

```powershell
$env:WW_TEST_EXTENSION_PATH = '.work/g1-dist'
$env:WW_LIVE_OPERATIONS = '1'
# 今回成功した隔離ブラウザー。普段のプロファイルは使わない。
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH = 'C:\Program Files\BraveSoftware\Brave-Browser\Application\brave.exe'
npm run test:e2e -- tests/operation-live.spec.ts --output=.work/g1-live-brave-results
```

Braveの実行ファイル版 `155.1.97.59`、新規プロファイル、本物のYouTubeで **1件成功（2.8分、ブラウザー終了待ち込み）**。

### 1フレームのCPU時間

同じ32レイヤーのWorld評価を、追加検査なし/ありでAB・BAの順を交互に12組、1組200フレーム、各300フレームのウォームアップ後に実行した。
Windows、Playwright Chromium 153、headless 1100×760、操作面29件。他のブラウザー試験を止めて計測した。
12組の中央値は中央2値の平均とし、差は各組の追加時間の中央値を別に求めた。

| 条件                                      | 検査なし相当 |   検査あり |   追加時間 |
| ----------------------------------------- | -----------: | ---------: | ---------: |
| 幾何が変わらない通常フレーム              |   0.01425 ms | 0.04925 ms | 0.03550 ms |
| 毎フレーム、実DOMの幾何と合成順を取り直す |   0.01300 ms | 0.70450 ms | 0.69225 ms |

検査ありにはHost sample/commit、数値ガード、安全な領域の分割、shadowのclip用CSS変数への書き込みを含む。
後者は重要な入力前などの再確認コストも毎回含めた条件である。
GPUのクリップ処理、実際のラスタライズ、任意の大きさのYouTube DOM全体の上限を示す計測ではない。
生の各組と計測定義は[JSON](benchmarks/operation-guard-windows.json)、再実行は `tests/operation-safety.spec.ts --grep 'frame overhead'`。

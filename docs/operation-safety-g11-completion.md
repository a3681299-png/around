## 実装したこと

- 操作面候補の差分収集、祖先の判定の共有、同じタスク内での合成先の判定の共有、拡張自身のDOM変更の除外で読み取りを減らした。幾何の連続変更は200msの窓で集約し、待つ間は作者の描画を停止する。入力直前の再取得は待たせない。
- ページ内の配置基準を持つルートに、文書と一緒にスクロールする描画先を追加した。ページと一緒に動く操作面は現在の矩形と4pxの余白で切り抜く。画面固定層の縦帯は維持する。
- `renderMode: 'atmosphere'` を追加した。雰囲気の描画先全体の実効不透明度をエンジンで33%に制限し、重ねても上限を超えない。ぼかし・フィルター・影とクリックの受け取りを禁止し、Studioにも種類と上限を表示する。
- DesignDocument v12で増やした保存項目は `renderMode` だけ。省略は従来の通常描画となる。v1〜v11の履歴由来fixture14件について、移行前との一致を確かめている。
- 編集中の中央の再生ボタンは、その矩形を保護し、中央全体を失わないようにした。ページ追従層・雰囲気層のルートを更新ごとに移動してドラッグを取り消す不具合と、ミュート解除ボタンを窓全体のメニューと誤分類する不具合も修正した。
- 今回、初期設定を読み込む前のStudio接続を、本当のOFFと区別した。未取得の応答には既存の再試行を使う。実際のCoreとClientを組み合わせた回帰試験は修正前に失敗し、修正後に成功する。最初の設定がOFFの場合は従来どおり拒否する。

現在の配置基準は画面とプレイヤーの2種類。ページ追従層を実際に使うのは、映像内の描画先を使えないプレイヤー基準のルートである。動画カードを識別して配置する保存項目や、説明欄の新しい選択肢は追加していない。グループの部分木・不透明度・マスクを維持し、重なり順を守れない構成は固定層へ戻す。全画面では従来の単一の描画面を使う。

## 確認用ビルド

統合前の拡張は、リポジトリ直下から見て `.work/creator-editor/.work/g11-check-dist`。Chromeの「パッケージ化されていない拡張機能を読み込む」で指定できる。通常の `dist` はまだ旧mainのままである。

再ビルドは作業ツリー `.work/creator-editor` で、PowerShellなら次を使う。

```powershell
$env:WW_BUILD_OUT = '.work/g11-check-dist'
npm run build
```

統合する場合は、mainが `6721ce4` のまま・作業ツリーがcleanであることを再確認してからブランチをマージし、mainで通常の `npm run build` を行う。ビルド後にmanifestの権限と通常distを確認してpushし、リモートのSHAが一致することを確認する。元の制約により、この統合操作だけはユーザーの明示的な確認を待っている。

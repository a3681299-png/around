# ライブキャンバスを中心にしたStudio

起点: `c23bed9`。Editor Core、World Runtime、DesignDocument v7と素材保存は維持する。現在の独立Studioは、対象タブのCoreへ共通コマンドを送り、サイト内のクイック編集と同じUI部品を使っている。

## ワイヤーフレーム

添付図を基に、実装済みの機能だけで構成する。

```text
┌ Studio  ファイル  編集  レイヤー  表示  ヘルプ ──────────────────┐
│ ↶ ↷ 保存  対象: YouTube   選択/変形  サイト操作  カード  マスク │
├──────────────┬────────────────────────────┬────────────────────┤
│ ツール│素材  │                            │ プロパティ         │
│       │ ＋   │  実際のYouTube             │ X Y / W H / 回転    │
│       │ □ □  │  元の動画・検索・スクロール │ 不透明度・基準      │
│       │ □ □  │  素材を直接選択・移動・変形 ├────────────────────┤
│       │      │                            │ レイヤー           │
│       │      │                            │ 階層・表示・ロック │
├──────────────┴────────────────────────────┴────────────────────┤
│ 接続状態 / 保存状態 / 選択数 / 操作とエラー                    │
└───────────────────────────────────────────────────────────────┘
```

タイムライン、ペイント、未実装のブレンド・光源はボタンを置かない。マスクと振る舞いは現在のエフェクトUIをプロパティ内で利用する。FPSやメモリーの架空の値も表示しない。

## 配置と技術案

- インページStudioはYouTubeタブ上にShadow DOMで制作UIを配置する。中央は透明でクリックを通し、その下の実YouTubeを使う。iframe・スクリーンショット転送は使わない。
- YouTube固有の幅、固定ヘッダー、ガイド、Watchの列とシアターの調整はSiteAdapterの専用モジュールに置く。既存ノードの親や順序、動画要素の寸法属性、再生状態を変更しない。
- 左右と上下の確保領域はUIからHostへ数値で渡す。Appの利用幅を狭め、固定ヘッダーを中央へ収める。中央の幅が小さい場合はWatchを一列へ切り替え、動画の縦横比を保つ。成立しないページはパネルを畳む表示に退避する。
- 標準は左176px・右320pxとし、それぞれ4pxのリサイズ境界を確保する。1366pxでは中央862px、1920pxでは中央1416pxになる。幅を調整できる。狭い画面では素材をツールレールへ畳み、さらに狭い場合は右パネルも畳む。
- 全画面は制作UIと確保領域を一時撤去し、選択ハンドルと編集キーも停止する。保存済み／ドラフトの作品表示は既存Rendererに従う。全画面を終了すると制作配置を戻す。
- Studio終了・OFF・0%では、専用CSS、属性、変数、Observerとリスナーを解除する。元のスタイルを上書き保存せず、CSSを外して復帰する。
- 画面基準の作品座標は従来のブラウザービューポートのまま。制作パネルの開閉で保存値を書き換えない。新規素材は中央の作業範囲へ配置する。パネル下の既存素材はパネルを畳んで選択できる。

## 操作と共通化

`選択/変形` は画像レイヤーを操作し、`サイト操作` は動画、リンク、検索へ操作を通す。`カード` で従来の動画カードを選択できるようにし、動画を見る操作と区別する。マスクボタンは選択中オブジェクトの既存設定を開く。

Coreの選択・変形・グループ・履歴・保存コマンドは共通。操作ツールは保存作品に入れない編集セッションの状態として扱う。独立Studioも同じ新しいWorkbenchを使い、接続UIをツールバーとステータスのスロットへ入れる。クイック編集は同じプロパティ、レイヤー、アイコンとコマンドを使うコンパクト表示として残す。

新Workbenchは `editor/panel.ts` の既存フォームを再利用し、UI自身のDOMだけを配置し直す。選択に応じた値の更新、入力検証、エフェクトUI、レイヤーツリーを二重実装しない。共通UIにChrome APIやYouTubeセレクタを入れない。

## デザインシステム

ニュートラルな暗色を4段階、1pxの境界線、2px程度の角丸、24〜28pxのコントロール高を基本にする。SVGアイコンは16px・共通線幅。通常のツールボタンは透明で、フォーカス・選択・ホバーを区別する。アクセントは選択と有効なツールに使う。

プロパティとレイヤーは上下で同時表示し、各領域にスクロールを一つずつ設ける。説明はヘルプへ移し、グループ化できない理由や保存エラーなど、その場で必要な情報は残す。未選択時は基本変形を無効状態で表示する。

## 段階と検証

1. 旧画面を保存し、実YouTubeでCSSによる領域確保と動画・ヘッダー・スクロールへの影響を計測。
2. SiteAdapterのレイアウトとインページ起動を実装し、元レイアウトへの復帰をテスト・コミット。
3. 共通Workbench、アイコン、素材棚、上下パネル、折りたたみと幅保存を実装。既存コマンドへ接続してコミット。
4. 独立Studioと共通化し、操作ツールと入力・ショートカットを確認。
5. 1366/1920/狭幅のスクリーンショット、既存機能の回帰、実YouTubeと性能測定を分けて記録。

通常・シアター・全画面・SPA・スクロール・保存・再接続・OFF/0%を確認する。実サイトの結果とfixtureの結果を混同しない。main、通常版dist、Chrome権限は変更しない。

## 実装した境界

- `sites/youtube-studio.ts` とCSS: YouTubeの表示領域、固定ヘッダー、プレイヤーの表示枠、全画面と復帰。UIから受け取るのは4辺の数値だけ。
- `studio/layout-types.ts`: 確保領域とHostの表示状態。DOM・Chrome APIを含まない。
- `studio/workbench.ts` とCSS: 2段のメニュー／ツールバー、左の素材、右の上下パネル、ステータス。UIの配置だけを所有する。
- `studio/asset-library.ts`: 作品で使用している素材の静止サムネイル。新しいプレイヤーを作らずHostの描画済み画素を利用する。
- `editor/panel.ts`, `workspace.ts`, `layer-tree.ts`, `effects-panel.ts`: 既存フォーム、入力検証、階層、コンテキストメニューを再利用。クイック編集も同じ部品を使う。
- `editor/number-scrub.ts`: 数値ラベルのドラッグを既存フォーム入力へ接続。`begin/end`で一つのUndo操作にまとめる。
- `editor-core/`: 操作ツールをセッション状態へ追加。作品文書・Runtime・変形や履歴の計算は維持する。
- `browser/studio-client.ts`, `studio/app.ts`: 独立Studioから同じ対象タブのWorkbenchを開く。既存Port、対象管理、復旧を利用する。

標準動画要素のサイズは、制作領域内のプレイヤーへCSSで収める。YouTubeが設定したinlineサイズをコピー・上書き保存しない。作品座標は従来どおりで、パネルの配置は別のUI設定として保存する。

将来のDesktop Hostは、`hostLabel`、レイアウト通知、Geometry／Storage／通信の既存ポートを供給する。WorkbenchにChrome APIやサイトセレクタを追加せず利用できる。任意のドッキングフレームワークやタイムラインの抽象化は導入していない。

# ライブモード：映像の世界と部屋をつなぐ（2026-11-12、ノート PC、Claude Code）

`feat/living-onboarding`。YouTube の MV やライブ映像を、3D の部屋全体で体験する。仮想デスクトップに「プレイヤー」を足し、通常再生（カードの中）とライブモード（部屋がライブ会場になる）を用意した。

狙いは、動画を再生するページではなく、**映像の光と音が部屋に出て、フェリスがそれを聴いている**こと。映像そのものには何も重ねない。

## 1. 起きること

| 順  | 見ている人                                                           | 部屋                                                                                                                                                                       |
| --- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | ドックの「プレイヤー」を開き、YouTube のアドレスを貼って「再生」     | カードの中で YouTube 公式のプレイヤーが再生する。カードはほかの窓と同じく掴めて、フェリスが触ったり座ったりできる                                                          |
| 2   | 「ライブモード」を押す。ブラウザーが「このタブを共有しますか」と聞く | カードがそのまま部屋の奥の大きなスクリーンになる（作り直さないので再生は途切れない）。カメラが寄り、部屋の明かりが落ち、バーやドックは消える                               |
| 3   | 許可する                                                             | 映像の左・中央・右の色が、棚・ベッド・床・フェリスを照らす。映像の縁の色が床・天井・左右の壁へ伸びる。フェリスはスクリーンの前へ来る                                       |
| 4   | 眺める                                                               | 静かな曲では画面を見て聴く。にぎやかになると体を揺らす。サビでは見ている人のほうを向いて踊る。静かな所から一気に盛り上がると跳ねて喜ぶ。光線が拍で揺れ、視点はゆっくり漂う |
| 5   | 「終える」か Esc                                                     | 取り込みをやめ、部屋が元に戻る。フェリスは自分の暮らしへ戻る（機嫌が良くなっている）                                                                                       |

操作は画面の下に小さく出る（ポインターを映像の外で動かすと出て、数秒で消える）：視点（ステージ／フロア）、光と音の連動、終える。

## 2. 実映像の色と音をどう取るか（調べた結果）

| 方法                                                                                                      | 結果                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 埋め込みの中を直接読む（canvas へ描く、音をつなぐ）                                                       | **できない**。プレイヤーは別オリジンの枠で、ページからは画素も音も読めない。ブラウザーの決まりであり、回避しない                                                                                |
| YouTube の IFrame Player API                                                                              | 再生状態・題名・エラーは取れる。色と音は取れない                                                                                                                                                |
| **このタブの取り込み＋領域の切り出し**（`getDisplayMedia` の `preferCurrentTab`、`CropTarget`／`cropTo`） | **できる**。実ブラウザーで確認した：取り込みの種類は「タブ」、プレイヤーの箱だけに切り出した映像が読め、タブの音も一緒に来る。見ている人の許可が毎回要る（画面共有と同じ確認）。Chromium 系のみ |
| サムネイル画像（`i.ytimg.com`）                                                                           | 取れる（どのページにも配られている）。動かない 1 枚                                                                                                                                             |

採用：ライブモードに入るときにタブの取り込みを頼み、出るときにやめる（`src/living-room/live/capture.ts`）。

- 取り込むのはこのタブだけ（確認の画面にほかの選択肢を出さない指定）。タブ以外が返ってきたら読まずに止める
- 映像は 256×144 以下で受け取り、16×9 の色に縮めて捨てる。音は低・中・高の大きさだけを見る。**保存・録画・送信はしない**
- 音は解析器にだけつなぐ（鳴っているのはプレイヤー自身の音）
- 断られた・対応していないブラウザー：サムネイルの色で部屋を照らす（動かない）。音は聞こえないので、フェリスは再生中だけ静かに揺れる（聞こえないものに合わせて踊るふりはしない）
- 埋め込みが許可されていない動画（公式 MV に多い）：YouTube 自身の「YouTube で見る」の案内が出る。こちらは理由を一言出し、ライブモードには入れない

### 権利・規約（2026-11-12、翔太の決定：この方式を残す）

翔太の決定：許可つきでこのタブの映像と音を読み取る方式を、コンテスト作品に残す。下は判断の材料として書いたもの。

- 映像は YouTube 公式の埋め込みプレイヤーをそのまま見せ、上に何も描かず、広告や操作部品も隠していない。色と音の読み取りは、見ている人が自分のタブの共有を許可したときだけ、そのページの中だけで行う
- ただし YouTube の API 利用規約は、プレイヤーの映像・音を分けて扱うことや加工を広く制限している。**「許可を得て色と音量を読み、部屋の照明に使う」ことが規約の範囲かは、こちらでは断定できない**。コンテスト作品として出す前に、翔太の判断がほしい。だめなら、サムネイルの色＋音なしの代替表現だけを残せる（コードは同じ道を通る）

### 会場（`live/stage.ts`）

| こと       | 中身                                                                                                                                                                                                                            |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 客電       | 部屋の焼いた光を 30% まで落とす（`screen-glow.ts` に `dim`）。ランプや画面は 45% まで                                                                                                                                           |
| 映像の光   | スクリーンの左・中央・右に灯り 3 つ。家具は自分の色と向きで受ける（前からある画面の光の仕組み）。フェリスにはスクリーンの両脇から、その側の色で                                                                                 |
| 縁の広がり | 16×9 に縮めた映像そのものを、床（下の縁）・天井（上の縁）・左右の壁（左右の縁）に、スクリーンから離れるほど薄く貼る。映像の端にある色が、その隣の部屋の面に続く                                                                 |
| にじみ     | 同じ絵を、スクリーンの後ろに 1.9 倍でぼかして置く                                                                                                                                                                               |
| 光線       | スクリーンの上から 6 本。色は映像の上の縁。曲がにぎやかなときだけ出て、2 拍で半往復揺れる。暗い映像では光線も暗い                                                                                                               |
| 視点       | ステージ：頭の上から少し見下ろす。スクリーンが画面の上 6 割、その下の床にフェリス。フロア：後ろから部屋全体。どちらも、ゆっくり漂い、ポインターに付いて回り込む（スクリーン・部屋・フェリスが互いにずれて動くのが奥行きになる） |

- **映像の上には何も描かない**。プレイヤーはページのカードで、いつも 3D より手前にある。フェリスや光線が重なる位置に来たら、映像のほうが勝つ
- 部屋の光を動かすのは映像だけ。拍で動くのは、光線・カメラ・フェリス

## 4. フェリス

- 心（`mind.ts`）には「ライブ」という行動を足した。自分からは選ばない（ライブモードの間だけ）。していた事はやめて来る。寝ていても音楽で起きる（怒らない）
- 何をするかは曲の盛り上がりで決まる：0.32 未満は聴く、そこから揺れる、0.64 以上で踊る。上がるには 0.8 秒、下がるには 2.5 秒続く必要がある（曲の短い息継ぎでは踊りをやめない）
- 気分が出る：不機嫌・疲れ切っているときは、にぎやかでも聴くだけ。うれしいときは、少し静かでも踊る
- 3 秒以上の静かな所から踊りに入ると「曲の一番いい所」として、跳ねて喜ぶ（うれしさが上がり、退屈が下がる）
- 聴く・揺れるの間は画面を見ている。踊るときは見ている人のほうを向く

実際の曲（NCS の Cartoon「On & On」、埋め込み可）での推移：イントロは揺れる → 静かな間は聴く → サビで踊る。テンポはイントロで 84〜87（曲は 87）。

## 6. 自分で決めたこと

- 映像はページの要素のまま遠近をかける（取り込んだ映像を 3D の板に貼り直さない）。貼り直すと、画質・音とのずれ・操作部品が失われ、規約上も加工になる
- そのため、3D の物は映像の手前に描けない。構図のほうを合わせた（フェリスは小柄で、耳の先がスクリーンの下の縁に届く高さに立つ）
- 取り込みはライブモードの間だけ。カードで普通に見ている間は読まない
- 点滅を弱める仕組みは、演出より安全を取った（速い点滅の MV では部屋はほぼ一定の明るさになる）
- 見本の動画は入れていない（他人の動画を決め打ちで載せない）。最後に見た動画の ID だけ、欄の初期値として `localStorage` に置く

## 7. 残り・気になる所

- Chromium 系だけ。Firefox・Safari はサムネイルの色になる
- 取り込み中はブラウザーの「共有中」の表示が出る（消せないし、消すべきでもない）
- プレイヤーの音量を大きく下げると、曲が静かだと判断される（盛り上がりの下限を絶対値で持つため）
- テンポは曲によって倍・半分に取ることがある。体は拍の時計で動くので破綻はしないが、踊りの速さは合わないことがある
- 踊りは内蔵の 1 本だけ。足は床に固定したまま上半身が踊る（足の固定の仕組みのため）
- フロアの視点では、手前の家具（カート、服のラック）がフェリスにかかることがある
- 足した壁と天井は客電と一緒に落ち、縁の広がりは乗るが、灯り 3 つの光は受けない
- 縦長の画面は未確認
- ライブ中の 180 秒の連続実行と、身体の e2e は回していない

## 9. 没入感の改修と、体力が切れたときの暮らし（2026-11-13、ノート PC、Claude Code）

狙い：動画を 3D の部屋で観るのではなく、映像の世界が部屋に広がること。効果を足すより、元の映像の光を部屋へ延ばすことを優先した（光線・にじみ・縁の広がりの強さは前のまま）。

### 体力（翔太の指摘：一定時間で体力が切れると何もしなくなる）

前は、ライブで体力が 0 まで減ると「疲れ切って聴くだけ」になり、そのまま戻らなかった。

| 場面                           | すること                                                                                                                                                                                                          |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ライブ中に体力が 0.14 を切る   | スクリーンの前のラグへ、見ている人の側から前へ倒れ込み、うつ伏せのまま顔を上げて画面を眺める（足はパタパタ、仰向けにはならない）。眠らない。寝転んでいる間に回復し（約 40 秒で 0.62）、起きて元の場所で音楽に戻る |
| 静かな曲を 12 秒聴き続ける     | その場に座って聴く。曲が揺れる・踊るほどになったら立つ                                                                                                                                                            |
| ライブが終わったとき体力がない | 今までどおり、心が「眠る」を選んでベッドへ行く                                                                                                                                                                    |

- ベッドではなく床にしたのは、ベッドがスクリーンの裏側にあるため（寝ても画面が見えず、見ている人からも隠れる）
- 寝転ぶ・座る間は、近い視点（ステージ）が一歩下がって少し見下ろし、床のフェリスが画面に入る。立つと戻る
- 置き場所は `live/stage.ts` の `rest`、判断は `director.ts` の `LIVE_REST`、うつ伏せのままにする印は `Seat.lie.prone`（`approach.ts`）
- 見つけて直したもの：同じ場所で「座る」から「立つ」へ替わると、席が替わったと見なされず座ったままだった（`approach.ts` の `moved`）

### 光

- **映像の中の光の位置**：16×9 の色から、全体より明るい所の重心を読む（`frame-light.ts` の `focus`）。真ん中の灯りをその位置へ動かし、フェリスに当たる左右の灯りの高さと強さも寄せる。左下にスポットがある映像なら、部屋はスクリーンの左下から照らされる。位置は色よりゆっくり追う
- **映像の光だけで部屋が浮かぶ配分**：客電を 30% → 16% に落とし、映像の灯りを 0.9 → 1.7 に上げた
- フェリスには、映像の上の縁の色を後ろ上から（頭と肩の縁）、下の縁の色を床から当てる
- 部屋の右の壁と天井が本物（焼いた面）になったので、前の残り「足した壁と天井は灯りを受けない」はなくなった

### 移行

一斉のフェードをやめて順番にした：客電が先に落ちる → カメラがゆっくり寄る → 暗くなってから映像の光が部屋に立ち上がる。出るときは逆（映像の光が先に引き、部屋の光が戻る）。

### 視差

ゆっくりした前後の漂い（±3.5%）を足し、ポインターでの回り込みを少し広げた。スクリーンの前の床と物が映像の下を滑る。映像の構図と縦横比は変えていない（カードに遠近をかける作りのまま）。

### 部屋の側

寝転ぶ帯（ラグの x 0.15〜0.75）から小物をどかして焼き直した。ラグの材質を `rug_` で始まらない名前にした（ページは `rug_` の面を体の下で 7 cm へこませるので、薄いラグは床の下へ潜る）。

### 残り

- 本物の YouTube の取り込みでは見ていない（手で与えた絵と音だけ）。実際の MV で、光の位置の動きと明るさの配分を見て直したい
- 重さは測っていない（足したのはフェリス用の平行光 2 つと数値の計算だけ）
- 手で与えた絵のように色の境目がはっきりした映像では、縁の広がりの境目が床と壁に四角く出る
- 寝転ぶ動きは、ベッドへ飛び込む動きをそのまま床に使っている。座っている間・寝転んでいる間は拍に合わせて体を揺らさない
- 机の椅子の頭がスクリーンの下の縁に少しかかる（机と椅子を奥へ動かしたため）

## 2. 作品データ v18（翔太が本番の部屋で使う書き方）

`space` に3つ足した（どれも省略できる。省略すると v17 と同じ）。数値と決まった名前だけで、JS・CSS・シェーダー・セレクターは入らない。

```jsonc
"space": {
  // …v17 の項目（room・lights・camera・glass・videoLight）…
  "resident": { "layerId": "mirdo", "front": 0.8 },   // 部屋に住むキャラ（作品の3Dレイヤーの id）と、手前へ来る気の多さ 0〜1
  "camera": {
    "sway": 1, "dolly": 0.6, "follow": 0.8,
    "shots": {                                          // 3つそろえて書く。あると sway・dolly は使わない
      "top":      { "x": 0,    "y": 0.05,  "z": 1.5,   "fovDeg": 30, "shiftX": 0,    "shiftY": 0,    "orbitDeg": 0, "sway": 0.15 },
      "comments": { "x": 0.2,  "y": -0.05, "z": -0.25, "fovDeg": 50, "shiftX": 0.3,  "shiftY": 0.06, "orbitDeg": 0, "sway": 0.6 },
      "theater":  { "x": -0.3, "y": 0,     "z": -0.2,  "fovDeg": 52, "shiftX": -0.7, "shiftY": 0.04, "orbitDeg": 3, "sway": 0.4 }
    },
    "transition": 1.6                                   // 形が変わるのにかける秒（0.2〜6）
  },
  "layout": {                                           // 部屋の素材の目印の代わりに使う（なければ素材から読む）
    "floorY": 0,
    "floor": [{ "x0": -2, "z0": -4, "x1": 2, "z1": 0 }],          // 歩ける床（長方形、32まで）
    "spots": [{ "kind": "sit", "x": 0.95, "y": 0.5, "z": -2.45, "headingDeg": 180 }]  // sit・hide・stand、32まで
  }
}
```

- カメラの形の `x`・`y`・`z` は camera_main から自分の軸でのメートル（z は後ろ）。`fovDeg` は縦の画角。`shiftX`・`shiftY` は画面の半分の高さに対する割合（横は画面の縦横比で割る）。`orbitDeg` は部屋の真ん中（camera_main の前 3.2m）の周りの回り込み。値の範囲：位置 ±6m、画角 10〜100、シフト ±1、回り込み ±30
- **配置データは、ふだんは部屋の素材から読む**（部屋の素材の約束のとおり）：`marker_sit_<場所>`（お尻の位置）・`marker_hide_<場所>`・`marker_stand_<場所>` の Empty（矢印＝Empty の +Z が顔の向き）と、`navmesh_floor` の三角形。テストの部屋は `marker_sit_chair`・`marker_hide_desk`・`navmesh_floor` で動いた。作品の `layout` は、目印のない部屋か、作品ごとに変えたいときだけ
- 住むキャラは、作品の3Dレイヤー（VRM）のキャラの動作から、名前で選ぶ：`idle`・`walk`・`sitting-idle`（座る）・`sitting-enter`（座り込み）・`sitting-exit`（立ち上がり）・`crouch`（隠れる）・`jump`（跳ねる）・`interact`（板に触れる）。名前で分からないときは、取り込みで測った役割（idle・move・sit）で選ぶ。ミルドの Quaternius の動作の名前でそのまま動く
- 移行：`migrateV17ToV18` を1段。v17 以前に3つの項目があれば拒否。期待値は `history-v17.json`（`18b8b6f` の `tests/space-data.spec.ts`）を変更前の `bd06c2a` のコードで取った（`tests/fixtures/designs/README.md`）

## 3. 自分で決めたこと

| 決めたこと                                                                                                                  | 理由                                                                                                                           |
| --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 住むキャラは部屋の描画器の場面の中に描き、手前に来たときだけ今までの手前のキャラに切り替える                                | 家具の裏に隠れる・部屋の光で照らすには、部屋と同じ奥行きで描くしかない。手前は今の G1 の守りをそのまま使う                     |
| 「手前へ行く」は、部屋が見えている割合（板・動画の面積から。一番上の形では 0.4 倍、シアターでは動画の左右の幅から）で決める | 設計書の「部屋が見えている所でミルドが見える時間を多く」。タイマーではなく、使う人のスクロールとシアターの切り替えに付いてくる |
| 空いた床に立つ場所を足す（0.9m 格子・16まで）                                                                               | 家具の場所が画面の外だと、ミルドが一度も見えない（テストの部屋は家具が右に寄っている）                                         |
| 既定のカメラの形は、テストの部屋で家具がコメント欄の右・シアターの右に来るように合わせた                                    | 部屋ごとに違う。本番の部屋では作品の `shots` を合わせ直す                                                                      |
| `resident.layerId` は id だけ持ち、レイヤーが消えたら住まない（検証で拒否しない）                                           | エディターでレイヤーを消しても作品が壊れないように                                                                             |

## 5. 残り・気になる所

- **e2e 全件は回していない**（Codex）。触った所の e2e は 51 通過・4 skip（`character-autonomy-editor`・`character-editor`・`g13-look-regression`・`layering`・`operation-controls`・`operation-player-overlays`・`page-change`・`playground`・`room-fallback`・`room-layer`・`world-host`）。unit 643 通過
- 性能：部屋に住むキャラが見えている間、部屋を 15〜30fps で描く（止まっていれば描かない、から変わった）。拡張の CPU は短い目安だけ。GPU の時間・正式な交互計測はしていない
- `space-live` は「今日の YouTube では逃げ道の板は0枚」を確かめるが、おすすめに「Auto-dubbed」の印が出た回は、逃げ道が正しく列に板を敷いて落ちた（ページの中身による）
- 手前のキャラから部屋への「跳ねる」は、部屋の側で跳ねて消えるだけで、手前の絵と位置はつながっていない（粗）
- 歩く足の滑りは、撮った回がほとんど椅子の裏だったので、まだ目で確かめきっていない
- 奥行きの土台の利用者の過去の作品での確認はしていない

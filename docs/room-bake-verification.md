# 部屋のライトマップ計測をデスクトップで再確認

2026-11-07。独立確認の対象は `codex/room-bake` の `d33e2c8`。机・椅子・ランプの GLB は翔太が置いた原本を環境変数から読み、三角形数は元報告と同じ 10,391・2,832・4,488 だった。原本と生成した部屋の GLB・EXR は Git の外に置いた。[元の計測と手順](https://github.com/a3681299-png/web-world-themes/blob/d33e2c8958374e7e6930cd2376416677cd3438ad/docs/room-bake-plan.md)

Ryzen 5 5600X、Radeon RX 6800、Windows 11 Pro 26H2（26300.9711）。Blender 5.2 の HIP で、5層を1層ずつ、1024 と 2048 を各384サンプルで焼いた。1層は 1024 で20.6〜24.9秒、2048で48.0〜69.4秒。描画は Playwright Chromium 153.0.8010.12 の画面外ウィンドウ、1920×1080、DPR 1、165 Hz（rAF 中央値 6.1 ms）。各条件を6秒ずつ3回採取し、偶数回は順序を反転した。GPU は WebGL2 の時間クエリ、CPU は1フレームの描画呼び出し時間。表の中央値と p95 は各試行で計算した値を3回の中央値にまとめた。

同じページに「動画だけ」を追加した。DOM の動画は同じ VP9 ファイル（64×48、`tests/fixtures/motion/long.webm`）を同じ位置と大きさで再生し、この条件では部屋・マネキン・WebGL の描画を始めない。動画カウンターは6秒窓の前後で読み、GPU クエリの回収待ちは動画の窓から外した。要因を切り分けるため、ページの大きさを保って描画バッファを 960×540 にする条件と、三角形を保ったまま静的メッシュを同じ材質の小さな範囲に分割して描く条件も加えた。実験用の変更は作業用スクリプトに置いた。

- 三角形を18,455から5,170へ減らしたときの GPU 中央値の差は −0.005 ms。画素を4分の1にすると −0.174 ms（約55%減）だった。描く単位を23から74に増やした場合は GPU がほぼ同じで、CPU 中央値が +0.10 ms。今回の規模で効いたのは GPU 側では画素数、CPU 側では描く単位の数だった。30万三角形や100回の描画という上限は今回の測定範囲を超える。
- 焼き込み2048の読み込みは629 → 2,287 ms（約3.6倍）。5層と合成先1枚の RGBA16F の容量は48 → 192 MiB（4倍）。容量はテクスチャの寸法と形式による見積もり。定常の GPU 中央値は0.317 → 0.320 msだった。
- 輪郭線は GPU 中央値が約3.1倍、p95が +0.48 ms。画像でも輪郭線と一緒に色・明るさが変わった。複数パスのため、輪郭線の行は最後のパスだけを返す描画統計を表から外した。床のプローブは基本に比べ GPU p95 +0.74 ms、CPU p95 +1.30 msだった。
- 部屋ありの動画落ちは順に0/43・2/44・0/44、動画だけは0/44・2/44・0/44。この素材では落ち枚数に差が出なかった。960×540 の条件では毎回2枚落ちた。動画落ちの結果をこの短い低解像度の素材から実 YouTube や高解像度再生へ外挿することはできない。
- 基本・輪郭線・動画だけの画像を開いて確認した。基本の机の前板に暗い斑があり、椅子はキャラを隠した。カメラを左へ0.4m／0.6m、前へ0.6mずらすと外が見えた割合は0.10%／0.21%／0.05%で、元報告と一致した。上下 ±0.4m、後ろ1.0m、ドリーズーム1.5m までの採取点では0%だった。

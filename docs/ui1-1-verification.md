# UI1.1 の独立検証

2026-10-27に時間指定で中断し、28日に再開した。**着せ替えありの起動性能は不合格。UI1.1を合格とはしない。** 検証対象は 74571be〜2c93579。性能は変更前29b8d5bと2c93579を未変更の別作業ツリーに固定し、機能確認はSPA修正16db4ceとアイコン修正07f7d46を専用ビルドで検証した。mainと通常版distは変更していない。

Claude Codeの報告 [ui-skin.md](ui-skin.md) と [ui1-1-windows.json](benchmarks/ui1-1-windows.json) を読み、主張を独立に確認した。数値の要約と途中の結果は [検証JSON](benchmarks/ui1-1-verification-windows.json)、フレーム配列・trace・CPUプロファイルは .work/ui11-verification/ に残す。

## 直したもの

- **製品：16db4ce**。SPAの前後で同じ種類の部品があると、前ページの文字色判定を再利用していた。明るい絵に白文字が残る失敗を先に再現し、遷移で再判定するよう修正。修正後10/10成功。
- **製品：07f7d46**。検索欄のクリア「×」は、YouTubeのSPANが決めた色をSVGが継承していた。文字ノードだけを読む判定にも入らず、色指定も届かなかった。文字が先に読めている2条件でも未修正で失敗するテストを書き、フォーム・SVGの色を読み、SVGへ既存の白黒colorを届けるよう修正。2条件を各10回成功。fillの書き込みは追加していない。
- **計測時計**。従来はdocument-idleの拡張読込時からフレームを数え、読込前の約90〜104フレームを起動区間の分母から落としていた。ページ開始時のrAF時刻と拡張世界のCPUを同じ時刻原点で対応付けた。
- **非同期処理の計測**。native awaitの継続部はPromise.prototype.thenのラッパーを通らなかった。計測ビルドだけでesbuildにasync/awaitをPromiseコールバックへ変換させ、同期区間を測る。待機時間をCPUに加えず、入れ子を二重計上しないテストも追加。IDB・MessagePortのon*とChrome接続イベントも捕捉する。
- **道具**。各ブロック前10秒のCPU監査、条件の異なる再開の拒否、完了した組と中断記録を保持する再開機能を追加。機能を止めた診断ビルドは合否用に拒否する。製品ソースの文字列置換は使わない。
- **実サイトの検査**。YouTubeのTrusted Typesを変えず、テスト用コードをDevToolsで評価する。同じ部品自身のG1余白も交差として記録し、別の操作面の遮蔽は全該当画素で比較する。真の遮蔽を検出し、前面の不透明な保護面を区別するfixtureは2/2成功。
- **録画ループのテスト**。CPU・traceとrAF登録元からG1の復帰タイマーを特定した。待ち秒数や許容本数を増やさず、保護停止の解除を待つよう修正した。
- **CI用の整形**。pullで追加されたデザインシステム資料の書式だけをPrettierに合わせた。内容や製品のデザインは変更していない。既存の未追跡コピー38件はリモートと一致を照合し、.workに保管してから取り込んだ。

通常ビルドにはCPU計測もページ変化カウンターも入らないことをテストしている。計測・診断の出力は.workに限定する。Chrome権限・作品データの安全検証・DesignDocumentの形式は変えていない。

## 起動負荷の調査

CPUプロファイルを先に2組取得した。上位の製品関数のself time（起動1回の平均、ms）は次のとおり。計測ラッパーの関数はこの表から外している。プロファイル付きの回は最終合否には使わない。

| 関数                         | なし  | 9部品 | 主な処理                             |
| ---------------------------- | ----- | ----- | ------------------------------------ |
| scan                         | 55.96 | 74.43 | 部分木・起動時のセレクター走査       |
| mark                         | 24.48 | 46.66 | 候補要素を各対象と照合して印を更新   |
| MutationObserverコールバック | 26.47 | 34.17 | 変更を分類して次の走査をまとめる     |
| videoCardContainer           | 10.81 | 16.93 | 変更ノードが属するカードを読む       |
| backdropLuminance            | 0.00  | 11.35 | 中央の絵と本物の背景から輝度を求める |

別の2組ずつで機能を一つずつ外した。小さすぎる判定なしでも起動p95の増分+1.70ms、文字色判定なしの診断プロファイルでも+1.20msが残った。文字色判定だけを原因とは言えない。印が必要なときの走査・照合の負荷も残る。これらは別の短い実行なので、差を厳密な関数別増分には割り当てない。

直す案は、起動時に重なる全体走査の整理と、候補に対する全セレクター照合の削減。文字色側は同一素材・切り位置・背景の輝度計算の共有が候補になる。アダプターの通知や再判定の範囲に関わるため、今回推測で製品を変えていない。

# UI0-b：エディターの中を仕上げる

ページの上に浮かぶエディター（`src/editor/`）の中を、`docs/wwt-studio-design-system/` の決まりで仕上げた。ページの上の印（`controller.ts` の枠、`skin-picker.ts` のマウスを乗せたときの枠）、`src/host/`、Studio 系（ウィンドウ・サイドパネル・ページ内 Studio）は触っていない。

浮かぶエディターと Studio は `panel.ts`・`workspace.ts`・`layer-tree.ts`・`skin-panel.ts`・`icons.ts` を共有している。今回の変更は、すべて浮かぶエディターのときだけ働くように分けた（`panel.ts` の `floating`、`createWorkspace` と `createSkinPanel` の `floating`、`createLayerTree` の `icon`）。Studio の DOM・文言・アイコンは変わっていない。

## 低い画面（UI0-a の 5 つの高さ）

UI0-a と同じ手順（本物の YouTube、幅 1366、ダーク、レイヤー 3 つ、一覧の上でホイールを 2 回 → 一番下の行を `elementFromPoint` で調べてクリック）。

| 高さ | 一覧の高さ | ホイールの前に見えていた一覧 | 一番下の行      | クリックで選べるか | 外側のスクロール | ページ           |
| ---- | ---------- | ---------------------------- | --------------- | ------------------ | ---------------- | ---------------- |
| 600  | 84px       | 41px                         | 42/42px、行の中 | 選べる             | 51px             | 動かない         |
| 657  | 84px       | 26px                         | 42/42px、行の中 | 選べる             | 66px             | 動かない         |
| 700  | 84px       | 69px                         | 42/42px、行の中 | 選べる             | 23px             | 動かない         |
| 736  | 97px       | 97px                         | 42/42px、行の中 | 選べる             | なし             | 動かない         |
| 800  | 161px      | 161px                        | 42/42px、行の中 | 選べる             | なし             | 動いた（下の注） |

- 657 の「ホイールの前に見えていた一覧」は、画像を入れた直後（入れた画像が選ばれ、選択の帯が「光とマスクを設定」などで高くなる）の値。開き直した直後は、帯が低いので 1 行目が丸ごと見える。これは e2e の「on a low window (1366×657) the guide folds to its title …」で確かめている（外側のスクロール 0 のまま、1 行目が画面に丸ごと入り、その中心が行そのもの）。
- 800 でページが動いたのは、3 行が一覧に収まって一覧がはみ出していないため。ブラウザは、はみ出していない入れ物をスクロールの連鎖に入れないので、一覧の上のホイールはページへ届く。UI0-a の前から同じ（`docs/ui0a.md` の「気になっている点」）。一覧がはみ出していて外側がはみ出していないときは、ページへ漏れない（e2e の「a low window …」の後半で確かめている）。

## 計測

交互計測はしていない。ページの上で動く処理（content script の動き・`src/sites/`・`src/world/`・`src/host/`・描画）を変えていないため。変えたのはエディターの Shadow DOM の中の DOM・CSS と、エディターのアイコンと作図の SVG だけ。

「a low window …」の後半の注：

- 最初は、高さ 800 で畳まれたガイドを開いて「一覧ははみ出すが外側ははみ出さない」状態を作った。ガイドを畳むようにしたため、800 では 3 行が一覧に収まるようになったからだ。手元（Windows）では通ったが、`019c271` の CI（Linux、e2e shard 1/4）では外側が 3px はみ出して落ちた。書体が違うと文字の高さがわずかに違うので、テストの前提が書体に左右されていた。製品の挙動の差ではない。
- 書体によらない形にした。高さ 900 でレイヤーを 9 行にすると、一覧は大きくはみ出し、外側には余りが残る。
- もう 1 つ見つけた。このテストは、UI0-a の「一覧に `contain` がない版」（ページへ漏れる版）でも通っていた。ブラウザは、ホイールを始まった箱に結びつける（latching）。そのため一覧にまだ回す余地があるあいだは、余った分がページへ伝わらない。一覧を端まで回してから、もう 1 回回す形にした。漏れる版ではページが 78px 動いて失敗し、今の版では通ることを確かめた。

## 未確認の点・気になっている点

- `prefers-reduced-motion` で最後の状態がすぐに出ることは、CSS の書き方で決めただけで、実機の設定を変えて確かめていない。
- アイコンは、16px の作図の点に乗せて描いたが、デザイナーの見本（README の Iconography の図）と並べた確認はしていない。とくに手（サイト操作）は見本がない。
- 開くときの線（`ww-construct`）は 7 コマ（約 0.6 秒）で消える。そのあいだ中身は見えないが押せる。e2e は、開いた直後に押しても通っている。
- 空の状態の作図は、文とボタンが出終わるまで毎回 25 コマ（約 2 秒）かかる。最後のレイヤーを消して空になったときも描き直す（README の「空のあいだ描き直さない」は守っている）。
- 保存の失敗の理由は「ブラウザの保存領域に書き込めませんでした。」の 1 つだけ。保存の処理（`editor-core/session.ts`）は失敗の種類を区別していないので、本当の理由が違う場合もありうる。理由を出し分けるには editor-core を変える必要がある（Studio とも共有）。
- 高さ 800 以下でガイドを畳むので、768 の画面では、はじめて開いた人がガイドの手順を見るには 1 回押す必要がある。

## 次の担当への引き継ぎ（UI0-c・UI0-d）

- 浮かぶエディターと Studio を分けるのは、`panel.ts` の `floating` だけ。Studio を移すときは、`floating` の分岐をはがして共通にし、`src/studio/editor-base.css`・`editor-skin-base.css` と `icons.ts` の 24px の `icon` を消す。
- G-pen は `src/editor/pen.ts`。ページの上の印（`ww-mark`、`controller.ts` の紫の枠）を作るときもこれを使う。bundle.js が変わったら `studio-pen.spec.ts` が落ちる。
- 保存のチップは `.save-state`（`.dirty` と `.save-failure`）。e2e の多くが `.status` の「保存しました。」で保存を確かめているので、下の文の中身は消さないこと（画面に描かないだけ）。
- ガイドを畳む高さ（800）は `workspace.ts` の `matchMedia` と、`panel.css` の作図を小さくする高さの 2 か所にある。変えるときは一緒に変える。
- 試していないこと：Studio のウィンドウ・サイドパネルの見た目（今回は触っていないので変わらないはず。e2e の `side-panel`・`studio-*` は通っている）。

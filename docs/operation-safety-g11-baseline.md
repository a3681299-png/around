これは、画面全体へ装飾を置くと仮定した**クリップの許可面積**であり、個々の素材のアルファやサイトが手前に描く画素、一時停止の継続時間を測る値ではない。実際にHostが停止中の瞬間は作者の描画が0になる。元のsnapshotと停止状態も[計測JSON](benchmarks/operation-g11-baseline-windows.json)へ残した。プレイヤーと一緒に動く専用描画先の面積は、画面固定の面積へ加算していない。

## フレーム全体のp95

Chromium 153.0.8010.12、headless、1920×1080、DPR 1。検証済みの `petal.png` を正式な取り込みUIで保存し、同じ原本を参照する32画像・16グループを使った。基底テーマはnull、画像の不透明度0.8、グループ0.7。毎フレーム、実際のRenderer全体を再描画させた。検査なしは、計測用の隔離ビルドだけでOperationGuardの構築を省く比較であり、製品へ停止スイッチを追加したものではない。

各区間でページを再読み込みし、再注入後2秒、再描画のウォームアップ3秒、その後6秒を目標に計測。ON/OFFの順序をAB・BA・AB・BAの4組で交互にした。前後で動画が再生中、readyStateが2以上、時刻が5秒以上進むことを確認した。**起動直後のYouTube DOM更新を含む条件であり、定常再生のp95ではない。** 他のテストは並行実行していない。

| p95の定義                                              | 検査なし |  検査あり |
| ------------------------------------------------------ | -------: | --------: |
| フレーム全体：Chrome traceのAnimationFrame開始から終了 | 13.07 ms | 160.66 ms |
| 同traceのRender段階：JSとstyle/layoutを含む経過時間    |  4.05 ms | 130.89 ms |
| 拡張のRAFコールバック経過時間の同一フレーム内合計      |  3.40 ms |  13.50 ms |
| 別に取得したRAF間隔                                    | 13.40 ms | 159.50 ms |

全体はmain threadで `FireAnimationFrame` が最も多いprocess/threadを選び、`AnimationFrame` のflow idが同じ開始(s)と終了(f)を結んだ経過時間。Renderは `AnimationFrame::Render` のb/eを結んだ値。コールバックだけの時間と区別し、GPU単独の実行時間や物理画面の表示遅延とは呼ばない。両条件に同じ計測フックとトレースの固定費を含む。

p95はnearest rank（小さい順のceil(0.95×件数)番目）。組ごとのp95を平均せず、条件別に全フレームをまとめて計算した。全体の件数は検査なし3268、あり673。低FPSの区間も捨てていない。

| 2   | guarded → unguarded |             13.11 |   130.28 |               69 |          3982.60 |            6.87秒 |

この4区間の幾何再取得は計337回、合計18295.70ms、1回の中央値55.20ms、p95 72.00ms。キャッシュで返ったcaptureは数えず、discover・実DOMの矩形・合成順・snapshotの構築までを測った。短い起動直後の区間の値であり、60秒の定常再生へ外挿しない。

G1の既存記録の約0.7msは29面のfixtureで毎回取り直した条件で、今回の数百面がある実DOMとは条件が異なる。コールバック合計だけのp95では、Observerから起きる再取得などの負荷を落としてしまうため、フレーム全体も併記した。

## 実装前に確認が必要な作品データ

現行[型定義](../src/design/types.ts)のレイヤーはimage / animation / model3dとgroupであり、通常装飾と雰囲気を区別する保存項目がない。[schema](../src/design/schema.ts)と移行処理は未知の項目・種類を拒否する。現在のopacityから自動判定すると、低不透明度の旧作品まで遮蔽検査を免除して意味が変わるため、採用しない。

最小の追加案は、共通のレイヤー属性へ `renderMode?: 'normal' | 'atmosphere'` を加え、DesignDocumentをv12にすること。省略はnormal。v1→…→v11→v12の移行で、既存作品はすべてnormalとして振る舞いを保つ。40%等の上限値は作品へ保存せず、エンジンが保持する。

40%はまだ候補値で、採用を確定していない。40%の層を2枚重ねると実効64%になるため、レイヤー単位の制限だけでは足りない。複数の雰囲気描画を重ねた結果も上限を超えない合成と、既存の重なり順・グループ不透明度・マスクの維持を併せて検証する必要がある。上限の根拠となるライト/ダークの実サイト比較画像も未作成である。

ページに追従する描画先は、既存のplacement.anchorから選べるので、そのためだけの新項目は不要と考える。実装時は同じスクロール関係を確認できた描画先だけ現在の矩形を使い、確認できない場合はG1の保守的な除外へ戻す。固定とスクロールを単に2つの大きな描画先へ分けると混在時の重なり順が変わるので、グループの部分木を分解せず順序を保つ方式を先に確認する。

今回、これらの実装、Studioの追加表示、上限の決定、変更後の面積測定には着手していない。

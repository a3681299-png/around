判定：**R3-1 は閉じない**。旧 VRM を含むバックアップの復元が退行している。不正な scene を持つ .vrma も追加・保存でき、再生時に例外になる。製品コードと既存テストは変更していない。

## 対象と方法

- 対象：`800373875d9a933b101e4e1cfdbfe7cfa40412e8`。比較：最後の G1.4 製品コード `8e63f0d451eeaf7811b7e0b5b60070d10b5233a9`。

- Windows、Chromium `153.0.8010.12`。表示が不要な試験は headless。実サイトの 3D は表示あり・画面外で実行した。
- トルーシェと動作は依頼された PC 上の外部ファイルを使用。VRM・VRMA 原本、私用モデルを含む画像・trace・プロファイルはコミットしない。報告に添えるバックアップと画像は、リポジトリの自作テスト素材だけを使ったもの。

### 数値の検査で見えた点

独立のデータ試験は44件中41件成功。失敗3件は上の scene 2件と、51段の有限スケールの積で腰高さが `Infinity` になる .vrma である。最後のものは `inspectAsset` と `parseVrmAnimation` だけなら通るが、**実 Studio では後段の数値検証で拒否され、動作は追加されなかった**。上流の受理を、製品での取り込み成功と混同しない。

NaN・無限大を含むキーや姿勢、601秒と極端な長さ、8 MiB超、壊れたコンテナは拒否された。600秒ちょうどは受理。作品中の duration・bones・restHipsHeight・hipsTravel・hipsTranslation を実測値から変えると、素材の照合が拒否した。

## 前からの残件・未分類の失敗

- `world-compatibility.spec.ts` の評価比較は変更前から同じ関数・同じ引数同士の自己比較だった。今回の版番号更新で弱めた箇所ではない。独立試験で両コミットの評価を比較して補った。
- HOLD待機を0にしても、選んだ `g13-look-regression` は通る。G1.4の報告にも同じ選択範囲の検出の穴が記録されている。今回も、HOLD全体が無効、または全テストに検出力がないとは結論しない。
- Windows全件だけで追加になった3件は**未分類**。`studio-transfer` の不正PNG、`ui0d-verification` の偽造要求では「作品を表示する」のcheckが状態に反映されず、`studio` の編集試験では絵をhitできなかった。同じ3件を前後それぞれ10回ずつ実行し、両方とも30/30成功。変更前で失敗を再現できていないので、前からの残件とも退行とも断定しない。影響は操作不能、頻度は今回の全件で各1回。実YouTubeで同じ失敗は未確認。
- 計測9組目のStudio接続準備失敗は変更前で発生し、変更後の同じ流れは成功した。実YouTubeの計測準備を止める残件として分ける。頻度は今回1回で、接続先が見つからない原因は未確定。今回の製品退行としては扱わない。
- 初回character-liveの画像にはキャラが見えないものがあった。内側のclip/poseだけで見た目の合格にはせず、同じSide panel手順を両版で取り直した。両版とも同じ300×400の位置にキャラが見え、変更後はidleも見えた。通常版・計測版のplayer基準でも表示を確認した。最初の画像の原因は確定しておらず、恒常の退行とは扱わない。既存character-liveには画素で出現を確かめるassertionがないため、今回の追加画像確認で補った。

## テスト更新の確認

`backup-data` は v13 の履歴作品を `parseDesign` した値との比較へ変わったが、「版番号を13に戻せば元データと完全一致する」という検査も追加されている。復元値と設定の完全一致も残る。変更後の値をそのまま期待値にしただけの比較にはなっていない。

履歴v13は導入コミット `3e18edc` の指定テストを再実行して取り直し、fixtureと完全一致した。実装者の `133f88b` 由来の期待値だけに依存せず、依頼された `8e63f0d` のパーサーでも16件を受理し、変更後と比較した。v14の追加項目がない作品の評価・CSSに差はなかった。

## 性能

校正は、拡張の rAF に2msを追加した版で **中央値 +2.00ms、p95 +2.00ms** を検出。拡張の isolated world の rAF・タイマー・Observer・イベント・Promise継続などをフレームごとに合算する既存プローブを使用した。

**全6場面がそろう静かな4組は得られなかったため、性能全体は未判定。** 通算9組を試した。全場面が成立したのは2・4組目だけ。3・5・6・8組目は前後いずれかの背景負荷が5%を超えた。1組目のキャラなし起動は文書時計の窓が約4.37秒に切り替わっており、7組目も同様の起動窓と、最後のSPAのtest期限跨ぎがあった。9組目の変更前は、キャラを追加するStudioの接続準備で止まった。

最初の計測testは30分の上限で失敗し、補完の2組も成立条件を満たさなかった。終了コードを合格へ読み替えていない。保存した値の参考集計では、**その場面自体の窓・広告・可視性・フレーム数・前後負荷が有効な区間**だけを選んだ。別場面や後の失敗によって合格を補っていない。

## 変更したもの・手動確認と引き継ぎ

- 変更はこの報告、再現用コード、公開可能な検証記録だけ。製品コード、既存テスト、通常のdistは直していない。Chrome権限の追加はなく、禁止された私用VRM名のコミットも全履歴で見つからなかった。
- 実際の利用者が保存したv1〜v13の作品は提供されていない。互換の確認は履歴から取ったfixtureと、今回変更前で作ったVRM作品・バックアップで行った。

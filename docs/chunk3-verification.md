# 塊3の独立検証

2026年11月6日、Codex。対象は `08de13d`、比較版は塊2取り込み後の `c6e3ced`。別々の detached worktree で製品ビルドを作った。報告を載せる時点のブランチには、対象 SHA より後のコミットがある。[計画と塊3の完了報告](autonomy-plan.md)

**判定は保留。** バーが出た初回の切り抜きは確認できた。広告中に帯が開く退行と、トルーシェを表示してから検索へ移るSPAの性能超過がある。マウスの接近・離脱でキャラが消える現象は、比較版にもあった。

### 作品と自律

- v1〜v14 の履歴由来14件と合成3件を、両版の `parseDesign` に別々に渡した。比較で読み替えたのは作品の版番号だけ。文書は固定期待値とも照合し、CSS はバイト単位、評価は状態と描画に渡す値を照合した。ポインター・再生／停止・スクロール・アンカーの変更・接近保護・非表示・動きを減らす設定を同じ順序で入れた。表示の証拠は履歴作品では CSS と評価値、マネキンでは実際の描画。
- v14 のマネキンを旧版のバックアップ画面から書き出して新版で読み込み、既存の計算の動きが有効なことを確認した。編集画面で自律をオンにして Undo・Redo・破棄。次に臆病さ0.8・自律オン・計算の動きオフを保存し、v15 の書き出し→未使用プロファイルへ復元→再書き出しを試した。作品の3項目、素材バイト列の SHA-256、描画と計算オフの反映を照合した。
- 版を更新した既存のテストは、引き続き版番号を固定値で照合する。未来版の拒否は v15 から v16 に更新された。独立試験で v16・文字列の `"15"`・小数の版を拒否した。旧版を名乗って v15 の項目を送る拒否、未知の性格キーと文字列のスイッチの拒否も確認した。Manifest は両ビルドで同じ SHA-256 だった。私用 VRM と動作はローカルのパスで参照した。
- 自律の判断は現在の入力と保存した状態で決まり、シードは計算の動きの瞬きなどに使う。自律をオンにし、作者のクリップとポインター追従の経路を200フレームずつ別々に評価した。作者優先の間は、呼吸で胸・背骨・上腕だけが動き、計算による移動・向きの変化は0だった。動きのコードの入力はポインター、時間、部屋の形などで、YouTube の部品を探す処理はサイト側にある。

### 消失とガード

実 YouTube の同じ動画、1,280×800 の画面、同じ v14 作品で、右下に座ったマネキンにマウスを近づけて離した。各往復でバーが出入りした。通常ビルドの `data-safety-limited`、クリップと描画要素の状態を rAF ごとに採取し、最初の停止サンプルから次の再開サンプルまでを計った。ms はサンプル間隔ぶんの誤差を含む。最初の集計は子要素の可視性だけで停止を見逃したため、保存済みの描画停止属性とガードの理由で集計し直した。停止中にレンダラーへ非表示を渡す処理も両版で確認した。

| ------------------ | ---: | -----------: | -----------------: | ------: | -------------: |
| `c6e3ced`          |    6 |        4,684 |         12（6／6） | 1,446.5 |    81.0〜254.7 |

- 比較版　116.9、86.3、109.1、129.5、138.6、93.6、106.1、133.0、104.5、93.2、254.7、81.0 ms。

`WW_GUARD_TRACE=1` の別実行では、接近時の `#movie_player[class]` とシークつまみ `.ytp-scrubber-container[style]`、離脱後の提案バッジ `.ytp-suggested-action-badge[class/style]` を両版で確認した。例えば離脱後に提案バッジのクラスが変わった回の停止は比較版65.5 ms、対象版96.6 ms。警告に出た停止理由は「操作部品が動いている間」と「位置が変わったため」の2種類だった。トレース版は通常ビルドと分けて扱い、スクリーンショット採取後で操作開始より前に起きた停止も上の数から外した。

設定メニューを開く別試験でも両版で止まった。メニューの表示を含む停止は比較版2,260.1 ms、対象版2,436.8 ms。開いている時間を含む値で、通常のマウス移動の件数には入れていない。

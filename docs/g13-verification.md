# G1.3 独立検証

2026-11-03、Codex。対象は `4d3f39b..66c2719`。両端を別の detached worktree に固定した。製品コードは変更していない。

検証中に対象ブランチは `8dd2f40` へ進み、G1.3 を閉じる判断と `.work` 整理用の道具が追加された。今回の計測と再現は指定どおり `66c2719` に固定したもので、新しい道具の動作は検証対象に含めていない。

## 判定

**G1 の保護は不合格。** D14①の模擬ページ再現で、操作部品が別のまとまりに押し出され、不透明な絵に部分的に隠れた。変更前は絵が止まり、同じ再現テストを通った。変更後は失敗した。翔太の A＋B の判断と正式な性能基準は尊重するが、この操作面の退行は性能基準や `signal-timeline-live` の後回し項目とは別に扱う必要がある。

## G1 の再現

固定サイズの横並びを作り、`#below` 内のボタンを class 変更で横に広げる。その結果、別の `#secondary` 内のボタンが x=370〜440 から x=480〜550 に移動する。画面上の不透明な絵は x=275〜725 を覆う。変更後は古い切り抜きが残り、移動先の中心 x=515 が描画可能域に入った。`elementFromPoint` はボタンを返したので、この再現で入力が絵に奪われたとは言えない。画像ではボタンの右側と文字の一部が黒い絵で覆われている。

- [移動直後の描画](screenshots/g13-verification/look-during.png)
- [前の観測](benchmarks/g13-verification/regression-before.json) / [後の観測](benchmarks/g13-verification/regression-after.json)
- [再実行手順](benchmarks/g13-verification/repro/README.md)

影響は操作面が隠れる、頻度はページのレイアウト条件がそろうと発生。AGENTS.md の表ではその段階で直す分類。依頼に従い修正していない。`lookResized` は同じ group 内の他の操作部品を比較するが、外の部品は比較しない。候補は、group をまたぐ移動がないと証明できない場合に全体を保留し、確認範囲を広げる方法。検出窓中の表示と入力の両方を失敗テストで守る必要がある。

CSS transform の確認では、DOM mutation なしでボタンを150px動かした。スクロール通知後の読み取りも、通知がなく500ms経った後の読み取りも元の位置を返し、入力相当の `validate` による強制読み直しで移動を検出した。後者は source 単体の観測であり、本物の YouTube で起きる頻度は未確認。分割確認は pending の変化がある間に進み、静止後に新たな mutation がない移動まで常に監視する仕組みではない。イベント時の再検証はヒットテスト後に実行されるため、入力先の保証としてだけでは不十分。固定の200ms＋約60msも、フレーム遅延がある環境では時間の上限にならない。

D11 では操作部品を含まない要素を部分木に追加し、別の部分木のボタンを110px動かした。source 単体では古い矩形を返した。実描画では、この一例では最初のフレームは絵が隠れ、次に新しい位置の切り抜きを確認した。別の条件で画素が露出しないことまでは証明できていない。

## 操作チェックの待ち切れ

| 5回ごとの順序 | 変更前の失敗 | 変更後の失敗 |
| ------------- | -----------: | -----------: |
| 1組目：前→後  |          1/5 |          1/5 |
| 2組目：後→前  |          1/5 |          5/5 |
| 3組目：前→後  |          4/5 |          5/5 |
| 4組目：後→前  |          0/5 |          2/5 |
| 合計          |         6/20 |        13/20 |

失敗19回すべてで `pointerdown`、`pointerup`、`click` の宛先とヒット先は Studio の `summary`。最終的に `details.open=false`、チェックボックスは非表示だった。失敗時のフォーカスと各イベントは [入力記録](benchmarks/g13-verification/controls-failures.json) にある。このテストの模擬 YouTube はトップページで、プレーヤー要素は存在しなかった。

`mountEditorSafety` には制限表示が一時的に不要になると `details.open=false` に戻す経路がある。状態更新の前後とクリックが競合している可能性はあるが、今回の記録だけではその経路を原因と断定できない。変更前にも発生し、後で多かった。ブロックごとの差も大きく、20回ずつでは G1.3 が差を生んだと確定しない。操作をやり直せる場合があるが、希望した操作チェックを開けない条件があるため、少し不便×条件付きとして原因を追う。

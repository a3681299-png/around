# WWT Visual Loop

「動いた」ではなく「良くなった」を確かめる。見本の視点で撮り、採点し、弱い所を直す。

## References

| File                               | Read it when                                 |
| ---------------------------------- | -------------------------------------------- |
| `references/presets-and-budget.md` | 見本の視点・画面の大きさ・重さの予算・残す物 |

採点表は `../wwt-toon-look/references/scorecard.md`。

## Core rule

スクショは、イラストを描く人の目で見る。「動いている」で止めず、各画面のいちばん弱い所を3つ名前を付けて挙げ、直し、もう一度撮る。

## ループ

1. 見本の視点 P0〜P5 を、決まった画面の大きさで撮る（決まった種で、時間を止めて撮れるようにする）
2. P0 と元の平らなページの画素の差を測る
3. 採点表で採点する（各項目に1行の根拠）
4. 画面ごとに弱い所を3つ挙げる
5. 直す
6. もう一度撮る。採点が上がったか、下がった項目がないかを見る
7. 区切りごとに、短い録画を残す（適用の遷移、引いて惑星、星を回す、建物へ飛ぶ、つむの暮らし）

## 決まり

- **ALWAYS** 撮るときは、時間・種・カメラを決めて、同じ絵がまた撮れるようにする（Playground に、テストのときだけ使える入口を用意する。製品のビルドには残さない）
- **ALWAYS** 重さは予算と比べる。超えたら、体感で分かるかを考え、分かるなら直す、分からないなら残りに書く
- **ALWAYS** 検証の終わりに、試行ごとのブラウザのプロファイルとビルドを消し、要約と報告で使う画像・録画だけ残す
- **NEVER** 同じことを何通りも測り直さない。手元は短い確かめ、正式な検証は区切りの終わりに1回
- **NEVER** 画素の数字だけで「良くなった」と言わない。採点表の根拠を書く

## Report

視点ごとの before / after のスクショ、P0 とページの差、採点表、直した弱い所、録画、重さの数字と予算、残りの一覧。

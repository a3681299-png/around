# 部品と街の対応

出発点の表。見せ場の採点（wwt-visual-loop）を見て、より効く対応があれば変えてよい（変えたら報告に書く）。

| ページの部品       | 街の物                                                               | つむとの関わり                                 |
| ------------------ | -------------------------------------------------------------------- | ---------------------------------------------- |
| ヘッダー           | 街の入口の高架の駅、または大通りのアーチ                             | 改札の前で待つ                                 |
| 検索欄             | 灯台か見晴らしの塔。入力すると灯りが回る                             | 登って見渡す、入力中の文字を覗き込む           |
| プレーヤー         | 広場の巨大スクリーンと、その前の湖。動画が水面にうつる               | 湖のほとりに座って見る。動画が止まると振り向く |
| 動画カード         | 建物。屋根＝カードの面（サムネイルと題名）、高さ＝大事さ、看板＝題名 | 看板を覗き込む、屋根の縁に座る                 |
| 動画の説明         | 公園と掲示板                                                         | 掲示板を読む                                   |
| コメント           | 道。1つのコメントが1区間、返信は枝道。新しいコメントで道が伸びる     | 道を歩く、伸びた道を見に行く                   |
| 高評価などのボタン | 信号・ポスト・ベンチなどの街の物。押すと街の物も反応する             | 信号を待つ、ベンチに座る                       |
| 余白               | 緑地・家並み・川（ページの「間」）                                   | 寄り道する                                     |

## 単位

- 平らなページの 1 CSS px を、地面の上の決まった長さにする（例 1px = 0.01 単位）。真上の望遠の視点で、ページと街の屋根が重なるように、カメラの距離と画角をこの単位から計算する
- 建物の高さは、カードの短い辺の 0.3〜1.2 倍の範囲で、大事さから決める（高すぎると真上以外の視点で隣を隠す）

## G1

- 近い視点：板（屋根・スクリーン）が平らなとき、本物の UI として扱う。HTML-in-Canvas の決まりに沿って、描いた位置を要素の位置として渡し、本物のクリックとキーボードを届ける
- 遠い視点：本物の UI として扱わない。押すと「そこへカメラが飛ぶ」。再生・停止・音量・戻るは、画面の手前に曲がらない操作として常に出す
- つむは操作部品を隠さない。近い視点で板の前を横切る道は選ばない
- テスト：近い視点で再生・シーク・音量・検索・カードを開く、遠い視点で手前の操作、両方を倍率 100/125/150% で

## HTML-in-Canvas がないとき

- 屋根は自前のサムネイル画像と canvas の題名
- 操作は手前の平らな操作だけ
- それでも街・惑星・つむは同じに見えること

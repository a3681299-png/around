# WWT Page to City

Web の構造が、そのまま街の形を決める。中身を差し替えれば街も変わる。

## References

| File                    | Read it when                                      |
| ----------------------- | ------------------------------------------------- |
| `references/mapping.md` | 部品と街の物の対応、作り方の規則、単位、G1 の扱い |

## Core rule

街はページから「生まれる」。手で置いた街ではなく、部品の四角（UI の領域情報）と、決まった規則と、種（seed）から毎回同じ街ができる。

## 決まり

- **ALWAYS** 街を作る関数は決定的にする（同じ入力なら同じ街）。入力は部品の一覧 `{ id, role, rect, importance }` と種。出力は街の配置（区画・建物・道・小物の位置と種類）の JSON
- **ALWAYS** 単位をそろえ、真上の望遠で見た屋根の面が、元のページの部品の位置と大きさに重なるようにする（`wwt-world-bend` の P0）
- **ALWAYS** 屋根にはカードの面を貼る。HTML-in-Canvas が使えるときは本物の UI、使えないときは自前のサムネイル画像と、canvas で描いた題名
- **ALWAYS** 本物の UI の操作（再生・シーク・音量・検索・カードを開く）は、近い視点で板がほぼ平らなとき（曲げのずれ 1px 未満）だけ届ける。遠い視点では、再生・停止・音量・戻るを、曲がらない手前の操作で必ず押せるようにする
- **ALWAYS** 読む距離では文字が 4.5:1 以上で読める。遠い視点は眺める視点として、読めなくてよい
- **NEVER** 作品データに JS・任意の CSS・シェーダー・セレクターを入れない。部品の役割と数値だけ持つ
- **NEVER** 本物の YouTube の画面や見た目を再現しない（Playground の動画サイトは自前で、YouTube に似せない）
- **NEVER** 本物のクリックの代わりにクリックを作って送らない。押せるのは本物の部品だけ

## 手順

1. 平らな動画サイトの部品の四角を集める（`getBoundingClientRect` と役割）。集める関数はテストを書く
2. 対応表（mapping.md）で街の物に変える関数を書く（`src/world/` の流儀で決定的に）
3. 屋根のカードの面を貼る。真上の視点でページと重なるか確かめる
4. 近い視点での本物の操作と、遠い視点の手前の操作を作る。両方の G1 のテストを書く
5. ページが変わったら（検索・カードを開く）、街も変わる。変わり方はなめらかに（建物が伸び縮みする）
6. `wwt-visual-loop` で撮って採点する

## Report

対応表の変更、作り方の関数の場所とテスト、真上の視点とページの差、G1 のテストの結果（近い視点・遠い視点・倍率 100/125/150%）、HTML-in-Canvas がないときの見え方。

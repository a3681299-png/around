# サイトアダプターの部品を足す・直す

YouTube についての知識（セレクター・DOM の形・状態の条件）は、すべて `src/sites/` の中に閉じ込める。エンジン・テーマ・作品データは、部品の**固定ID**と**状態の名前**しか知らない。`npm run lint`（`scripts/lint.mjs`）は、`src/themes`・`src/design`・`src/editor`・`src/world`・`src/renderers` に `ytd-` などのセレクターがあると失敗する。

## どこに何があるか

| ファイル                          | 役割                                                                                            |
| --------------------------------- | ----------------------------------------------------------------------------------------------- |
| `src/sites/youtube-targets.ts`    | 作者が選べる部品の一覧（固定ID・ラベル・セレクター・状態の条件・典型の大きさ）                  |
| `src/sites/youtube.ts`            | アダプター本体。部品に印（`data-around-surface`）を付け、ページの変化を分類して通知する         |
| `src/sites/youtube-operations.ts` | G1 の操作面（押せる・ドラッグできる本物の部品）の一覧                                           |
| `src/sites/youtube-cards.ts` ほか | 動画カードなど、セレクターだけでは決まらない部品の判定                                          |
| `src/sites/types.ts`              | `SiteAdapter` の契約と `SitePageChange`（content / structure / navigation / mode / fullscreen） |

## 部品を足す手順

1. **本物の YouTube で DOM を確かめる**。未ログインの新しいプロファイルで、部品が出るページ（トップ・検索結果・動画ページ・チャンネル）をすべて開き、要素の形を記録する。新旧の2つの DOM（例：`ytd-subscribe-button-renderer` と `yt-subscribe-button-view-model`）が混在していることが多い。両方を拾う
2. **固定ID を決める**。意味で名前を付ける（`subscribe-button`）。一度作品に保存された ID は変えない・消さない。G1 の操作面の連番 ID は使わない
3. `youtube-targets.ts` に足す
   - セレクターは、部品そのもの（クリックやフォーカスを受ける要素）に当たるようにする。外側の飾りの要素ではない
   - 状態の条件は `&` を1つ含むセレクター。エンジンが `&` を部品の印に置き換える。状態の名前は `hover`・`focus`・`selected`・`pressed`・`disabled` から選び、部品固有の名前は `labels` で付ける（`selected` → 「登録済み」）
   - `where`（どのページにあるか）と `sample`（典型の大きさ）を、確かめたページの実測で入れる
4. **印を付ける処理は既存の走査に相乗りする**。部品のための MutationObserver や定期的な検索を新しく作らない
5. **文書全体を検索しない**。ページの変化のたびに `document.querySelectorAll` をしない。アダプターが通知に添える「新しく印を付けた要素」だけを使う。文書全体を見るのは、作品や設定が変わったときと navigation のときだけ
6. テスト
   - 模擬ページ（`tests/fixtures/youtube.html`）に、新旧両方の DOM の部品を足し、印が付くこと・外れることを確かめる
   - 実サイト（`AROUND_LIVE_*`）で、部品が見つかる数と、印の付いた要素が実際の部品であることを確かめる（around-live-test を参照）

## ページの変化の分類

`SitePageChange` の分類を変えたり、新しい変化を拾ったりするときは、次を守る。

- content：文字や数字だけの変化。部品の登録はし直さない
- structure：要素の追加・削除。足された部分だけを走査する
- navigation：SPA の遷移。印をすべて見直す
- mode / fullscreen：ダーク・ライト、全画面の出入り
- 自分（`[id^="around-"]` の中）の変化で、もう一度通知しない

## 操作面（G1）に関わる部品

- 押せる・ドラッグできる本物の部品は、`youtube-operations.ts` の操作面に入れる。エンジンは、そこに作者の絵が重なって操作が壊れることを起こさせない
- プレーヤーの操作帯（上 64px・下 112px）は保護される。新しい部品がプレーヤーの中にあるなら、操作帯との関係を `docs/spatial-design.md` の「操作性の保証（G1）」で確かめる
- 部品の形を変えたら、`tests/operation-*.spec.ts` を動かす

## ログインが要る状態

登録済み・高評価済み・コメントの入力欄の展開後などは、未ログインでは DOM を確かめられない。

- 推測で条件を書いたら、そうと分かるコメントと docs の「未確認」に残す
- 翔太が手動で確かめる手順（どのページで何をして、DevTools で何を見るか）を、完了報告に書く

## YouTube の DOM が変わったとき

- 実サイトのテストが「部品が見つからない」で落ちたら、まず本物のページで DOM を見る。テストを緩めない
- 新しい形をセレクターに**足す**。古い形は、すべての利用者に新しい形が届いたと確かめられるまで残す
- 変わった日付と、新旧の DOM の違いを、コミットのメッセージに書く
